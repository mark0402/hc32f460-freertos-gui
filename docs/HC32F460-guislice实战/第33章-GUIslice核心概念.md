## 3.1 GUIslice 是什么、不是什么

**GUIslice 是一个"轻量级、嵌入式、C 语言 GUI 库"。**

- "轻量"：不依赖操作系统、不占大块显存，几百 KB Flash、几十 KB RAM 就能跑；
- "嵌入式"：为 MCU + 小屏设计，常见于 Arduino、STM32、ESP32；
- "C 语言"：没有 C++、没有拖拽设计器，界面全靠代码"画"出来。

但请务必建立正确的边界认知：

| GUIslice **负责** | GUIslice **不负责** |
|---|---|
| 管理"有哪些元素、在哪个页面、现在该显示什么" | 直接操作你的屏硬件（它不知道你的屏） |
| 计算"哪些元素需要重绘、重绘哪块矩形" | 提供中文字库（它只有 ASCII 字体） |
| 提供按钮、文本、滑块等控件的行为框架 | 决定底层 SPI 怎么发数据 |
| 把"画某个元素"翻译成"画点/画线/画字"的调用 | 处理具体业务（你的时钟、你的设置逻辑） |

一句话：**GUIslice 是"界面元素的管理者与调度者"，不是"屏的驱动者"**。它只知道"该画个按钮在 (2,2,72,24)"，但"怎么在 (2,2) 点亮像素"这件事，必须**由你来告诉它**。

这就是"适配层 `gslc_drv_hc32.c`"存在的根本原因。详见 3.3。

## 3.2 三个核心概念：元素 / 页面 / 字体

GUIslice 的世界里，几乎所有东西都由这三者组合而成。

### 3.2.1 元素（Element）：屏幕上的"对象"

一个**元素**就是屏幕上一个有身份、有位子、有样式的可视对象。比如：

- 一段文字（文本元素）
- 一个按钮（按钮元素，本质 = 矩形框 + 文字 + 是否按下）
- 一个进度条、一个图片框……

每个元素在创建时都要声明（或框架替你记住）这些信息：

| 属性 | 含义 | 例子 |
|---|---|---|
| ID | 元素在"当前页面"内的唯一编号 | 1、2、3……（全局要唯一） |
| 所属页面 | 这个元素属于第几页 | page 0 / page 1 |
| 位置与大小 | 一个矩形 `{x, y, w, h}` | `{2, 2, 72, 24}` |
| 类型 | 按钮 / 文本 / 滑块…… | `ElemCreateBtnTxt` |
| 样式 | 边框色、填充色、文字色 | `ElemSetCol` |
| 状态 | 是否被选中/聚焦/按下 | `ElemSetGlow` |
| 内容 | 按钮上的文字、文本框的字符串 | `"保存"`（本工程传空串，手绘中文） |

【提示】注意"ID 全局唯一"这条。GUIslice 用 `(页面, ID)` 唯一定位元素。两个元素 ID 撞了，框架会找不到正确的那个，表现就是"控件不显示 / 点不动"，而且**不报错**。后面新增页面时，ID 规划是第一要务。

### 3.2.2 页面（Page）：一组元素 + 一个显示状态

一个**页面** = 当前屏幕上所有元素的一个集合，外加"现在显示的是不是我"的状态。

为什么需要多页面？因为界面空间小，一屏放不下所有功能。主页、设置页、启动页……本质就是"几组不同的元素集合"，同一时刻只显示一组。

GUIslice 的页面管理很朴素：

- 你先"注册"一个页面，告诉它"这个页面最多能放多少元素"；
- 然后往这个页面里"创建"元素；
- 想显示某页时，调 `gslc_SetPageCur(&gui, 页码)` 切过去。

【注意】`gslc_SetPageCur()` 会触发**整页重绘并清屏**。这是个副作用很大的操作：切页后，你手绘的内容（中文、图形）会被擦掉，必须重新画。所以本工程每次切页都会**主动置脏标记**（见第 42 章）。记不住这点，你会在切页后看到"中文/图形消失"的灵异现象。

### 3.2.3 字体（Font）

GUIslice 用"字体引用"来画文字。本工程因为要用 ASCII（状态栏、数值），又不用 GUIslice 自己的字体数据，所以在初始化时注册一个"占位"字体：

```c
gslc_FontSet(&gslc, 0, GSLC_FONTREF_PTR, NULL, 16);   // 字体 0, 16px
```

意思：把 0 号字体设成"指针引用、指向 NULL、字号 16"。NULL 是因为本工程真正画字时，驱动层会**忽略 GUIslice 的字体数据，直接调 `tftlcd` 的 ASCII 字库**（见 3.3）。

【提示】对中文，GUIslice 的字体机制完全不参与——中文是我们在 `chinese_font.c` 里完全自绘的。所以新手有个常见误解："GUIslice 能不能显示中文？"——在本工程的用法里，**中文绕过了 GUIslice**，它"看不见"中文。

## 3.3 回调驱动：GUIslice 怎么"画"到你的屏上

这是移植的灵魂。GUIslice 自己不会点亮任何一个像素，它定义了一组叫作 `gslc_Drv*` 的函数接口（"驱动回调"），然后在需要画东西时**反过来调用这些函数**。我们要做的，就是实现这些函数，把"画点/画线/画字"转接到现成的 `tftlcd` 函数上。

打个比方：

> GUIslice 是餐厅的"前台"，客人（重绘请求）来了，前台喊后厨："画个按钮！"。但后厨（你的屏）前台不认识——所以你得事先告诉前台："画按钮 = 找 `tftlcd` 这个厨师，按这个菜谱做。" 这组"菜谱"，就是 `gslc_drv_hc32.c`。

本工程实现的关键回调一览：

| GUIslice 调用 | 我们转接到 | 作用 |
|---|---|---|
| `gslc_DrvInit` | 直接写 | 告诉框架屏的宽高、开启局部重绘 |
| `gslc_DrvDrawPoint` | `LCD_Draw_ColorPoint` | 画点 |
| `gslc_DrvDrawLine` | `LCD_DrawLine` | 画线 |
| `gslc_DrvDrawFillRect` | `LCD_Fill` | 填充矩形 |
| `gslc_DrvDrawFrameRect` | `LCD_DrawRectangle` | 画矩形框 |
| `gslc_DrvDrawTxt` | `LCD_ShowChar(循环)` | 画文字 |
| `gslc_DrvGetTxtSize` | 自己算宽度 | 文字尺寸（用于对齐） |
| `gslc_DrvLoadImage` | 返回 `(void*)1` | 占位（本工程不用图片元素） |
| `gslc_DrvFontAdd` | 返回 `(void*)1` | 占位（字体走 tftlcd） |
| `gslc_DrvGetTouch` | 返回 false | 无触摸 |
| `gslc_DrvPageFlipNow` | 空实现 | 无帧缓冲，无需翻页 |

两个"必须返回非空"的坑（新手极容易栽）：

```c
void* gslc_DrvLoadImage(...)      { return (void*)1; }        // 非空, 否则上层认为图片加载失败
const void* gslc_DrvFontAdd(...)  { return (const void*)1; }  // 必须非空, 否则框架认为字体加载失败
```

本工程不用 GUIslice 的图片元素、也不用它的字体数据，但这两个函数**返回 NULL 会让上层判定失败并中止流程**。返回 `(void*)1` 即可——框架只检查"非 NULL"，不真的用返回值。

【注意】`gslc_DrvInit` 里有一行是本项目观感的关键：

```34:46:project/source/guislice/gslc_drv_hc32.c
bool gslc_DrvInit(gslc_tsGui* pGui)
{
    if (pGui)
    {
        pGui->nDispW     = LCD_Width;
        pGui->nDispH     = LCD_Height;
        pGui->nDispDepth = 16;
        // 开启局部重绘: 仅重绘"变脏且带填充"的元素, 不再每次整屏清黑
        pGui->bRedrawPartialEn = true;
    }
    return true;
}
```

`bRedrawPartialEn = true` 让框架只擦"变脏且带填充"的元素那块矩形。若关掉它，每次重绘都会整屏清黑，本工程状态栏每秒刷新一次就会"一秒一闪"。代价是：无填充的透明文本在局部重绘下会残留——本工程元素都带填充，所以安全。

## 3.4 重绘机制：脏矩形、局部重绘

把第 32 章的"重绘"概念对照到 GUIslice 的具体机制：

```
你改了某个元素的状态（比如 ElemSetTxtStr 换文字）
        │
        ▼
GUIslice 把该元素所在的矩形标记为"脏"（dirty）
        │
        ▼
下次 gslc_Update() 时，只重绘"脏矩形"那一块
        │
        ▼
框架回调 gslc_DrvDrawXxx，由你的 tftlcd 真正画上去
```

几个名词对照：

| 概念 | 含义 |
|---|---|
| 脏矩形（Dirty Rect） | 被标记"需要重画"的那块矩形区域 |
| 局部重绘 | 只重画脏矩形，而非整屏 |
| `gslc_Update()` | 每帧调用一次，框架据此执行"重绘所有脏矩形"的调度 |
| `bRedrawPartialEn` | 是否启用局部重绘（本工程开启） |

【提示】理解"脏"字很重要。GUIslice 不会自己去比较"现在和上一帧有什么不同"，而是**你改了元素，它才知道那块脏了**。所以"我明明改了数据，屏幕怎么不更新"这一类问题，本质常常是：你改了数据，但**没有通过 GUIslice 的接口去改元素**（比如直接改了元素内部的字符串缓冲区），框架不知道脏了。

这正是本工程 `sStatusScratch` 存在的原因（第 42 章详述）：更新文本必须"构造新串 → `ElemSetTxtStr`"，让框架自己发现变化并标记脏。

## 3.5 输入：触摸与按键如何进入 GUIslice

GUIslice 原生是为"触摸屏 / 带坐标的输入"设计的。它的输入回调是 `gslc_DrvGetTouch`（返回触摸点的坐标和是否按下）。

本工程**没有触摸**，所以：

```c
bool gslc_DrvGetTouch(...)  { /* 全填 0 */ return false; }   // 本板无触摸
```

那交互从哪来？从我们自己的按键队列来。GUI 任务每帧用 `bsp_key_recv(&ev, 0)` 取一个"短按/长按"事件，再**由应用层自己解释这个事件、去改 GUIslice 的元素**。换句话说：

> GUIslice 的"输入"在本工程是**被架空**的。我们不用它的触摸回调，而是把按键事件翻译成对元素的操作（移动焦点、改文本、切页面）。

这意味着本工程的事件流是：

```
PC13 按键 → bsp_key 状态机 → 队列 → GUI 任务取出 ev
   → 应用层 switch(ev) → 改 g_u8Sel / g_u8SetFocus / 切页 / 改元素
   → 下一帧 gslc_Update() 把这些变化画出来
```

【注意】这里有个**线程安全**的细节：只有 GUI 任务能碰 GUIslice 的内部状态。其它任务（串口、按键、时间服务）想更新界面，不能直接改元素，而要"只发通知、由 GUI 任务自己改"——本项目的时间正是这么做的：`app_time.c` 在 RTC 中断里自增版本号 `AppTime_GetVersion()`，GUI 任务下一帧发现版本号变了才自己取数重绘（见第 40 章 8.2）。否则多任务并发写 GUIslice 会出诡异 bug。

## 3.6 本工程的"混合绘制"策略

把 3.1～3.5 收口，你就能理解为什么本工程代码里 GUIslice 和"手绘"是混着写的。三句话：

**第一句：GUIslice 管"它认识的元素"。**
按钮框、状态栏文字——这些是 GUIslice 元素，由框架重绘。

**第二句：图形和中国字，GUIslice 不认识，我们手绘。**
右侧图形区、按钮上的中文标签——绕过 GUIslice，直接调 `tftlcd` / `chinese_font.c`。

**第三句：手绘必须在 `gslc_Update()` 之后。**
因为 GUIslice 重绘按钮时，会用它的背景色**擦掉整块矩形区域**。如果你先把中文画上去，再 `gslc_Update()`，中文会被擦掉——表现为"文字一闪就消失"。正确顺序是：

```
gslc_Update();          // 框架先画它认识的（按钮框、状态栏）
DrawCnLabels();         // 再手绘中文，压在按钮之上
DrawShapeArea();        // 再手绘图形（独立区域）
```

【注意】"手绘内容必须置脏重画"也源于此。因为 GUIslice 每次重绘按钮都会擦那块区域，所以手绘的中文**每帧都得重画**（脏标记为真时）。这也是为什么本工程有 `g_bCnDirty`、`g_bShapeDirty` 两个脏标记——它们管的就是 GUIslice "管不到"的那部分。

## 3.7 新手最易困惑的 5 个问题（FAQ）

**Q1：GUIslice 是不是一个"屏幕驱动"？**
不是。它不碰硬件，只管理界面元素。真正驱动屏的是 `tftlcd.c` + SPI。GUIslice 通过 `gslc_Drv*` 回调间接使用它们。

**Q2：为什么我的按钮框出来了，但里面没字？**
最常见两个原因：① `DRV_HAS_DRAW_TEXT` 为 0，框架整体跳过文字绘制；② 像本工程这样，文字是中文、被改成手绘了（按钮文本传空串 `""`，中文另画）。先确认你是哪种。

**Q3：元素创建出来了，但屏幕上看不到？**
按概率排序：① 元素池（`GUI_MAX_ELEM_*`）不够，`ElemCreate*` 返回 NULL；② 元素 ID 和别的撞了；③ 这一页根本没被 `SetPageCur` 切到。

**Q4：我改了数据，屏幕为什么不更新？**
多半是"没通过 GUIslice 接口改元素"，框架不知道脏了。或者手绘内容忘了置 `g_bCnDirty` / `g_bShapeDirty`。

**Q5：中文到底能不能用 GUIslice 显示？**
在本工程的用法里**不走 GUIslice**——中文是脚本取模、在 `chinese_font.c` 里自绘的，GUIslice "看不见"它们。这也是为什么中文绘制顺序要在 `gslc_Update()` 之后。

## 3.8 本章小结

- GUIslice = 界面元素的管理者与调度者，不是屏驱动；"怎么画像素"由你通过 `gslc_Drv*` 回调告诉它。
- 三要素：元素（对象，含 ID/位置/样式/状态/内容）、页面（元素集合 + 显示状态）、字体（本工程用占位）。
- 移植本质 = 实现 `gslc_Drv*` 回调，映射到 `tftlcd`；两个"必须非空"的返回值是新手坑。
- 重绘靠"脏矩形"：你改元素 → 框架标记脏 → `gslc_Update()` 重绘那块。
- 本工程无触摸，按键事件由应用层翻译成对元素的操作。
- 混合绘制：GUIslice 管控件 + 手绘管图形/中文；**手绘必须在 `gslc_Update()` 之后**，且要置脏。
