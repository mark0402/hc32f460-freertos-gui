## 6.1 为什么图片要"预先提取"

在 PC 上，显示一张 PNG 是：打开文件 → 解码 → 得到像素数组 → 交给显卡。这套流程依赖文件系统、动态内存、强大的 CPU。

嵌入式小屏都没有这些奢侈条件：

- 没有文件系统（或没必要为一张 Logo 挂文件系统）；
- 没有足够 RAM 让你把整张解码后的图放内存里随便折腾；
- 屏是 SPI 直驱，`LCD_Show_Image` 期望的是"一串 RGB565 字节，我直接往 SPI 推"。

所以嵌入式显示图片的标准做法是：**在 PC 上把图片预先转换成 C 数组（头文件），编译进 Flash，运行时直接把数组地址交给屏**。转换这一步，就是 `gen_image.py` 干的事。

```bash
cd project/tools
python gen_image.py TitansLogo.png
# 生成 project/source/guislice/titans_logo.h，里面是一个巨大的 const uint8_t 数组
```

## 6.2 RGB565 是什么

屏是 16 位色（RGB565）。先理解它和常见 24 位色（RGB888）的关系：

| 格式 | 每通道 | 每像素 | 示例"纯红" |
|---|---|---|---|
| RGB888（PC 常见） | R8 G8 B8 | 3 字节 | `FF 00 00` |
| RGB565（本屏） | R5 G6 B5 | 2 字节 | `F8 00`（高字节 `F8`=1111 1000） |

RGB565 把红压到 5 位、绿 6 位、蓝 5 位，凑成 16 位 = 2 字节。转换公式（把 8 位截断到对应位数）：

```python
def rgb888_to_rgb565(r, g, b):
    """RGB888 -> RGB565 (5-6-5)"""
    return ((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3)
```

- 红：`r & 0xF8` 取高 5 位，再左移到高字节的 bit15~bit11；
- 绿：`g & 0xFC` 取高 6 位，左移 3 位到中间；
- 蓝：`b >> 3` 取高 5 位，落在低字节低 5 位。

### 为什么要"高字节在前"（MSB first）

`LCD_Show_Image` 把字节流**原样**推给 SPI（第 31 章 1.4 看过）。屏控制器按"先收到高字节"解析 16 位色。所以数组里必须是 `[高字节, 低字节, 高字节, 低字节, ...]`：

```python
data.append((v >> 8) & 0xFF)   # MSB first
data.append(v & 0xFF)          # LSB
```

【注意】如果字节序搞反（低字节在前），颜色会整体错乱——比如红色变成别的颜色。脚本已经处理成高字节在前，你**用脚本生成就不用操心**；但若将来你自己拼数据，一定要记住这点。

## 6.3 `gen_image.py` 做了什么

把转换流程拆开，脚本其实就四步：

```
打开 PNG (PIL)
   │
   ▼
① 缩放 (可选, --resize)        大图先缩到屏内, 否则 LCD_Show_Image 会越界静默失败
   │
   ▼
② 逐像素处理                    遇透明(alpha<阈值)填 --bg 色; 否则转 RGB565
   │
   ▼
③ 按"高字节在前"打包成字节流
   │
   ▼
④ 写出 .h 文件                  包含 _W/_H 宏 + g_au8Xxx 数组 + 版权注释
```

完整主循环（逐像素转 RGB565 + MSB first）：

```python
for y in range(h):
    for x in range(w):
        r, g, b, a = px[x, y]
        if a < args.alpha_threshold:
            v = bg                      # 透明区域填背景色(默认黑)
        else:
            v = rgb888_to_rgb565(r, g, b)
        data.append((v >> 8) & 0xFF)   # MSB first
        data.append(v & 0xFF)
```

【提示】"透明区域填背景色"这个设计，是因为开机 Logo 背景是黑的，透明部分填黑 `0000` 能与背景无缝融合。若你的图片要叠在别的背景上，用 `--bg` 指定对应颜色。

## 6.4 脚本用法

基本命令：

```bash
cd project/tools

# 最简：输出 ../source/guislice/<文件名>.h，宏名由文件名推导
python gen_image.py TitansLogo.png

# 自定义宏名与输出路径
python gen_image.py icon.png -n ICON -o ../source/guislice/icon.h

# 大图先缩放（屏幕只有 240x135）
python gen_image.py photo.jpg --resize 120x60

# 透明区域填白（默认填黑 0000）
python gen_image.py logo.png --bg FFFF
```

参数表：

| 参数 | 默认 | 说明 |
|---|---|---|
| `src` | — | 源图（png/jpg/bmp），位置参数 |
| `-o, --output` | `../source/guislice/<stem>.h` | 输出头文件路径 |
| `-n, --name` | 由文件名推导 | 宏名前缀。`TITANS_LOGO` → `TITANS_LOGO_W/H` 宏 + `g_au8TitansLogo` 数组 |
| `--resize` | 不缩放 | `WxH`，用 LANCZOS 重采样 |
| `--bg` | `0000` | 透明像素填充色（RGB565 十六进制） |
| `--alpha-threshold` | `128` | alpha 低于此值视为透明 |
| `--per-line` | `24` | 输出每行字节数（仅影响可读性） |

【注意】超出 240×135 时脚本会打印警告："图片超过屏幕，LCD_Show_Image 会直接 return，请用 --resize 缩小"。这是**善意提醒**，脚本不会自动缩——它尊重你的显式意图。要么改 `--resize`，要么确保源图本来就在屏内。

## 6.5 产物格式

生成的 `titans_logo.h`（节选）：

```3:10:project/source/guislice/titans_logo.h
// Auto-generated from TitansLogo.png (RGBA -> RGB565, MSB first).
// Transparent pixels (alpha < 128) are drawn as BLACK to blend with the boot background.
#ifndef TITANS_LOGO_DATA_H
#define TITANS_LOGO_DATA_H
#include <stdint.h>
#define TITANS_LOGO_W 201
#define TITANS_LOGO_H 47
static const uint8_t g_au8TitansLogo[18894] = {
```

可以看到产物包含三部分：

1. **尺寸宏** `TITANS_LOGO_W` / `TITANS_LOGO_H`：代码里算位置、判越界用；
2. **数组** `g_au8TitansLogo[18894]`：18894 = 201 × 47 × 2，即"宽×高×2 字节"；
3. **命名规则**：宏名由 `-n` 推导（默认文件名大写），数组名 = `g_au8` + 宏名。这套规则与工程里现有文件一致，照着用即可。

## 6.6 在代码里使用

代码侧三步：包含头文件（已在 `guislice` 目录、被 include 路径覆盖）→ 计算位置 → 调用 `LCD_Show_Image`。

```408:410:project/source/guislice/gui.c

        uint16_t ly = (LCD_Height > TITANS_LOGO_H) ? (uint16_t)((LCD_Height - TITANS_LOGO_H) / 2) : 0u;
        LCD_Show_Image(lx, ly, TITANS_LOGO_W, TITANS_LOGO_H, g_au8TitansLogo);
```

【注意】**图片显示不出来，第一嫌疑永远是"越界"**。`LCD_Show_Image` 越界会静默 `return`，不报错也不画。所以：图片比屏大、或坐标算错导致超出右/下边界，你只会看到一片黑。用 `--resize` 缩到屏内是根治办法。

## 6.7 屏幕边界与 Flash 账

两点工程常识：

**边界**：x + 宽 ≤ 240，y + 高 ≤ 135。否则 `LCD_Show_Image` 直接 return。

**Flash 开销**：图片按 `宽 × 高 × 2` 字节进 Flash。算几笔账：

| 图片 | 字节数 | 约合 |
|---|---|---|
| 本工程 Logo 201×47 | 18894 | ~18.5 KB |
| 满屏 240×135 | 64800 | ~63 KB |
| 一个小图标 32×32 | 2048 | ~2 KB |

小容量 MCU 上，一张满屏图就吃掉几十 KB Flash。大图建议：缩小尺寸、或只在必要时显示、或改用更省的方案（如单色图标）。

## 6.8 改一张图片的标准流程

1. 准备源图（png 最佳，支持透明）；
2. 若大于 240×135，加 `--resize WxH`；
3. 跑 `python gen_image.py xxx.png -n XXX`；
4. 在代码里 `#include` 对应头（目录已在 include 路径），用 `LCD_Show_Image(x, y, XXX_W, XXX_H, g_au8XXX)`；
5. 重新编译。

【动手试】随便找一张小图标 PNG（比如 24×24），跑脚本生成，把 `g_au8Xxx` 在启动页画出来，确认能看到。这是验证整条"图片流水线"最快的方法。

## 6.9 本章小结

- 嵌入式图片必须预先在 PC 上转成 C 数组编译进 Flash，运行时直接喂 SPI。
- RGB565 = R5G6B5 共 16 位 2 字节；转换截断高位；字节序必须**高字节在前**否则颜色错乱。
- `gen_image.py`：打开 →（缩放）→ 逐像素（透明填背景 / 转565 / MSB first）→ 写出 `.h`。
- 产物 = 尺寸宏 + `g_au8Xxx` 数组；数组名规则 `g_au8`+宏名。
- 图片不显示先查越界（`LCD_Show_Image` 越界静默 return）；Flash 开销 = 宽×高×2。
