# 第 44 章　刷新机制与脏标记（核心章）

【本章学习目标】

读完本章，你应该能回答：

1. 为什么"刷新"是本项目最容易出 bug 的地方？
2. 主循环里 `gslc_Update()`、手绘中文、手绘图形，三者的顺序为什么不能乱？
3. 脏标记 `g_bCnDirty` / `g_bShapeDirty` 为什么必须有？哪些时机必须置？
4. 切页为什么会"擦掉手绘内容"，为什么切页后必须置脏？
5. 更新 GUIslice 文本时，为什么不能直接改元素缓冲区，而要用 scratch 缓冲？

本章是全书承上启下的枢纽。前几章拆了三个页面，但都零散提到"置脏标记"。这里把所有刷新相关机制收口成一套可操作的纪律。

---

## 12.1 为什么刷新是核心难点

回顾三条铁律（第 33 章）：

- **铁律一**：GUIslice 只管按钮框和状态栏；图形、中文手绘。手绘**必须在 `gslc_Update()` 之后**。
- **铁律二**：无帧缓冲，动态内容必须"先擦后画"。
- **铁律三**：C 里没有中文。

刷新机制的复杂性，正是这三条叠加的结果：

1. 屏幕上有"框架画的部分"和"我们手绘的部分"两套；
2. 框架不知道我们手绘了什么，不会帮我们重画；
3. 我们手绘的部分每次都可能变，得自己决定"何时重画"。

如果顺序错了 → 中文被擦掉；如果漏置脏 → 界面卡住不更新；如果切页忘了置脏 → 手绘内容消失。这三类的 bug 占本项目界面问题的绝大多数。

---

## 12.2 主循环：三层顺序不能变

GUI 任务主循环（第 38 章 8.3 出现过，这里再强调）：

```533:544:project/source/guislice/gui.c
        gslc_Update(&gslc);
        if (g_bCnDirty)                         // CJK labels are not GUIslice elements; repaint after redraw
        {
            DrawCnLabels();
            g_bCnDirty = false;
        }
        if (g_bShapeDirty && (g_u8Page == 0u))   // shape area is not a GUIslice element; maintain it after redraw
        {
            DrawShapeArea(g_u8Sel);
            g_bShapeDirty = false;
        }
        vTaskDelay(pdMS_TO_TICKS(20));
```

正确的三层顺序：

```
① gslc_Update()       框架重绘它认识的：按钮框、glow、状态栏文字
② DrawCnLabels()      手绘中文（压在按钮之上）
③ DrawShapeArea()     手绘图形区（独立区域）
```

---

## 12.3 为什么手绘必须在 `gslc_Update()` 之后

`gslc_Update()` 重绘按钮时，会用它自己的背景色**刷掉整块矩形区域**。如果你先把中文画上去、再 `gslc_Update()`，按钮重绘会把中文所在的那块矩形刷掉——表现为：

- 中文"一闪就消失"；
- 或"只在部分时刻可见"；
- 或"切页后才出现"。

所以**手绘永远跟在 `gslc_Update()` 后面**，手绘内容天然压在按钮之上，不会被框架擦掉。

【动手试】把 `DrawCnLabels()` 移到 `gslc_Update()` **之前**编译运行，观察中文是不是"闪一下就没了"。改回来。这个对照实验能让你对"顺序"产生肌肉记忆。

---

## 12.4 脏标记：为什么必须有

GUIslice 有完整的脏矩形管理，但**只管自己的元素**。我们手绘的内容，它既不知道存在、也不知道该不该重绘。于是：

- **不设脏标记** → 每 20ms 全画一遍：SPI 带宽吃满、CPU 白烧、可能闪烁；
- **设了但忘置位** → 界面"卡住不更新"（**最常见的 bug**）。

两个标记：

```70:71:project/source/guislice/gui.c
static bool    g_bShapeDirty = true; // right shape area needs redraw
static bool    g_bCnDirty    = true; // CJK labels need redraw (drawn over GUIslice buttons)
```

### 必须置脏的时机（漏一个就是 bug）

| 时机 | 置哪个 | 代码位置 |
|---|---|---|
| 切换图形选中 | 两个都置 | 主页短按分支 |
| 进入设置页 | `g_bCnDirty` | `EnterSettings()` |
| 返回主页 | 两个都置 | `SaveSettings()` / `CancelSettings()` |
| 设置页焦点移动 | `g_bCnDirty` | 长按分支 |
| 数值被修改 | `g_bCnDirty` | `ActOnFocus()` |

例如进入设置页：

```349:358:project/source/guislice/gui.c
static void EnterSettings(void)
{
    AppTime_Get(&g_tm_edit);     // 从时间服务取当前时间, 作为设置页的工作副本
    g_u8SetFocus = 0u;
    RefreshSettingsFields();     // refresh the 6 field strings
    UpdateSetFocus();            // default focus on "YEAR"
    g_u8Page = 1u;
    g_bCnDirty = true;           // repaint CJK labels for settings page
    SetPageCurClear(1u);         // 切页前完整清屏, 防止旧页面残留
}
```

【注意】最后一行 `gslc_SetPageCur` 触发**整页清屏**——这是为什么切页后必须置脏（见 12.5）。

## 12.5 切页必清屏 → 必置脏

`gslc_SetPageCur(&gslc, N)` 会清掉整屏、重画第 N 页的元素。副作用：我们手绘的内容（中文、图形）**会被清屏擦掉**。

所以**凡是切页，手绘内容都要重新画**，必须置脏：

```360:370:project/source/guislice/gui.c
static void SaveSettings(void)
{
    /* 提交给时间服务: 校验 + 持久化都在那里做, 界面不碰墙上时钟。
       底部状态栏会在主循环里检测到版本号变化后自动重绘。 */
    (void)AppTime_Set(g_tm_edit.year, g_tm_edit.month, g_tm_edit.day,
                      g_tm_edit.hour, g_tm_edit.minute, g_tm_edit.second);
    g_u8Page = 0u;
    g_bCnDirty = true;           // repaint CJK labels for main page
    SetPageCurClear(0u);         // 切页前完整清屏, 防止旧页面残留
    g_bShapeDirty = true;        // redraw shape on return to main
}
```

【注意】这里两个脏标记都置了。若只置 `g_bCnDirty` 漏了 `g_bShapeDirty`，从设置页返回主页后，右侧图形区会**一片黑**——因为 `DrawShapeArea` 依赖 `g_bShapeDirty` 触发。这类"切页回来某块区域黑掉"的 bug，根因几乎都是切页时漏置了对应脏标记。

## 12.6 字符串双缓冲：一个隐蔽的坑

更新 GUIslice 文本元素时，**不要直接改元素自带的缓冲区**：

```127:128:project/source/guislice/gui.c
static char sStatus[32] = "2026-01-01 00:00:00";   // element storage (don't mutate in place)
static char sStatusScratch[32];                       // build new string here, pass to ElemSetTxtStr
```

正确姿势：**在 scratch 里构造新串 → 交给 `ElemSetTxtStr` → 由 GUIslice 自己拷贝进元素存储并标记重绘**。

```529:530:project/source/guislice/gui.c
    AppTime_Format(sStatusScratch, sizeof(sStatusScratch), &tm);
    if (pElemStatus) gslc_ElemSetTxtStr(&gslc, pElemStatus, sStatusScratch);
```

**原因**：`ElemSetTxtStr` 内部会比较新旧文本、计算重绘区域。若你直接改元素内部的字符串，GUIslice 无从得知"内容变了"，结果是屏幕不更新；或者它按旧长度算重绘区域，导致残留字符（例如 "12:59:59" 变 "01:00:00" 时末尾几位擦不干净）。

【注意】这个坑的表象和"漏置脏标记"很像（界面不更新/残留），但根因不同：一个是"没告诉框架要重画"，一个是"告诉框架的方式错了，框架算错了重绘区域"。排错时分清这两类。

## 12.7 局部重绘与手绘的关系

`bRedrawPartialEn = true` 让 GUIslice 只擦自己元素的矩形（第 3、5 章）。但手绘区域不在它的管理范围内：

- **好处**：手绘内容不会被 GUIslice 乱擦（只要它在别的区域）；
- **代价**：手绘内容要更新，得自己先清底再画（`DrawShapeArea` 开头的 `LCD_Fill` 就是这个作用）。

若中文直接画在 GUIslice 按钮上方（本工程就是），按钮重绘时会把中文擦掉——**所以每帧都得重画中文（`g_bCnDirty` 为真时）**。这正是中文用脏标记而非"只画一次"的根本原因。

---

## 12.8 一帧完整时序

```
[每 20ms，GUI 任务]
  bsp_key_recv(&ev, 0)              非阻塞取按键
      ├─ 有事件 → 改状态 → 置脏标记
      └─ 无事件 → 跳过
  gslc_Update()                     GUIslice 按脏矩形重绘元素（局部）
  if (g_bCnDirty)    DrawCnLabels()      手绘中文（在 gslc_Update 之后）
  if (g_bShapeDirty) DrawShapeArea()     手绘图形（仅主页）
  vTaskDelay(20ms)

[每 1s，硬件 RTC 中断]
  RtcPeriod_IrqCallback() 推进 app_time 时间副本 → AppTime_GetVersion() 自增；
  GUI 任务下一帧检测到版本号变化 → FormatClock → ElemSetTxtStr（走 AppTime 接口，非任务）
```

---

## 12.9 刷新纪律总结（背下来）

1. **手绘在 `gslc_Update()` 之后**；
2. **状态一变就置脏**；切页必置脏；
3. **改文本用 scratch 缓冲** + `ElemSetTxtStr`，不直接改元素存储；
4. 漏置脏 → 界面卡住；切页漏置脏 → 手绘区域黑掉；顺序反了 → 中文消失。

---

## 12.10 本章小结

- 刷新复杂 = 框架画 + 手绘两套、框架不知手绘、无帧缓冲三因叠加。
- 三层顺序：Update → 手绘中文 → 手绘图形；手绘必须在 Update 之后，否则被擦。
- 脏标记管"手绘何时重画"：状态变、切页、焦点移、值改都要置。
- 切页会整页清屏，手绘内容被擦，故切页必置脏（漏则黑块）。
- 文本用 scratch 缓冲 + ElemSetTxtStr，直接改元素缓冲会导致不更新/残留。
