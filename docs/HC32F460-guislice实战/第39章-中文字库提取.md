## 7.1 中文为什么需要"取模"

第 31 章 1.5 说过三个障碍叠加：GUIslice 无中文、**本工程约定 C 源码不含中文（与编译器无关）**、屏不认中文。

核心难点在于第三点：**屏控制器只认识"像素亮/不亮"，不认识"汉字"**。所以要让屏显示一个"能"字，我们必须先把"能"字**预先变成一张点阵图**——哪些像素亮、哪些不亮。

这个过程叫**取模（font extraction）**：

```
"能" 这个字
   │ 用系统中文字体渲染
   ▼
一张 16×16 的黑白图（亮=笔画, 不亮=空白）
   │ 二值化 + 打包成字节
   ▼
32 字节的点阵数据（每字固定 32 字节）
```

然后屏上画"能"，就是**逐字节、逐 bit 判断，bit=1 的点亮、bit=0 的不亮**。

【提示】"取模"是嵌入式中文显示的通用做法，并不专属 GUIslice。任何没有字库的屏，显示中文都绕不开它。本工程的特色只是"用 Python 脚本自动化取模，且全程不让中文进 C 源码"。

---

## 7.2 中文字模的数据结构

本工程采用 **16×16 单色点阵**：每个汉字 16 行、每行 16 个点。

- 16 个点 = 2 字节（每字节 8 bit，高位在左 = 最左像素）；
- 16 行 × 2 字节 = **32 字节/字**。

举例"能"字（示意，非真实数据）：

```
行0: 00000000 00000000   -> 0x00, 0x00  (顶部空白)
行1: 00000000 10000000   -> 0x00, 0x80  (一竖的顶端)
...
行15: ...
```

内存里就是 32 个 `uint8_t`。屏幕绘制时：`b0` 的最高位 bit7 对应"左上角第一个像素"，`b1` 的最低位 bit0 对应"右上角最后一个像素"。

【注意】"高位在左"这个约定必须和绘制函数严格一致。如果取模时是高位在左、绘制时当成低位在左，字会左右翻转。本工程 `LCD_ShowChinese` 就是按"高位在左"解的（见 7.6）。

## 7.3 `gen_chinese_font.py` 产出哪三个文件

脚本在 `project/tools/`，运行后生成三个文件（都在 `project/source/`）：

| 文件 | 内容 | 是否手改 |
|---|---|---|
| `chinese_font.h` | 类型定义 + 函数声明 | 自动生成，**勿手改** |
| `chinese_font_data.c` | 单字点阵数组，按 Unicode 索引 | 自动生成，**勿手改** |
| `cn_strings.h` | 常用词条的 UTF-8 字节数组 | 自动生成，**勿手改** |

绘制函数 `chinese_font.c` 是**手写的**，不在脚本产物内（脚本只管"数据"）。

【注意】`chinese_font_data.c` 和 `cn_strings.h` **千万不要手改**——下次跑脚本会被整体覆盖。所有中文的增删，都通过改脚本实现。这是第 31 章铁律三的延伸。

## 7.5 取模算法详解（四步）

核心函数 `render_glyph`：

```python
def render_glyph(ch, font):
    """渲染单个汉字为 16x16 单色点阵, 返回 16 个 16-bit 行值(高位在左)。"""
    img = Image.new("L", (W, H), 0)
    d = ImageDraw.Draw(img)
    d.text((0, 0), ch, fill=255, font=font)
    # 裁剪到字形包围盒并居中, 避免黑体在 16px 下被顶部裁切
    bbox = img.getbbox()
    if bbox:
        crop = img.crop(bbox)
        cw, chh = crop.size
        ox = (W - cw) // 2
        oy = (H - chh) // 2
        img = Image.new("L", (W, H), 0)
        img.paste(crop, (ox, oy))
    px = img.load()
    rows = []
    for y in range(H):
        row = 0
        for x in range(W):
            row = (row << 1) | (1 if px[x, y] > 128 else 0)
        rows.append(row)
    return rows
```

四步拆解：

**① 渲染**：用 `ImageDraw.text` 把字画成 16×16 灰度图（笔画=255，背景=0）。

**② 裁包围盒并居中**：**关键步骤**。16px 下黑体字形容易顶到边界被切，裁到包围盒后居中，保证每个字都完整。这一步直接决定小字号下中文"会不会缺胳膊少腿"。

**③ 二值化**：`>128` 置 1、否则 0。把灰度变纯黑白。

**④ 打包**：每行 16 bit 从左往右依次塞进一个 16 位值（高位在左），得到 16 个 16-bit 行。

字体按 `FONT_PATHS` 顺序自动查找（优先 `simhei.ttf` 黑体，笔画均匀、小字号最清晰）。

【提示】想改点阵尺寸（如 12×12 更省空间），改脚本顶部 `W, H = 16, 16` 即可，但**必须同步改 `chinese_font.c` 里 `LCD_ShowChinese` 的循环上界和字宽常量**——取模和绘制两处必须一致，否则字会错位或截断。

## 7.6 绘制链路：从点阵到屏幕

三个函数，在 `project/source/chinese_font.c`（手写，非脚本产物）。

### ① 查表：CN_FindGlyph

线性查找，按 Unicode 找到该字的点阵：

```17:25:project/source/chinese_font.c
const uint8_t* CN_FindGlyph(uint16_t unicode)
{
    for (uint16_t i = 0u; i < g_cn_font_num; i++)
    {
        if (g_cn_font[i].unicode == unicode)
            return g_cn_font[i].data;
    }
    return (const uint8_t*)0;
}
```

### ② 画单字：LCD_ShowChinese

32 字节 = 16 行 × 2 字节，逐 bit 画点（高位在左）：

```27:43:project/source/chinese_font.c
void LCD_ShowChinese(uint16_t x, uint16_t y, uint16_t color, const uint8_t* g)
{
    if (g == (const uint8_t*)0) return;
    for (uint8_t row = 0u; row < 16u; row++)
    {
        uint8_t b0 = g[row * 2u];
        uint8_t b1 = g[row * 2u + 1];
        for (uint8_t col = 0u; col < 8u; col++)
            if (b0 & (0x80u >> col)) LCD_Draw_ColorPoint(x + col,       y + row, color);
        for (uint8_t col = 0u; col < 8u; col++)
            if (b1 & (0x80u >> col)) LCD_Draw_ColorPoint(x + 8u + col, y + row, color);
    }
}
```

`b0` 的最高位 `0x80 >> 0` 对应最左像素，`b1` 的最低位对应最右像素——正是 7.2 说的"高位在左"。

### ③ 画字符串：LCD_ShowChineseStr

边解析 UTF-8 边画，中英混排，返回像素宽度（便于对齐）：

```47:90:project/source/chinese_font.c
uint16_t LCD_ShowChineseStr(uint16_t x, uint16_t y, uint16_t color, const uint8_t* utf8)
{
    uint16_t cx = x;
    const uint8_t* p = utf8;
    while (*p)
    {
        uint32_t code = 0u; uint8_t len = 0u;
        if (*p < 0x80u)            { code = *p; len = 1u; }            // ASCII
        else if ((*p & 0xF0u)==0xE0u){ /* 3字节 UTF-8 解码 */ len = 3u; }
        ...
        if (len == 3u) { const uint8_t* g = CN_FindGlyph((uint16_t)code);
                         LCD_ShowChinese(cx, y, color, g); cx += 16u; }   // 汉字 16px
        else if (len == 1u){ LCD_ShowChar(cx, y, (char)code, 16u); cx += 8u; }  // ASCII 8px
        p += len;
    }
    return (uint16_t)(cx - x);
}
```

规则：**3 字节 UTF-8 = 汉字**（画 16px），**1 字节 = ASCII**（复用 8×16 字库，画 8px）。这就是为什么中文宽度是英文的两倍。

【提示】`CN_FindGlyph` 是 O(n) 线性查找。88 个字时最坏 88 次比较，完全无感；若字库扩到几百字，建议改成"按 Unicode 排序 + 二分查找"。

## 7.7 新增中文词条的标准流程

以新增「系统信息页」需要「系统信息 / 容量」两个词为例（电压/电流/温度已存在）：

**第 1 步**：改脚本 `STRINGS`：

```python
    "SYS_INFO": "系统信息",
    "CAPACITY": "容量",
```

**第 2 步**：重跑：

```bash
cd project/tools
python gen_chinese_font.py
```

脚本会重建字库（自动补上"系/统/信/息/容/量"等新字）和词条头文件。

**第 3 步**：确认产物，`cn_strings.h` 出现新宏：

```c
static const uint8_t CNSTR_SYS_INFO[]  = {0xE7, 0xB3, 0xBB, ... , 0x00};
static const uint8_t CNSTR_CAPACITY[]  = {0xE5, 0xAE, 0xB9, ... , 0x00};
```

宏名规则：`STRINGS` 的 key 加 `CNSTR_` 前缀。

**第 4 步**：代码里用：

```c
LCD_ShowChineseStr(x, y, GREEN, CNSTR_SYS_INFO);
```

**第 5 步**：重新编译（字库数据变了，必须全量重编）。

## 7.8 常见疑问

**Q：只加一个孤立的字（不成词）怎么办？**
放进 `EXTRA_CHARS`：`EXTRA_CHARS = list("年月日...")`。

**Q：某个字显示成空白？**
该字没进字库。检查它是否在 `STRINGS`/`EXTRA_CHARS`，以及是否重跑过脚本；另确认系统字体里有这个字（生僻字、emoji 可能缺失）。

**Q：能显示任意中文（如串口输入的）吗？**
不能。这是**固定词条**方案，只支持预取过模的字。要显示任意中文需外接字库芯片（如 GT21L16S2W）或内置全字库（几百 KB Flash），对本项目不划算。

**Q：字看起来缺笔画？**
多半是取模时 16px 下没裁包围盒/居中（7.5 第②步），或绘制与取模的字宽不一致（7.5 提示）。

## 7.9 本章小结

- 中文显示 = 预先"取模"成 16×16 单色点阵（32 字节/字，高位在左）。
- 脚本产出三文件：数据（自动）、词条（自动）、绘制函数（手写，不归脚本管）。
- 日常只改 `STRINGS` + 重跑；字库数据文件勿手改。
- 取模四步：渲染 → 裁包围盒居中 → 二值化 → 打包成 16-bit 行。
- 绘制链路：CN_FindGlyph（查）→ LCD_ShowChinese（画单字）→ LCD_ShowChineseStr（画串，中英混排）。
- 新增词：改脚本 → 重跑 → 用 `CNSTR_XXX` → 重编译。
