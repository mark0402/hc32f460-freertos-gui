# 第 34 章　最小可运行示例

【本章学习目标】

读完本章，你应该能回答：

1. 一个 GUIslice 程序，骨架由哪几步固定动作组成？
2. `gslc_Init` / `gslc_FontSet` / `gslc_PageAdd` / `gslc_ElemCreateXxx` / `gslc_Update` 各在干什么？
3. 创建一个按钮需要声明哪些信息？按钮文本为什么可以传空串？
4. 主循环里 `gslc_Update()` 到底在重复做什么？
5. 这套骨架在本工程 `gui.c` 里分别对应到哪些代码？

本章**不引入任何业务**（不看时钟、不看中文、不看图形），只把 GUIslice 的"骨架"单独拎出来讲清楚。先建立"一个能跑的 GUI 长什么样"，再回真实工程读复杂的页面，就不会迷路。

---

## 4.1 为什么先跑"最小示例"

真实工程 `gui.c` 里，一个页面初始化往往夹杂着：坐标常量、中文标签、焦点状态、脏标记、跳转函数……新手直接读，很容易被这些"业务杂音"淹没，看不清 GUIslice 本身的骨架。

所以我们先做一次"降噪"：把业务全部去掉，只保留 GUIslice 的必需要素，看看一个**最小能跑的界面**由什么组成。理解了骨架，再往里塞业务，就是"填空"而不是"解谜"。

【提示】本章的代码片段是**教学骨架**（为了聚焦概念，去掉了错误处理和部分参数），它们用来说明"调用顺序和职责"。真实、可编译、带完整参数的代码，在第 35 章之后的各章以及工程 `gui.c` 里。

---

## 4.2 最小骨架：五步法

一个 GUIslice 程序，无论多复杂，都逃不出下面五步：

```
① 准备驱动与全局对象
② 初始化 GUI（gslc_Init）+ 注册字体
③ 注册一个页面（gslc_PageAdd）
④ 往页面里创建元素（gslc_ElemCreateXxx）
⑤ 进入主循环，每帧 gslc_Update()
```

画成流程图：

```
        ┌─────────────┐
        │ ① 驱动/对象  │
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │ ② gslc_Init │  告诉框架: 多少页、字体在哪、屏多大(由 drv 回填)
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │ ③ PageAdd   │  注册页面 + 它的元素池大小
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │ ④ ElemCreate│  往页面里放按钮/文本，声明位置ID样式
        └──────┬──────┘
               ▼
        ┌──────────────────┐
        │ ⑤ while(1)       │  gslc_Update()  // 每帧重绘脏元素
        │   处理输入/改状态 │
        └──────────────────┘
```

## 4.3 逐行讲解骨架

### ① 准备驱动与对象

```c
gslc_tsGui     gslc;          // GUI 全局对象（框架的"大脑"）
gslc_tsDriver  m_drv;         // 驱动对象（指向我们实现的 gslc_Drv* 回调）
gslc_tsPage    sPage[1];      // 页面池，这里只有 1 页
gslc_tsElem    sElem[8];      // 该页的元素池，最多 8 个
gslc_tsElemRef sElemRef[8];   // 元素的"引用"数组（框架内部用）
```

【注意】`sElem` 和 `sElemRef` 是**静态数组**，大小就是"这个页面最多能放多少元素"。池不够时 `ElemCreate` 会返回 NULL 且不报错——这是新手最常见的"控件不显示"原因之一。

### ② 初始化 GUI

```c
if (!gslc_Init(&gslc, &m_drv, sPage, 1, sFont, 1)) { /* 错误处理 */ }
gslc_FontSet(&gslc, 0, GSLC_FONTREF_PTR, NULL, 16);   // 注册 0 号字体, 16px
```

- 第 1 个参数 `&gslc`：框架大脑。
- 第 2 个 `&m_drv`：驱动对象（里面挂着你的 `gslc_Drv*` 回调）。
- 第 3、4 个 `sPage, 1`：**页面池**和**页数**。页数必须和池大小、实际 `PageAdd` 的数量一致。
- 第 5、6 个 `sFont, 1`：字体数组和字体数。

`gslc_Init` 内部会调用 `gslc_DrvInit()`（就是第 33 章说的那个），由你的驱动回调把屏的宽高回填给框架。这是"框架怎么知道屏多大"的答案。

### ③ 注册页面

```c
gslc_PageAdd(&gslc, 0, sElem, 8, sElemRef, 8);
```

- 第 2 个参数 `0`：**页码**。
- 后四个参数：`sElem, 8, sElemRef, 8` —— 这一页用的元素池及其大小（必须 ≥ 实际创建数）。

### ④ 创建元素（以按钮为例）

```c
gslc_tsElemRef* pBtn = gslc_ElemCreateBtnTxt(
    &gslc,        // 框架大脑
    1,            // 元素 ID（在当前页内唯一）
    0,            // 所属页面（0 号页）
    (gslc_tsRect){10, 10, 100, 30},   // 位置与大小 {x, y, w, h}
    "",           // 按钮文字（本工程传空串，中文另画）
    1u,           // 文字缓冲区长度
    0,            // 字体 ID（0 号）
    NULL          // 点击回调（最小示例不绑定）
);
```

逐参数对应第 33 章的"元素属性表"：ID=1、页面=0、位置=`{10,10,100,30}`、类型=按钮、内容=`""`、字体=0。

【提示】**为什么按钮文字可以传空串 `""`？** 因为按钮这个"控件"本身 = 矩形框 + 文字，二者是分开的。你完全可以先画一个空按钮（只有框），再在它的位置上方手绘任意内容（比如中文）。本工程正是这么干的——按钮只当"画框 + 高亮"用，中文由 `DrawCnLabelInBox` 叠加。这一招是理解本工程"混合绘制"的钥匙。

### ⑤ 主循环

```c
gslc_SetPageCur(&gslc, 0);     // 切到 0 号页显示
while (1) {
    // （这里将来放：读输入、改元素状态）
    gslc_Update(&gslc);        // 框架重绘所有"脏"元素
    delay(20);                 // 简单的帧间隔
}
```

`gslc_Update()` 就是第 2、3 章反复说的"重绘调度"：它检查哪些元素脏了，调用对应的 `gslc_DrvDrawXxx` 把它们画（或擦）在屏上。

【注意】最小示例里 `delay(20)` 只是示意。真实工程里这是 FreeRTOS 的任务延时 `vTaskDelay(pdMS_TO_TICKS(20))`，让出 CPU 给别的任务。但"每帧 Update 一次"这个节奏不变。

## 4.4 在最小骨架上"动一下"

光有静态按钮没意思，加一点交互感受重绘。假设我们想：每按一次键，按钮文字在 "A" 和 "B" 之间切换。

```c
char sBuf[4] = "A";
gslc_tsElemRef* pBtn = gslc_ElemCreateBtnTxt(&gslc, 1, 0,
    (gslc_tsRect){10, 10, 100, 30}, sBuf, sizeof(sBuf), 0, NULL);

gslc_SetPageCur(&gslc, 0);
while (1) {
    if (key_pressed()) {                 // 伪代码: 有按键
        strcpy(sBuf, (sBuf[0]=='A') ? "B" : "A");      // 改内容
        gslc_ElemSetTxtStr(&gslc, pBtn, sBuf);         // 关键: 通过接口通知框架
    }
    gslc_Update(&gslc);                  // 框架发现文字变了 → 重绘按钮
    delay(20);
}
```

这里的关键动作是 `gslc_ElemSetTxtStr()`：**你不能直接改 `sBuf` 然后指望屏幕变**——你必须通过这个接口，框架才会知道"按钮的文本脏了"，下一帧 `gslc_Update()` 才会重画它。

这正是第 33 章 3.4 里"脏"字的落地：框架不知道你怎么改了数据，它只在你**通过它的接口**改元素时才标记脏。

【注意】本工程因为中文不能进 C 源码，按钮文字传的是空串，所以"改文本"这个动作在本工程里**不用于中文**；中文是另一套手绘机制（第 7、10、12 章）。但 ASCII 的状态栏、数值，依然走 `ElemSetTxtStr` 这条路。

## 4.5 把骨架对应到本工程

现在"降噪"结束，看真实工程 `gui.c` 里这五步在哪：

| 骨架步骤 | 本工程代码位置 | 说明 |
|---|---|---|
| ① 对象/池 | `sPage[2]`、`sElemMain[8]` 等定义 | 第 35 章后会看到，初始是 2 页 |
| ② `gslc_Init` | `gslc_Init(&gslc, &m_drv, sPage, 2, sFont, 1)` | 页数 2 |
| ② `gslc_FontSet` | `gslc_FontSet(&gslc, 0, GSLC_FONTREF_PTR, NULL, 16)` | 占位字体 |
| ③ `gslc_PageAdd` | `gslc_PageAdd(&gslc, 0, sElemMain, ...)`、`...1...` | 主页 0、设置页 1 |
| ④ `ElemCreate` | `gslc_ElemCreateTxt(...)`、`gslc_ElemCreateBtnTxt(...)` | 状态栏 + 4 按钮 |
| ④ 中文/图形 | `DrawCnLabelInBox(...)`、`DrawShapeArea(...)` | 手绘，不在框架元素里 |
| ⑤ `SetPageCur` | `gslc_SetPageCur(&gslc, 0)` | 启动后切到主页 |
| ⑤ 主循环 | `gslc_Update()` + `DrawCnLabels()` + `DrawShapeArea()` | 见第 42 章 |

你会看到：工程的 `vGuiTask()` 函数，骨架就是 ②→③→④（初始化时一次性做完），然后进入 ⑤ 主循环。

【提示】本工程还有"启动页"（Logo + 倒计时），它**不是** GUIslice 页面，而是 `gslc_Init` 之前用纯 `tftlcd` 直画的。原因很简单：那时 GUIslice 还没初始化，没法用框架元素。这再次印证第 33 章的铁律一——GUIslice 只管它初始化之后的部分。

## 4.6 你能"看到"的和"看不到"的

跑通最小示例（或读懂本工程骨架）后，建议建立这样的心理画像：

**你能直接看到的：**
- 按钮框、状态栏文字（GUIslice 元素，框架画）；
- 图形区、中文标签（手绘，应用层画）。

**你看不到、但框架在做的事：**
- 维护每个元素的位置/状态/脏标志；
- 每次 `gslc_Update()` 计算"哪些矩形要重画"；
- 把"重画某元素"翻译成 `gslc_DrvDrawXxx` 回调；
- 通过回调把像素送上屏。

**你最该记住的一句：**
> GUIslice 把"画什么、画在哪"和"怎么画像素"解耦了。你写界面，是在填"元素表"；真正的像素，由 `gslc_Drv*` → `tftlcd` 负责。

## 4.7 本章小结

- 最小 GUIslice 程序 = 五步：准备对象 → `gslc_Init`+`FontSet` → `PageAdd` → `ElemCreate` → 主循环 `gslc_Update`。
- `gslc_Init` 的页数、`PageAdd` 的池大小、`ElemCreate` 的池大小三者必须一致，否则越界或元素创建失败。
- 按钮文字可传空串：按钮 = 框 + 文字，二者可分；本工程用空按钮框 + 手绘中文。
- 改元素内容必须走 `ElemSetTxtStr` 这类接口，框架才会标记"脏"并重绘。
- 本工程的 GUI 骨架就是这几步，复杂处在于"手绘叠加"和"多页面/状态机"，而非 GUIslice 本身。
