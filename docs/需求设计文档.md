## 1. 设备总览与目标

### 1.1 这到底是什么设备

这个工程做出来的是个基于 HC32F460 的小终端，带一块 240×135 的彩屏：

- 一块 240×135 的 SPI 彩色 LCD 作为唯一输出；
- 一个物理按键（PC13）作为唯一输入；
- 上电先显示开机 Logo + 5 秒倒计时，然后进入**主页**——左侧选图形（矩形 / 三角 / 五角星 / 六芒星），右侧实时画出来，底部一行实时墙钟；
- **长按**进**设置页**，用同一个键的"短按 / 长按"编辑年/月/日/时/分/秒，保存后掉电不丢；
- 一根 USB 串口引出**统一控制台组件** `console`：分级异步日志（`LOG_ERR`/`WARN`/`INFO`/`DEBUG`，启动早期日志即可见）+ 自助注册命令行（`help` / `led` / `echo` / `gettime` / `uptime` / `settime`，支持行编辑 / 历史），可在电脑上直接对时、看运行时间、看启动与运行日志；
- 三色 LED（PA00/PA01/PA02）做心跳灯，可用 `led on|off|blink` 控制（三灯同模式）。

别看功能不多，从裸机外设、实时系统、GUI 框架移植，到单键交互、硬件 RTC、Flash 掉电保存、中文/图片资源生成，嵌入式应用开发里该碰的坑基本都覆盖到了。跟着做一遍，等于把这条链路完整走了一道。

### 1.2 硬件清单（设计必须服从的前提）

| 项 | 规格 | 对设计的影响 |
|---|---|---|
| 主控 | HC32F460，200MHz，Cortex-M4F | 200MHz 来自 XTAL 8MHz → MPLL；晶振不起时回退 HRC 16MHz |
| 显示屏 | 240×135 横屏，ST7789 类，**SPI3（带 DMA）** | 无触摸，纯输出 |
| 帧缓冲 | **无**（屏无显存可回读） | 动态内容必须"先刷背景再重画" |
| 输入 | 仅 **PC13 单键**（上拉，按下低） | 所有交互靠"短按 / 长按"复用 |
| LED | **PA00/PA01/PA02** 三色输出（心跳 / 常亮 / 常灭） | 最基础的外设，也是"裸机第一步" |
| 串口 | USB 转串口（控制台 + 日志通道） | 统一控制台组件 `console`：命令行对时 / 看 uptime / 回显 + 分级异步日志输出 |
| 编译器 | Keil MDK **ARM Compiler 6（AC6 / armclang）** | 中文走脚本生成的点阵手绘，与编译器无关 |
| 实时系统 | **FreeRTOS V10.4.6**（经 CMSIS6 集成，代码用原生 API） | 任务 / 队列 / 软件定时器 |
| 实时钟 | **硬件 RTC + 32.768kHz 外部晶振（XTAL32）** | 真实日历时间、掉电可续、零 CPU 负担 |
| 持久化 | Code Flash 末尾 8KB 扇区 | 时间掉电保存（日志式磨损均衡） |

### 1.3 通过本项目你能学到什么

| 阶段 | 主题 | 关键知识点 |
|---|---|---|
| 0 | 裸机点亮 LED | GPIO 输出、时钟树（XTAL→MPLL→200MHz）、轮询延时 |
| 1 | 引入 FreeRTOS | 任务、调度器、栈大小、优先级、临界区 |
| 2 | 外设独立任务化 | 任务划分原则、队列（解耦生产者/消费者）、状态机按键、CLI 框架 |
| 3 | 时间服务 | 硬件 RTC + 1s 中断、版本号机制、临界区保护共享数据、Flash 磨损均衡、异步落盘 |
| 4 | GUI 移植 | 开源框架适配层、无帧缓冲局部擦写、脏标记、手绘中文/图形、软件定时器 |
| 5 | 交互与设置页 | 单键短按/长按复用、编辑副本模式、掉电保存、图片取模、中文点阵生成 |

第 4 章就按这 6 个阶段展开，每个阶段讲清楚：加了哪一层、实现了什么、代码落在哪、能学到什么。

### 1.4 文档结构

- **第 1–4 章**：总览、需求汇总、潜在优化点、演进式开发设计（本工程最重要的方法论）；
- **第 5–11 章**：GUI 子系统详细设计（架构 / 界面 / 时间 / 存储 / 接口 / 资源 / 维护），是"已完成需求"的落地参考。

### 1.5 术语

| 术语 | 含义 |
|---|---|
| GUIslice | 开源嵌入式 GUI 框架，本工程界面骨架 |
| 适配层 | `gslc_drv_hc32.c`，把 GUIslice 绘图回调映射到 `tftlcd` |
| 手绘 | 绕过 GUIslice，直接调 `tftlcd` 原语（如 `LCD_DrawLine` / `LCD_ShowChineseStr`） |
| 元素 / Element | GUIslice 中的按钮、文本框等界面零件 |
| 页面 / Page | GUIslice 的一屏界面（0=主页，1=设置页） |
| 时间服务 | `app_time` 模块，以硬件 RTC 为权威时基，对外提供读写 |
| 版本号 | `AppTime_GetVersion()`，每次墙钟变化自增，界面据其判断要不要重绘 |
| 脏标记 | `g_bCnDirty` / `g_bShapeDirty`，标记"某块手绘内容需在下一次 `gslc_Update()` 后重画" |
| 日志式存储 | `nv_store` 的磨损均衡策略：顺序追加记录，写满整扇区才擦 |
| 心跳 / 运行秒 | `g_u32Sec`，由 LED 任务累加的系统运行时间（非墙钟） |

## 4. 开发设计：从裸机 LED 到完整设备

> 这一章是整个文档里最该认真看的部分。我不打算把函数一个个列出来凑篇幅，而是按开发者真正会经历的 6 个阶段来讲：每个阶段说清楚加了什么、实现了什么、代码在哪、能学到什么。跟着走一遍，你手头就有一个结构清楚的带屏设备，而不是一堆零散的驱动 demo。

### 4.2 阶段 0：裸机点亮 LED

**目标**：不依赖任何 OS，验证"芯片能跑、引脚能控、时钟对得上"。

**新增框架/模块**
- 时钟树：XTAL 8MHz → MPLL(×50/÷2) → 200MHz（`SystemClock_Config`，`main.c:53`）；
- 最基础输出外设：`gpio_out.c`（`gpio_out_init` 配 **PA00/PA01/PA02** 三色 LED 为推挽输出，低电平点亮）。

**新增功能点**
- FR-S01（系统时钟配置）、FR-S03 的"灯能亮"（最朴素形态）。

**关键实现（裸机最小形态）**
```c
// 阶段0 的 main 长这样（无 OS）：
SystemClock_Config();
gpio_out_init();
for (;;) {
    PORT_Toggle(LED_OUT_PORT, LED0_PIN);  // 翻转 PA00（三色灯之一）
    Ddl_Delay1ms(500);                    // 裸机延时
}
```

**学到的知识**
- Cortex-M 启动后默认跑 `main`；GPIO 方向/电平寄存器操作；
- 时钟树配置（外部晶振 → PLL → 系统时钟），以及"晶振起不来要回退"的健壮性意识；
- 裸机延时的本质：空转 CPU，浪费——这正是阶段 1 要解决的。

---

### 4.3 阶段 1：引入 FreeRTOS（任务调度）

**目标**：把"一个死循环干所有事"变成"多个任务各干各的，调度器来切换"。

**新增框架/模块**
- FreeRTOS V10.4.6（CMSIS6 软件包）；`main.c` 在 `SystemClock_Config` 之后调 `MX_FREERTOS_Init()` 再 `vTaskStartScheduler()`（`main.c:171-173`）；
- 任务创建集中入口 `RTOSThread.c:MX_FREERTOS_Init`（`RTOSThread.c:50-61`）。

**新增功能点**
- FR-S02（启动调度器、统一创建任务）。

**关键实现**
```c
// 阶段1 起：裸机 for(;;) 变成任务体
static void vLedTask(void *pv) {
    for (;;) {
        PORT_Toggle(...);
        vTaskDelay(pdMS_TO_TICKS(500));  // 让出 CPU，不再空转
    }
}
// main.c:
MX_FREERTOS_Init();          // 创建各任务
vTaskStartScheduler();       // 启动后永远不会返回
```

**学到的知识**
- 任务 vs 函数：任务是"带栈、能被抢占的独立执行流"；
- `vTaskDelay` 让出 CPU（对比阶段 0 的空转延时）；
- 栈大小（`configMINIMAL_STACK_SIZE`）与优先级的含义；
- 调度器启动后 `main` 退出，系统由任务驱动。

---

### 4.4 阶段 2：外设独立任务化（LED / 按键 / 串口 CLI）

**目标**：把每个外设拆成独立任务，用**队列**解耦"产生事件"和"消费事件"，互不等赖、互不阻塞。

**新增框架/模块**
- **LED 任务**（`bsp_led.c:vLedTask`）：500ms 心跳 + 累加 `g_u32Sec`；模式由全局 `g_u8LedMode` 控制（由 `led` 命令写入）；
- **KEY 任务**（`bsp_key.c:vKeyTask`，`bsp_key.c:41-116`）：10ms 轮询 PC13，去抖 30ms、长按 1000ms，**只发事件到队列** `s_xKeyQ`；
- **控制台内部任务**（已迁入 `console.c`，取代早期 `vUartTask`）：`prv_shell_task` 阻塞等 RX 信号量、做行编辑与命令分发；`prv_print_task` 异步把输出队列的日志/打印搬去串口；
- **按键输入配置** `gpio_input.c`（PC13 上拉输入）；
- **统一控制台组件** `console.c`/`console.h`：把串口收发、分级日志、命令解释器合并为单一组件；命令以 `CONSOLE_CMD_EXPORT` 宏经链接段（`ConsoleCmdTab`）自助注册（参考 RT-Thread finsh），无需手动注册表、不依赖堆；内置行编辑（退格 / 光标 / 历史 / Ctrl+C）；
- **分级异步日志**：`LOG_ERR`/`WARN`/`INFO`/`DEBUG` 四级，经环形队列 + 低优先级打印任务异步发送，调度器未起时同步兜底，保证启动早期日志不丢；
- （历史参考：早期工程曾用 `cli.c` 注册表 + `main.c` 命令表 + `vUartTask` 任务，现为统一 `console` 组件所取代。）

**新增功能点**
- FR-S03（LED 三模式 + `led` 命令）、FR-S04（CLI）、FR-S05（单键去抖识别短按/长按）、FR-S06（串口对时）、FR-S10（统一控制台组件）、FR-S11（分级异步日志）。

**关键实现**
- 按键状态机（节选，`bsp_key.c:56-105`）：
```c
case KEY_ST_PRESSING:
    if (pressed) {
        if (!long_fired && 按住>=1000ms) { 发 KEY_EVT_LONG; long_fired=1; }
    } else {
        if (!long_fired) 发 KEY_EVT_SHORT;   // 没到长按门槛→短按
        state = KEY_ST_IDLE;
    }
```
- 队列解耦：`bsp_key_recv(&ev, 0)` 由 GUI 任务非阻塞取（`RTOSThread.c` 创建 KEY 任务，GUI 主循环消费）。

**学到的知识**
- **任务划分原则**：一个外设一个任务，慢的外设别卡快的外设；
- **队列**是 RTOS 里最常用解耦手段（生产者 KEY 任务 / 消费者 GUI 任务）；
- **状态机**做按键去抖 + 长短按判定（比裸机 `if/else` 稳健）；
- **CLI 框架**：注册表 + 参数解析，命令可插拔。

### 4.5 阶段 3：时间服务（硬件 RTC + 版本号 + 持久化）

**目标**：让设备"知道现在几点"，且**关电不丢、软件零漂移**——这是裸机/轮询方案做不到的。

**新增框架/模块**
- **时间服务** `app_time.c/.h`：
  - 硬件 RTC 配 1s 周期中断，`RtcPeriod_IrqCallback`（`app_time.c:110-137`）是唯一写 `s_tm` 的地方；
  - 对外 `AppTime_Get/Set/Init/RTCInit/GetVersion/Format/DaysInMonth`；
  - 版本号 `s_u32Version`：每次墙钟变化自增，界面据此判断"要不要重绘"；
- **非易失存储** `nv_store.c/.h`：Flash 日志式追加（512 条/扇区，写满才擦）、独立 `NvStore` 任务消费队列异步落盘；
- **耗时初始化并发线程** `vTimeInitTask`（`RTOSThread.c:29-39`）：`NvStore_Init`→`AppTime_RTCInit`（内部 `vTaskDelay` 等晶振约 3s 让出 CPU）→`AppTime_Init`→自删。

**新增功能点**
- FR-S07（RTC 走时零漂移）、FR-S08（掉电保存）、FR-06 的底层支撑。

**关键实现**
- 线程安全读（`app_time.c`）：`AppTime_Get` 用 `taskENTER_CRITICAL` 防 RTC ISR 写到一半被读；
- 异步落盘：`AppTime_Set` 校验后 `NvStore_Save`（任务上下文）；整分自动保存走 `NvStore_SaveFromISR`（中断上下文入队）；
- 并发：`TimeInit` 优先级 0（低于 GUI 的 1），与 GUI 同时跑，不抢闪屏。

**学到的知识**
- **硬件 RTC + 中断采样**：走时 100% 硬件，软件零漂移（对比阶段 0 的软件计数）；
- **版本号/脏标记**是"数据变了才重绘"的通用范式；
- **临界区**保护"ISR 写、任务读"的共享数据；
- **独立任务 + 队列**做异步落盘，避免 Flash 擦写阻塞界面；
- **日志式磨损均衡**：Flash 寿命约放大 512 倍；
- **耗时初始化拆线程**：启动时并行，不黑屏。

## 5. 系统架构设计

### 5.1 软件模块划分

```
┌──────────────────────────────────────────────────────────┐
│ 应用层                                                       │
│  ├─ guislice/gui.c      界面 + 交互（展示层，不计算时间）     │  ← 维护主要改这里
│  ├─ console.c           统一控制台：串口 / 分级日志 / 命令自助注册 / 行编辑 │  ← 调试与验证入口
│  ├─ app_time.c          时间服务（硬件 RTC 权威时基）         │  ← 时间逻辑都在这
│  └─ nv_store.c          非易失存储（独立任务 + 日志式磨损均衡）│  ← 落盘都在这
├──────────────────────────────────────────────────────────┤
│ 框架层   GUIslice      元素 / 页面 / 重绘调度                │  ← 开源库，基本不改
├──────────────────────────────────────────────────────────┤
│ 适配层   gslc_drv_hc32.c  驱动回调映射                      │  ← 移植核心
├──────────────────────────────────────────────────────────┤
│ 驱动层   tftlcd.c        画点/填充/线/字/图                  │  ← 现成底层
├──────────────────────────────────────────────────────────┤
│ 硬件     ST7789 240×135  SPI3 + DMA / 硬件 RTC + XTAL32     │
└──────────────────────────────────────────────────────────┘
        ▲
        │ FreeRTOS 把以上任务调度起来
```

**模块依赖方向（单向、可测）**：
- `gui` → 依赖 `app_time`（读时间展示）、`nv_store`（间接，经 app_time 请求保存）；
- `app_time` → 依赖 `nv_store`（`NvStore_SaveFromISR` / `NvStore_Save`）；
- `nv_store` → **独立**，只依赖 FreeRTOS 队列与 EFM；
- `console` → 仅依赖 FreeRTOS（队列/信号量/任务）+ 底层 USART 驱动 + `app_time`（命令改时间）；调 `Gui_SetRx/SetInfo` 仅为可选上屏（当前为空实现，见 OPT-01），不反向依赖 GUI；
- 三者都不反向依赖 GUI，**界面纯粹是消费者**。

> 为什么要把"时间"和"存储"从 `gui` 里拆出来：界面只该做"展示 + 交互"。一旦让它自己持有时间副本、自己写 Flash，就会出现多个任务抢时间、抢 Flash、职责混乱、难维护的坑。拆开之后——时间权威归 RTC、落盘归存储任务、界面只在版本号变化时重绘——这是整个工程在架构上最看重的一点（见 5.5）。

### 5.2 模块职责一览

| 模块 | 文件 | 职责 | 对外关键接口 |
|---|---|---|---|
| 界面 | `guislice/gui.c/.h` | 画三界面、处理按键、手绘中文/图形、闪屏倒计时 | `Gui_Start` |
| 时间服务 | `app_time.c/.h` | 硬件 RTC 配置、1s 中断采样、进位/校验/格式化、版本号 | `AppTime_Get/Set/Init/GetVersion/...` |
| 非易失存储 | `nv_store.c/.h` | Flash 扫描恢复、异步写记录（独立任务） | `NvStore_Init/Save/SaveFromISR` |
| 控制台 | `console.c/.h` | 串口收发 + 分级异步日志 + 命令自助注册 + 行编辑交互 | `Console_Init` / `Console_Print` / `LOG_*` / `CONSOLE_CMD_EXPORT` |

### 5.3 FreeRTOS 任务划分

| 任务 | 优先级 | 栈(word) | 周期/阻塞 | 职责 | 与 GUI 的关系 |
|---|---|---|---|---|---|
| `GUI` | 1 | 128+512 | 20ms | LCD/GUIslice 初始化 + 渲染循环 + 闪屏软件定时器 | **唯一**可碰 GUIslice 的任务 |
| `KEY` | 2 | 128+64 | 10ms | 轮询 PC13，去抖/长按识别，事件入队 | 产生 `KEY_EVT_SHORT` / `KEY_EVT_LONG` |
| `ConsoleShell` | 2 | 128+256 | 阻塞等 RX 信号量 | 行编辑 + 命令分发（`settime` 调 `AppTime_Set`），不轮询、不占 CPU | 经 `app_time` 改时间，不碰界面；由 `Console_Init` 创建 |
| `ConsoleOut` | 1 | 128+64 | 阻塞等队列 | 消费输出队列，异步把日志 / 打印搬去串口（低优先级） | 由 `Console_Init` 创建；保证业务不被波特率阻塞 |
| `LED` | 1 | 128 | 500ms | 心跳灯 + 累加 `g_u32Sec` | 无关 |
| `TimeInit` | 0 | 128+128 | 自删 | 读 Flash + 配 RTC + 设时（`NvStore_Init`→`AppTime_RTCInit`→`AppTime_Init`） | 与 GUI 并发，初始化完 `vTaskDelete` |
| `NvStore` | 1 | 128+64 | 阻塞等队列 | 消费待写队列，写 Flash（擦除期间 `__disable_irq`） | 异步落盘，不阻塞界面 |

- **任务创建入口**：业务任务集中在 `project/User/RTOSThread.c` 的 `MX_FREERTOS_Init()`（`RTOSThread.c:50-61`）；**控制台任务（`ConsoleShell` / `ConsoleOut`）由 `Console_Init()` 在 `vTaskStartScheduler()` 之前创建**，早于调度器，故启动早期日志无需调度器即可经同步兜底输出。
- **GUI 最先创建**（`Gui_Start()` 第一行），屏立即亮、闪屏立即画；`TimeInit` 最后创建（优先级 0），与 GUI 并发，不抢占闪屏。
- **删除原 `UP` 任务**：走时不再靠任务 `vTaskDelay` 累加，改由硬件 RTC 1s 中断驱动。
- **GUI 取按键非阻塞**：`bsp_key_recv(&ev, 0)`（等待 0 tick），无事件也继续渲染。
- **跨模块更新走接口/队列**：改时间走 `AppTime_Set`，落盘走 `nv_store` 队列；绝不直接操作对方内部状态。

### 5.4 GUIslice 集成方案

- 调用链：应用层只调 `gslc_Init` / `gslc_Update` / `gslc_ElemSetXxx`；框架经函数指针**回调** `gslc_drv_hc32` → `tftlcd`，应用层从不用手动喂底层。
- 文件：`gslc_config_hc32.h`（开关）、`gslc_drv_hc32.c/.h`（适配）、`guislice/gui.c`（页面）、`tftlcd.c`（驱动）、`GUIslice-master/`（官方库，改过 2 处补丁）。

### 5.5 关键设计原则

- **铁律一（GUIslice 只管一部分）**：只负责按钮框 + 状态栏文字；图形和中国字绕过它、直接调 `tftlcd` 手画，且**必须在 `gslc_Update()` 之后**。
- **铁律二（无帧缓冲 = 局部擦写）**：动态内容"先刷背景再重画"；切页前先 `LCD_Clear` 防残留（`SetPageCurClear`，`gui.c:343-347`）。
- **铁律三（C 里没有中文）**：中文以脚本生成字节数组，绝不写进 C 源码。
- **原则四（计时归硬件、显示归界面）**：墙钟由硬件 RTC 推进（`app_time`），界面只 `AppTime_Get()` 读 + 版本号变化才重绘，**不参与任何时间计算**。
- **原则五（线程安全）**：GUIslice 非线程安全，仅 GUI 任务碰；`app_time` 的 `s_tm` 由 RTC ISR 唯一写、任务侧 `taskENTER_CRITICAL` 读；`nv_store` 写 Flash 在专用任务里、用队列解耦。
- **原则六（可观测 / 可调试优先）**：设备须"看得见、可操作"。串口统一收口到 `console` 组件——日志用分级宏（`LOG_*`）异步输出、命令用 `CONSOLE_CMD_EXPORT` 自助注册；加一条命令、加一处日志都只是一行宏的事，内部状态随时能暴露出来，现场调试会省事很多。

### 5.6 控制台组件设计（`console`）

> 设计目标就一句话：让业务模块用最小的代价，既能把内部状态"打出来看"（日志），也能被命令行"遥控"（CLI）。原先分散的 `usart` / `log` / `shell` 三件套被合并成一个组件，对外只暴露 `console.h`。链接段自助注册和 shell 行编辑的思路，参考了 RT-Thread 的 finsh。

**① 串口统一收口**：`console.h` 一组 `CONSOLE_USART` 系列宏描述控制台串口（外设 / 波特率 / 时钟 / 引脚 / 复用 / 中断源必须配套）；换串口只改这一处，业务层不碰底层收发。RX 走「中断 + 环形缓冲 + 信号量」，交互任务阻塞等信号量取字节，不轮询、不占 CPU。

**② 异步打印（不阻塞调用方）**：打印经「环形队列 + 低优先级 `ConsoleOut` 任务」发送，调用方入队即返回，不被串口波特率拖住实时任务。队列满则丢弃（绝不阻塞业务）。`prv_emit` 在调度器未运行时退化为同步直发，保证启动早期日志不丢。

**③ 分级日志（编译期消除）**：`LOG_ERR`/`WARN`/`INFO`/`DEBUG` 四级，低于 `LOG_LEVEL` 阈值的级别编译为空、零运行时开销；每条日志自动带 `[tick][级别]` 前缀，回看有完整时间线。开发开 `DEBUG`、出厂调高到 `INFO`/`WARN` 减体积。

**④ 命令自助注册（核心）**：`CONSOLE_CMD_EXPORT(name, desc, func, params)` 把命令描述符放进独立链接段 `ConsoleCmdTab`，`Console_Init()` 扫描该段一次性注册——无需手动注册表、不依赖堆。GCC 由 `hc32f46x_flash.ld` 提供段起止符号，Keil 由 armlink 自动提供 `$$Base/$$Limit`，双工具链通用。

**⑤ 行编辑交互**：提示符 `> `、退格、左右光标、上下历史（`s_hist_saved` 暂存当前行）、`Ctrl+C` 取消、`ESC` 退出；命令解析后分发到对应 `func`。

**⑥ 内置命令**：`clear` / `led` / `echo` / `gettime` / `settime` / `uptime`，`help` 由框架自动汇总。其中 `settime` 经 `AppTime_Set` 改 RTC 并立即 `nv_store` 落盘——典型体现"不重烧固件即可现场校时并持久化"。

**资源占用**：约 1.5KB RAM（输出队列 + 交互任务栈 + 行 / 历史缓冲），打印任务低优先级空闲。在 HC32F460 这种级别的 SRAM 上，这点开销几乎可以忽略，换回来的可维护性却很实在。

## 7. 时间服务设计（`app_time`）

> 设计底线：**界面只展示、不计算**。时间权威是硬件 RTC。

### 7.1 时基与走时（零软件漂移）

- 时基：片内硬件 RTC，由 **32.768kHz 外部晶振 XTAL32** 驱动（2¹⁵ 分频得 1Hz）。
- 走时 100% 硬件：RTC 配为"1 秒周期中断"，每秒硬件自己跳一格并产生中断。
- **中断采样**：`RtcPeriod_IrqCallback()`（`app_time.c:110-137`，优先级 15、FreeRTOS 安全）把 RTC 当前值读进软件副本 `s_tm`、自增 `s_u32Version++`；该 ISR 是 `s_tm` 的**唯一写者**。
- 软件对走时零负担、零漂移——绝不会被任务抢占变慢。

### 7.2 对外接口（`app_time.h`）

| 接口 | 语义 |
|---|---|
| `AppTime_RTCInit(void)` | 配 XTAL32 + 启动 RTC 硬件（内部 `vTaskDelay` 等晶振约 3s，让出 CPU）；注册 1s 中断回调（不开中断） |
| `AppTime_Init(pRestored, have)` | 用 Flash 恢复值或默认值设时，开启 1s 周期中断（正式开始计时） |
| `AppTime_Get(pt)` | 读当前时间（内部 `taskENTER_CRITICAL`，防半帧） |
| `AppTime_Set(y,mo,d,h,mi,s)` | 校验 + 写硬件 RTC + 立即请求持久化；非法返回 `false` |
| `AppTime_Format(buf,len,pt)` | 格式化为 `YYYY-MM-DD HH:MM:SS` |
| `AppTime_DaysInMonth(y,m)` | 当月天数（闰年正确），设置页校验用 |
| `AppTime_GetVersion()` | 版本号，界面据此判断重绘 |

### 7.3 启动与并发（见 NFR-05）

`TimeInit` 线程（`RTOSThread.c:29-39`）：`NvStore_Init(&t0)`（读 Flash）→ `AppTime_RTCInit()`（配 RTC）→ `AppTime_Init(&t0, bHave)`（设时 + 开 1s 中断）→ `vTaskDelete(NULL)`。与 GUI 并发，3s 晶振等待用 `vTaskDelay` 让出 CPU，不冻结界面。

### 7.4 持久化触发（与时间服务联动）

- **整分自动保存**：`RtcPeriod_IrqCallback` 在 `second==0` 且累加达 `NV_AUTOSAVE_PERIOD_MIN`（=1 分钟，`app_time.c:31`）时，调 `NvStore_SaveFromISR(&s_tm, ...)` 异步入队（`app_time.c:126-136`）。
- **对时立即保存**：`AppTime_Set()` 校验通过后写 RTC 并立即 `NvStore_Save(&t)`（`app_time.c:285`）。
- 串口 `settime` 命令（控制台 `console.c:prvCmdSetTime`）直接调 `AppTime_Set()`，不再穿过 GUI。

## 8. 非易失存储设计（`nv_store`）

> 状态变更：**v1.0 中 `NvSaveTime` 曾被"暂时屏蔽"，掉电保存未生效；v2.0 已重构为独立任务并实际启用。**

### 8.1 存储布局

| 项 | 值 |
|---|---|
| 位置 | Code Flash 末尾 8KB 扇区，`NV_SECTOR_ADDR = 0x0007E000`（512KB Flash 尾部，链接器不占用） |
| 记录 | 每条 16 字节（`nv_rec_t`）：magic(4) + year(2) + month/day/hour/minute/second(各1) + chk(1, 字节4..10 异或) + pad(4) |
| 容量 | 512 条 / 扇区 |

### 8.2 日志式磨损均衡策略

- 从头到尾**顺序追加**记录；写满 512 条才整体擦除一次、从头再来（`nv_store.c:69-78`）。
- 擦除次数被摊薄到 512 次写入才 1 次，Flash 寿命约放大 **512 倍**。
- 上电 `NvStore_Init()` 扫描全扇区，取**最后一条校验正确**的记录为当前时间（`nv_store.c:125-182`）；半写入（掉电中断）记录自动跳过。

### 8.3 独立任务 + 异步写入

- `NvStore_Init()` 创建队列（4 槽）与 `NvStore` 任务（优先级 1，`nv_store.c:168-175`）。
- 调用方用 `NvStore_Save()`（任务上下文）/`NvStore_SaveFromISR()`（中断上下文）把记录**压入队列即返回**，真正的 Flash 擦写在 `NvStore` 任务里完成（`vNvStoreTask`，`nv_store.c:109-120`）。
- 写 Flash 期间 `EFM_SectorErase`/`EFM_SingleProgram` 必须 `__disable_irq()`（`nv_store.c:72-101`）——这段全局停顿被关在最低优先级专用任务里，不污染定时器回调或其它业务任务。
- 队列满则**丢弃**（保存是尽力而为，不阻塞生产者）。

## 10. 中文与图片资源方案

**问题**：GUIslice 自带字体仅 ASCII、屏不认中文 glyph，界面中文需点阵手绘；中文一律由脚本生成字节数组（C 源码不含中文），与编译器版本（AC6/AC5）无关。

**方案（工作纪律）**：`Python 用系统中文字体渲染汉字 → 输出十六进制点阵/字节数组 → C 里只有数字，绝不出现中文`。

### 11.2 千万不要手改的

- `chinese_font_data.c` / `cn_strings.h` —— 脚本生成，会被覆盖；
- `GUIslice-master/` 官方文件（2 处补丁除外）；
- `nv_rec_t` 的 Flash 地址，除非确认链接脚本未占用该扇区；
- 不要在 GUI / 其它任务里直接写 `s_tm` 或调 `EFM_*` 擦 Flash——时间归 `app_time`、落盘归 `nv_store`。

### 11.3 新增一个界面（步骤摘要）

1. 在 `gui.c` 定义新页面元素数组与状态；
2. `gslc_PageAdd()` 注册、`gslc_ElemCreateXxx()` 创建（GUIslice 管的部分）；
3. 中文/图形在 `DrawCnLabels()` / 新增手绘函数里绘制，并在 `gslc_Update()` **之后**调用；
4. 用脏标记控制手绘重画；切页走 `SetPageCurClear` 防残留；
5. 任何时间显示/修改一律经 `AppTime_Get/Set`；任何需要掉电保存的数据经 `nv_store` 队列，勿自行写 Flash；
6. 跨任务更新走模块接口/队列，勿直接碰对方内部状态。

### 11.4 新增一条控制台命令（步骤摘要）

1. 在目标 `.c` 中 `#include "console.h"`，实现一个 `BaseType_t prvCmdXxx(char *out, size_t len, const char *cmd)` 函数；
2. 用 `CONSOLE_CMD_EXPORT(xxx, "xxx: usage\r\n", prvCmdXxx, 0)` 注册；第四参 `0` 表示固定 0 参、`2` 表示至少 2 参、`-1` 表示变长（由命令自行解析）；
3. 把该 `.c` 编进工程即可——`Console_Init()` 会自动扫描 `ConsoleCmdTab` 链接段完成注册，`help` 也会自动带上它，无需改任何注册表、不依赖堆；
4. 需要输出时走 `Console_Print` / `out` 缓冲（经异步队列），不要直接调底层串口发送；
5. 需要记录事件走 `LOG_*` 分级宏，按 `LOG_LEVEL` 控制详略。
