# 第 26 章 软件定时器与硬件 RTC:闪屏倒计时与每秒走时

本工程有两个"按时间自动发生"的功能:

1. **开机闪屏**:显示 LOGO 并倒数 5 秒,然后进入主界面;
2. **万年历走时**:底部状态栏的墙上时钟每秒 +1 秒。

这两个功能看起来都是"和时间打交道",但它们的**时间来源完全不同**,这也是本章要先讲清的核心:

- **闪屏倒计时**只关心"过了多久"(一段时长),不关心现在是几月几号 → 用 **FreeRTOS 软件定时器**(RTOS 层的"到点到一下")。
- **墙上时钟**关心的是**真实的日历时间**,而且要求准、要求掉电可续 → 用 **硬件 RTC**(芯片里的独立日历时钟,由 32.768kHz 外部晶振驱动)。

| | 内容 |
|---|---|
| **本章功能** | 5 秒开机倒计时(软件定时器)+ 墙上时钟每秒走时(硬件 RTC) |
| **用到的 API** | 软件定时器:`xTimerCreate` / `xTimerStart` / `xTimerStop` / `xTimerChangePeriod` / `xTimerGetExpiryTime`<br>RTC / 延时:`RTC_Init`、`RTC_Cmd`、`RTC_IrqCmd`、`vTaskDelay`、`xTaskGetSchedulerState` |
| **要讲清的** | RTC 与软件定时器的本质区别与选型;软件定时器回调跑在哪里;本工程如何躲开"启动卡顿"这个大坑 |

> 本章把"时间"拆成两条主线来讲:**走时归硬件 RTC**(精度、真实时间、零 CPU 负担),**计时归软件定时器**(闪屏这种纯时长)。最后用一个真实的启动优化案例,把"有界面时为什么要规避忙等、为什么要分层"讲透。

---

## 26.1 先分清两种"时间":RTC vs 软件定时器

很多人一上来就把"定时"和"看时间"混为一谈。先建立两个概念:

### 26.1.1 软件定时器:RTOS 层的"到点到一下"

它是 FreeRTOS 提供的一种**调度构造**:你告诉内核"每过 N 个 tick 调我一次回调"。它的底层是 **SysTick 节拍**,本质是"相对时长",**它自己不知道现在是几点几分**。

适合:**"每隔多久干一件事"**——比如闪屏倒数 5 秒、某个状态机每隔 200ms 扫描一次。

### 26.1.2 硬件 RTC:芯片里的"真实日历钟"

RTC(Real-Time Clock)是 MCU 内部一个**独立的外设**,它自己维护"年/月/日/时/分/秒/星期",由一颗 **32.768kHz 外部晶振**驱动,只要备份电源(VBAT)在,即使主电源掉电、芯片复位,它还在走。

适合:**"真实的日期时间"**——万年历、定时任务、日志记录时间戳、对时。

### 26.1.3 选型一句话

> **要不要"真实时间"?要 → 硬件 RTC;只是"每隔多久干一件事" → 软件定时器。**

本工程正是如此:闪屏只是"5 秒时长"→ 软件定时器;底部时钟是"真实日期时间"→ 硬件 RTC。两者各司其职,不要互相替代。

## 26.2 硬件 RTC:原理与本工程用法

### 26.2.1 为什么用外部 32.768kHz 晶振

32.768 = 2¹⁵,经过 15 级二分频正好得到 **1 Hz**,即每秒跳一格,天然适合日历钟。

更重要的是**精度与独立性**:

- **外部晶振温度漂移小**,长期走时准;用 200MHz 主时钟分频也能得 1Hz,但主时钟是 RC/PLL,温漂大、且主时钟一停 RTC 就废。
- **可接 VBAT 备份电源**:主电源掉了,RTC 靠纽扣电池继续走,下次上电时间不丢(本工程若未焊备份电池,则复位后从头开始,但走时精度仍在)。

### 26.2.2 本工程的 RTC 时基:硬件每秒中断 + ISR 采样

关键点:**走时 100% 由硬件完成,软件只负责"采样"**。

我们让 RTC 工作在"1 秒周期中断"模式,每秒硬件自己跳一格,然后产生一次中断;中断里把硬件当前值读进软件副本。这样软件对走时**零负担、零漂移**——绝不会被某个任务抢占而变慢。

```c
/* app_time.c —— RTC 1 秒周期中断回调, 跑在中断里(优先级 15, FreeRTOS 安全) */
static void RtcPeriod_IrqCallback(void)
{
    stc_rtc_date_time_t rt;
    if (RTC_GetDateTime(RtcDataFormatDec, &rt) != Ok) return;

    /* 本 ISR 是 s_tm 的唯一写者, 界面侧用临界段读, 因此此处无需再加临界段 */
    s_tm.year   = (uint16_t)(2000u + rt.u8Year);
    s_tm.month  = rt.u8Month;
    s_tm.day    = rt.u8Day;
    s_tm.hour   = rt.u8Hour;
    s_tm.minute = rt.u8Minute;
    s_tm.second = rt.u8Second;
    s_u32Version++;                              // 版本号 +1, 供界面判断要不要重绘

    if (s_tm.second == 0u)                      // 整分到了, 顺便请求落盘(异步)
    {
        s_u8MinAcc++;
        if (s_u8MinAcc >= NV_AUTOSAVE_PERIOD_MIN)
        {
            s_u8MinAcc = 0u;
            BaseType_t xHigher = pdFALSE;
            NvStore_SaveFromISR(&s_tm, &xHigher);
            portYIELD_FROM_ISR(xHigher);
        }
    }
}
```

> **为什么放中断而不是软件定时器?** 软件定时器(下一节)是 SysTick 节拍驱动的"回调",它本身也依赖调度;而 RTC 中断是**硬件级别**的,哪怕所有任务都在睡,它照样每秒精准触发。走这种"真实时间"就该交给硬件,软件只做轻量采样。

### 26.2.3 配置与启动(AppTime_RTCInit / AppTime_Init)

RTC 启动有固定的仪式,里面藏着一个**最容易踩的坑**(详见 26.5):

```c
/* app_time.c —— 使能外部晶振并等它稳定 */
static void prvXtal32Config(void)
{
    CLK_Xtal32Cmd(Disable);
    prvTaskDelayMs(100u);                       // 关掉后稍等再配(让出 CPU)
    stcXtal32Cfg.enDrv        = ClkXtal32HighDrv;
    stcXtal32Cfg.enFilterMode = ClkXtal32FilterModeFull;
    CLK_Xtal32Config(&stcXtal32Cfg);
    CLK_Xtal32Cmd(Enable);
    prvTaskDelayMs(3000u);                      // ★ 必须等晶振稳定约 3 秒, 否则读数乱
}

void AppTime_RTCInit(void)
{
    prvXtal32Config();                          // 外部晶振上电
    /* 注册 1 秒周期中断回调(先不开中断) */
    stcIrqRegiConf.enIntSrc    = INT_RTC_PRD;
    stcIrqRegiConf.enIRQn      = Int006_IRQn;
    stcIrqRegiConf.pfnCallback = &RtcPeriod_IrqCallback;
    enIrqRegistration(&stcIrqRegiConf);
    NVIC_SetPriority(stcIrqRegiConf.enIRQn, DDL_IRQ_PRIORITY_DEFAULT); // 15, >=5 → FreeRTOS 安全
    NVIC_EnableIRQ(stcIrqRegiConf.enIRQn);

    if (0u == M4_RTC->CR1_f.START)              // 仅在未启动时配置一次(热复位不重复)
    {
        RTC_DeInit();
        RTC_Init(&stcRtcInit);                  // 时钟源 = RtcClkXtal32, 周期中断 = 1 秒
        RTC_Cmd(Enable);                        // 启动硬件走时
        prvTaskDelayMs(1u);
    }
}

void AppTime_Init(const app_time_t *pRestored, bool have)
{
    prvRtcSet(have ? pRestored : &def);         // 用 Flash 恢复值或默认值设时
    RTC_IrqCmd(RtcIrqPeriod, Enable);           // ★ 到这里才"正式开始计时"(开启 1s 采样)
}
```

注意两处"启动"的区别:

- `RTC_Cmd(Enable)`:硬件开始走时,但**还没开中断**;
- `RTC_IrqCmd(RtcIrqPeriod, Enable)`:开启 1 秒周期中断,软件副本 `s_tm` 才开始被每秒刷新。

### 26.2.4 时间服务对外接口 & 版本号机制

`app_time.c` 把"推进、进位、校验、持久化"全部收进去,对外只暴露纯粹的读写接口,界面完全不碰时间计算:

```c
void     AppTime_Get(app_time_t *pt);              /* 读(内部临界段, 读到完整一帧) */
bool     AppTime_Set(uint16_t y, uint8_t mo, ...); /* 写(带校验 + 立即落盘) */
uint32_t AppTime_GetVersion(void);                 /* 版本号, 界面据此判断要不要重绘 */
void     AppTime_Format(char *buf, size_t len, const app_time_t *pt);
uint8_t  AppTime_DaysInMonth(uint16_t year, uint8_t month);
```

`RtcPeriod_IrqCallback` 每次采样后 `s_u32Version++`。界面用"版本号变了才重绘"避免每秒无脑刷屏 50 次(见 26.7)。`AppTime_Get` 内部用 `taskENTER_CRITICAL()` 与 RTC 中断互斥,防止读到"秒已归零、分还没加"的半帧错值(第 19 章临界段)。

## 26.3 软件定时器:为什么需要

先看看不用它会怎样。要让某件事"每 1 秒 / 每 5 秒发生一次",常见两种做法:

**做法一:开一个任务,循环里延时**(本工程早期正是这么做的,后来在 26.9 的重构中删掉了——如今走时归硬件 RTC,软件定时器只负责开机闪屏倒计时)

```c
static void vUptimeTask(void *pv)
{
    for (;;) {
        Gui_TickSecond();                  /* 时间 +1s */
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}
```

代价:白白占一个任务(栈 + TCB),而且它是**相对延时**——`vTaskDelay` 从"调用那一刻"起算 1000ms,任务体耗时或被抢占都会把周期拉长(第 18 章)。

**做法二:用软件定时器**

```c
TimerHandle_t xTimer = xTimerCreate("Splash", pdMS_TO_TICKS(5000), pdFALSE, NULL, prvCb);
xTimerStart(xTimer, 0);
```

内核在"定时器服务任务"里,每到周期就调一次你的回调。

### 软件定时器 vs 任务延时

| | 任务 + `vTaskDelay` | 软件定时器 |
|---|---|---|
| 资源开销 | 一个任务的栈 + TCB | 只要一个很小的数据结构 |
| 周期精度 | 相对延时,会被任务体耗时挤长 | **绝对周期**,由内核按到期时刻维护,不受回调耗时影响 |
| 适合 | 任务本来就要长期存在、且循环里还要干别的事 | 单纯的"到点了做一下" |
| 不用时 | 要删任务 | `xTimerStop()`,零开销 |

**一句话**:这件事"不需要自己的栈、也不需要阻塞等待"→ 用软件定时器,而不是专门开一个任务。闪屏倒计时正是这种典型。

## 26.4 软件定时器原理:回调跑在哪里

这是理解软件定时器最关键、也最容易写错的一点。

软件定时器的回调函数**不是**在中断里执行,而是运行在一个由内核创建的**定时器服务任务(Timer Service / Daemon Task)**里:

1. 内核维护一个"定时器命令队列";
2. 你调 `xTimerStart` / `xTimerStop` / `xTimerReset`,其实是**往队列发一条命令**,不直接操作定时器;
3. SysTick 的 tick 里,内核检查有没有定时器到期;
4. 到期的定时器,其回调由**定时器服务任务**取出来执行。

由此三条铁律:

**① 回调里绝不能调用会阻塞的 API**

`vTaskDelay`、带阻塞超时的 `xQueueReceive`、等信号量……一概不行。回调跑在定时器服务任务里,一旦阻塞,**所有定时器都被卡住**。要等待就用任务,别用定时器。

**② 回调要尽量短**

回调执行期间,其它定时器的回调都得排队等。

**③ 注意栈**

回调用的是定时器服务任务的栈(`configTIMER_TASK_STACK_DEPTH`),不是你自己的任务栈。

> 本工程闪屏回调只做"置一个标志位"(`s_bSplashDone = true`),绝不干重活、绝不阻塞——完美符合三条铁律。

## 26.5 配置:必须先打开 configUSE_TIMERS

软件定时器**默认关闭**。本工程 `FreeRTOSConfig.h` 里:

```c
#define configUSE_TIMERS                         1
#define configTIMER_TASK_PRIORITY                ( 3 )
#define configTIMER_QUEUE_LENGTH                 10
#define configTIMER_TASK_STACK_DEPTH             ( configMINIMAL_STACK_SIZE * 2 )
```

- `configUSE_TIMERS`:总开关。不开则 `timers.c` 整块被编译忽略。
- `configTIMER_TASK_PRIORITY`:定时器服务任务优先级。**要高于使用定时器的任务**,否则回调被延后。本工程设为 **3**,高于 LED/GUI/NvStore 的 1 和 ConsoleShell/KEY 的 2,所以闪屏回调能及时执行。
- `configTIMER_QUEUE_LENGTH` / `configTIMER_TASK_STACK_DEPTH`:命令队列长度与服务任务栈深度(单位是字)。

打开后会多占一个任务和一个队列的堆空间,记得用 `xPortGetFreeHeapSize()` 确认余量(第 23 章)。

> **本工程踩过的坑**:曾有一版 `FreeRTOSConfig.h` 里根本没有 `configUSE_TIMERS`,而 `FreeRTOS.h` 默认把它定义为 0——`timers.c` 虽在编译,但整块被关掉。加定时器前务必先确认这个宏。

## 26.6 用到的 API

```c
/* 创建: 周期(tick)、是否自动重载、ID、回调; 返回句柄, 失败 NULL */
TimerHandle_t xTimerCreate(const char * const pcTimerName,
                           const TickType_t xTimerPeriodInTicks,
                           const UBaseType_t uxAutoReload,   /* pdTRUE=周期, pdFALSE=单次 */
                           void * const pvTimerID,
                           TimerCallbackFunction_t pxCallbackFunction);

BaseType_t xTimerStart (TimerHandle_t xTimer, TickType_t xTicksToWait);  /* 启动 */
BaseType_t xTimerStop  (TimerHandle_t xTimer, TickType_t xTicksToWait);  /* 停止 */
BaseType_t xTimerChangePeriod(TimerHandle_t xTimer, TickType_t xNewPeriod, TickType_t xTicksToWait); /* 改周期 */
TickType_t xTimerGetExpiryTime(TimerHandle_t xTimer);                    /* 查到期时刻 */
```

回调签名固定:`void vCallbackFunction(TimerHandle_t xTimer);`

要点:

- **`xTimerPeriodInTicks` 不能为 0**——内核有 `configASSERT` 会拦。
- **`uxAutoReload`**:`pdTRUE` 周期(反复触发),`pdFALSE` 单次(触发一次即停)。闪屏用**单次**。
- **`xTicksToWait`**:命令队列满时愿意等多久。在**任务里**调用可给 `portMAX_DELAY`;**在中断里**必须用 `xTimerStartFromISR()` 等 `FromISR` 版本。
- **调度器启动前也能创建**:`xTimerCreate` 会顺带建好定时器基础设施,`xTimerStart` 只是把命令排进队列,等调度器跑起来、服务任务开始运行才真正生效。本工程 `Gui_Start()`(调度器启动前)就创建了闪屏定时器。

## 26.7 本工程实战(一):闪屏倒计时(软件定时器,GUI 私有)

闪屏是**纯界面逻辑**,与 RTC 毫无关系——它只想知道"还有几秒",不需要真实时间。所以倒计时归 GUI 自己管,用软件定时器:

```c
/* gui.c —— 倒计时是界面私有的, 不放进时间服务 */
static TimerHandle_t s_xSplashTimer = NULL;
static volatile bool s_bSplashDone   = true;

static void prvSplashTimerCb(TimerHandle_t xTimer)   /* 跑在定时器服务任务里 */
{
    (void)xTimer;
    s_bSplashDone = true;            // 单次定时器到点: 倒计时结束(回调只置标志, 不阻塞)
}

static void prvSplashStart(uint8_t seconds)
{
    if ((seconds == 0u) || (s_xSplashTimer == NULL)) { s_bSplashDone = true; return; }
    s_bSplashDone = false;
    (void)xTimerChangePeriod(s_xSplashTimer, pdMS_TO_TICKS((uint32_t)seconds * 1000u), 0u);
    (void)xTimerStart(s_xSplashTimer, 0u);
}

/* 剩余秒数由定时器"到期时刻"反推, 不自己数数 */
static uint8_t prvSplashRemain(void)
{
    if (s_bSplashDone) return 0u;
    TickType_t now = xTaskGetTickCount();
    TickType_t exp = xTimerGetExpiryTime(s_xSplashTimer);
    if (exp <= now) return 0u;
    uint32_t msLeft = (uint32_t)(exp - now) * (uint32_t)portTICK_PERIOD_MS;
    return (uint8_t)((msLeft + 999u) / 1000u);   // 向上取整, 让 "5" 先显示满约 1 秒
}
```

GUI 任务的闪屏阶段只做"画 + 轮询剩余":

```c
/* vGuiTask: 画闪屏 → 开 5 秒倒计时 → 等结束 → 进主界面 */
LCD_Show_Image(...); LCD_ShowChineseStr(...);     // 立刻画出闪屏(立即可见)
log_debug("boot: splash shown");
prvSplashStart(SPLASH_SECONDS);                    // 5 秒, 软件定时器自计时
log_debug("boot: countdown start");

uint8_t u8LastShown = 0xFFu;
while (!s_bSplashDone)
{
    uint8_t u8Remain = prvSplashRemain();
    if (u8Remain != u8LastShown)                   // 秒数变了才重画
    {
        u8LastShown = u8Remain;
        LCD_Fill(LCD_Width - 20, 0, LCD_Width - 1, 20, BLACK);
        if (u8Remain > 0u) LCD_ShowNum(LCD_Width - 14, 2, (uint32_t)u8Remain, 1, 16);
    }
    vTaskDelay(pdMS_TO_TICKS(20));                 // 20ms 节奏刷新, 不空转
}
```

**为什么用 `xTimerGetExpiryTime` 反推剩余,而不是自己 `for(s=5;s>=1;s--) vTaskDelay(1000)` 数数?**
前者界面只是"把定时器告诉它的剩余秒数画出来",计时权在定时器;后者界面自己在数数。一旦想让倒计时可配置(串口改时长)、或闪屏时要响应按键跳过,后者立刻露馅。这就是**"计时归定时器、显示归界面"**的分工。

> 那 20ms 的 `vTaskDelay` 不是忙等——它是"让出 CPU 20ms 再回来看一眼",让界面在闪屏期间仍能以 20ms 节奏刷新(将来加动画/按键跳过直接加)。这与第 22 章 UART 任务轮询 10ms 是同一类取舍。

## 26.8 本工程实战(二):时间服务 app_time.c(硬件 RTC 驱动)

主界面的墙上时钟**完全不自己算**,只"版本变了就重画一次":

```c
/* vGuiTask 主循环: 墙上时钟由硬件 RTC 每秒中断推进, 界面只展示 */
if (AppTime_GetVersion() != s_u32ClockVer)
{
    app_time_t tm;
    s_u32ClockVer = AppTime_GetVersion();
    AppTime_Get(&tm);
    AppTime_Format(sStatusScratch, sizeof(sStatusScratch), &tm);
    if (pElemStatus) gslc_ElemSetTxtStr(&gslc, pElemStatus, sStatusScratch);
}
```

配套改造(与第 26.2 的时间服务呼应):

- 删除了 `vUptimeTask`(不再需要专门的任务去延时调 GUI);
- 删除了 `Gui_TickSecond()` / `Gui_SetTime()`(界面不再持有、不再计算时间);
- 串口 `settime` 命令直接调 `AppTime_Set()`,不再穿过 GUI;
- 设置页用 `AppTime_Get()` 取工作副本、`AppTime_Set()` 提交。

**界面只读取并展示数据,不参与任何时间计算**——这是本工程时间架构的底线。

## 26.9 本工程实战(三):启动流程与架构优化(重点案例)

前面所有代码都正确,但**把它们"怎么串起来启动"**才是本工程真正踩坑、也最值得讲的地方。核心教训一句话:

> **有界面展示时,任何会抢占 CPU 的忙等行为,都要提前规避。**

### 26.9.1 反例:上电先黑屏几秒

最早的问题链路:`MX_FREERTOS_Init()`(调度器启动前同步执行)里就去做 RTC 初始化,而 RTC 初始化内部有一步**等 32.768kHz 晶振稳定**,要 3 秒。这 3 秒如果写成忙等,现象就是:

- 屏还是黑的(LCD 还没初始化,GUI 任务还没机会跑);
- 整个系统被这一个忙等卡死 3 秒;
- 3 秒后屏才亮、才进闪屏。

用户看到的就是"开机先黑屏好几秒"。

### 26.9.2 坑一:`Ddl_Delay1ms` 是忙等,在 RTOS 任务里会卡死其它线程

`Ddl_Delay1ms` 是**软件空转**——它不主动让出 CPU。一旦在某个 FreeRTOS 任务里调它,这 3 秒里 CPU 被独占,**同优先级甚至低优先级的其它线程全被冻住**。这和我们"用多线程调度"的初衷完全相反。

**正确做法**:在任务里用系统的 `vTaskDelay`(睡眠),让出时间片,其它线程照常调度。我们封装了一个守卫函数:

```c
/* app_time.c —— 任务内毫秒级等待: 用系统 sleep 让出 CPU, 不忙等 */
static void prvTaskDelayMs(uint32_t ms)
{
    if (xTaskGetSchedulerState() == taskSCHEDULER_RUNNING)
        vTaskDelay(pdMS_TO_TICKS(ms));   // 调度器已起: 让出 CPU, 其它线程照跑
    else
        Ddl_Delay1ms(ms);                 // 仅调度器未起(本工程不会发生)才回退忙等
}
```

`xTaskGetSchedulerState()` 这道守卫很重要:若有人在调度器启动前误调(会 HardFault),我们回退到忙等,避免崩溃。

### 26.9.3 坑二:把"耗时初始化"塞进 GUI 任务

即便把忙等改成 `vTaskDelay`,如果"读 Flash + 配 RTC"仍然写在 `vGuiTask` 里,GU!I 任务自己就会被这段耗时逻辑占用,闪屏数字会卡住不动(虽然别的线程能跑了,但 GUI 自己的倒计时被拖住)。

**正确做法:把时间加载拆成独立线程,GUI 最先创建。**

```c
/* RTOSThread.c —— 时间加载线程: 与 GUI 并发的"耗时线程" */
static void vTimeInitTask(void *pv)
{
    (void)pv;
    app_time_t t0;
    bool bHave = NvStore_Init(&t0);   // 1) 读 Flash 里最后一条有效时间
    AppTime_RTCInit();                // 2) 配 XTAL32 + 启动 RTC 硬件(内部 3s vTaskDelay 让出 CPU)
    AppTime_Init(&t0, bHave);         // 3) 设时 + 开启 1s 周期中断(开始计时)
    vTaskDelete(NULL);                // 初始化完自毁, 不占资源
}

/* 业务线程在 MX_FREERTOS_Init 里依次创建, GUI 在最前;
   控制台线程(ConsoleShell / ConsoleOut)由 main.c 的 Console_Init() 更早创建 */
void MX_FREERTOS_Init(void)
{
    Gui_Start();                      // ★ GUI 最先: 立即画闪屏(倒计时用软件定时器, 与 RTC 无关)
    bsp_key_init();                   // KEY 任务在 bsp_key_init 内部创建
    bsp_led_init();                   // LED 任务在 bsp_led_init 内部创建
    xTaskCreate(vTimeInitTask, "TimeInit",
                configMINIMAL_STACK_SIZE + 128, NULL, 0, NULL);   // 耗时线程最后, 优先级 0
}
```

要点:

- **GUI 最先创建**:屏立刻亮、闪屏立刻画,用户体验从"黑屏 3 秒"变成"上电即见 LOGO"。
- **时间加载独立成 `TimeInit` 线程**:和 GUI **并发**运行,互不阻塞。
- **`TimeInit` 优先级 0(低于 GUI 的 1)**:即便它偶尔忙,也绝不抢占 GUI 的闪屏刷新。
- **那 3 秒晶振等待用 `vTaskDelay`**:让出 CPU,GUI 闪屏和其它线程照常跑。
- **闪屏用 FreeRTOS 软件定时器自计时、自显示,与 RTC 是否就绪无关**:闪屏退出时 RTC 通常已在走时;即使异常,最多界面时间不更新,不会影响启动体验。

### 26.9.5 坑点清单(最佳实践)

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | `Ddl_Delay1ms` 忙等,在 RTOS 任务里卡死其它线程 | 任务里用 `vTaskDelay`(系统 sleep)让出 CPU |
| 2 | 把"读 Flash / 配 RTC"等耗时初始化塞进 GUI 任务 → 闪屏卡住、甚至黑屏 | 拆成独立线程(`TimeInit`),GUI 最先创建 |
| 3 | 调度器启动前调 `vTaskDelay` → HardFault | 用 `xTaskGetSchedulerState()` 守卫,未起才回退忙等 |
| 4 | 软件定时器回调里阻塞 / 干重活 → 所有定时器被卡 | 回调只置标志位,绝不阻塞 |
| 5 | RTC 晶振不起振就读取 → 时间乱 | 使能后**等约 3 秒稳定**,且等待要"让出 CPU" |
| 6 | 界面自己算时间 / 自己数秒 → 职责混乱、难维护 | **计时归服务/定时器,显示归界面**;界面只"版本变了才重绘" |
| 7 | 把"真实时间"交给软件定时器 → 掉电丢失、精度受调度影响 | 真实日历时间用**硬件 RTC**,软件定时器只管"时长" |

---

## 26.10 小结

- **两种"时间"要分清**:真实日历时间 → 硬件 RTC;纯时长("每隔多久")→ 软件定时器。本工程闪屏用软件定时器、墙上时钟用 RTC。
- **RTC 走时靠硬件**:32.768kHz 外部晶振驱动,1 秒周期中断里轻量采样进 `s_tm`,零 CPU 负担、精度高、可掉电续。软件只做采样,绝不自己计数。
- **软件定时器跑在定时器服务任务里(非中断)**:回调不能阻塞、要短、用服务任务的栈;用前必须开 `configUSE_TIMERS` 并配齐优先级/队列/栈。
- **界面只展示、不计算**:墙上时钟"版本号变了才重绘";闪屏倒计时由软件定时器自计时,GUI 只画剩余秒数。
- **有界面就必须规避忙等**:启动优化三板斧——① `Ddl_Delay1ms` 忙等换成 `vTaskDelay` 让出 CPU;② 耗时初始化(读 Flash / 配 RTC)拆成独立 `TimeInit` 线程;③ `main` 里 GUI 最先创建、闪屏用软件定时器自计时。最终效果是"上电即见闪屏,RTC 在后台并发初始化,3 秒晶振等待不再冻结任何线程"。
