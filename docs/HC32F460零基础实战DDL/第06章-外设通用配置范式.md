# 第 6 章 外设通用配置范式

到这一章为止，第二篇"通用机制"就完整了。你会发现，HC32 上几乎所有外设的初始化都可以归纳成同一个流程。掌握了这个流程，后面学习任何一个新外设，都只是查几个具体的参数而已。

这一章讲两个所有外设共有的步骤——开时钟门控和配置引脚复用，然后给出统一的配置流程。

---

## 6.1 时钟门控

### 什么是时钟门控

芯片里每个外设都通过一组"与门"连到时钟网络上。这个门关着，时钟信号就到不了外设，外设的寄存器虽然能写地址，但内部电路没有时钟驱动，不会有任何动作。

这是低功耗设计的基本手段：不用的外设关掉时钟，就不消耗动态功耗。

对编程的影响是：**使用任何外设之前，必须先打开它的时钟门**。忘了这一步，现象是代码能编译、能下载、能运行，但外设毫无反应——寄存器写进去读出来还是 0，或者状态标志永远不置位。

这是新手最常踩的坑之一，而且现象很迷惑人，因为代码"看起来完全正确"。

### 四个 FCG 分组

HC32F460 把所有外设的时钟门分成四组，对应四个寄存器：

```c
PWC_Fcg0PeriphClockCmd(periph, Enable);
PWC_Fcg1PeriphClockCmd(periph, Enable);
PWC_Fcg2PeriphClockCmd(periph, Enable);
PWC_Fcg3PeriphClockCmd(periph, Enable);
```

哪个外设在哪个组是硬件定死的，不查的话很容易搞错。以下是从 `driver/inc/hc32f46x_pwc.h` 里整理出的完整清单：

### FCG0

```c
PWC_FCG0_PERIPH_RAMHS     高速 SRAM
PWC_FCG0_PERIPH_RAM0      SRAM
PWC_FCG0_PERIPH_ECCRAM    ECC RAM
PWC_FCG0_PERIPH_RetRAM    保持 RAM
PWC_FCG0_PERIPH_DMA1      DMA 控制器 1
PWC_FCG0_PERIPH_DMA2      DMA 控制器 2
PWC_FCG0_PERIPH_FCM       时钟频率测量
PWC_FCG0_PERIPH_PTDIS     周期检测
PWC_FCG0_PERIPH_AES       AES 加密
PWC_FCG0_PERIPH_HASH      HASH
PWC_FCG0_PERIPH_TRNG      真随机数
PWC_FCG0_PERIPH_CRC       CRC
PWC_FCG0_PERIPH_DCU1~4    数据运算单元
PWC_FCG0_PERIPH_KEY       KEYSCAN 键盘扫描
```

### FCG1

```c
PWC_FCG1_PERIPH_CAN       CAN
PWC_FCG1_PERIPH_QSPI      QSPI
PWC_FCG1_PERIPH_I2C1      I2C 1~3
PWC_FCG1_PERIPH_USBFS     USB 全速
PWC_FCG1_PERIPH_SDIOC1/2  SDIO
PWC_FCG1_PERIPH_I2S1~4    I2S
PWC_FCG1_PERIPH_SPI1~4    SPI 1~4
PWC_FCG1_PERIPH_USART1~4  USART 1~4
```

### FCG2

```c
PWC_FCG2_PERIPH_TIM01/2   Timer0 单元 1/2
PWC_FCG2_PERIPH_TIMA1~6   TimerA 单元 1~6
PWC_FCG2_PERIPH_TIM41~3   Timer4 单元 1~3
PWC_FCG2_PERIPH_EMB       紧急制动
PWC_FCG2_PERIPH_TIM61~3   Timer6 单元 1~3
```

### FCG3

```c
PWC_FCG3_PERIPH_ADC1/2    ADC 1~2
PWC_FCG3_PERIPH_DAC       DAC
PWC_FCG3_PERIPH_CMP       比较器
PWC_FCG3_PERIPH_OTS       片内温度传感器
```

### 容易记错的几个

| 外设 | 分组 | 说明 |
|---|---|---|
| **ADC** | **FCG3** | 很多人误以为是 FCG1 |
| **DMA** | **FCG0** | 和它配合的 SPI/USART 在 FCG1，两者不在同一组 |
| **Timer0** | **FCG2** | 定时器统一在 FCG2 |
| **SPI / USART / I2C** | FCG1 | 通信外设集中在 FCG1 |
| **AOS** | FCG0 | DMA 触发源选择器，与 DMA 同组 |

最后一行需要说明一下。`PWC_FCG0_PERIPH_AOS` 这个宏在我核对的 `hc32f46x_pwc.h` 里没有出现在 FCG0 的定义块中，但开发板的 LCD 驱动里确实调用了 `PWC_Fcg0PeriphClockCmd(PWC_FCG0_PERIPH_AOS, Enable)`。不同版本的驱动文件可能有差异，**以你实际工程里的头文件为准**。用 DMA 触发功能时，如果 DMA 不工作，检查 AOS 的时钟是否打开了。

### 用法

可以一次开多个（同一组内用按位或）：

```c
/* 一次性打开 4 个串口的时钟 */
uint32_t u32Fcg1Periph = PWC_FCG1_PERIPH_USART1 | PWC_FCG1_PERIPH_USART2 | \
                         PWC_FCG1_PERIPH_USART3 | PWC_FCG1_PERIPH_USART4;
PWC_Fcg1PeriphClockCmd(u32Fcg1Periph, Enable);

/* 只开一个 */
PWC_Fcg2PeriphClockCmd(PWC_FCG2_PERIPH_TIM02, Enable);
```

第二个参数是 `Enable` 或 `Disable`。关闭时钟的代码很少用到，除非做低功耗。

### 一个重要例外

**GPIO 不需要开时钟门**。GPIO 挂在始终供电的域上，`PORT_Init()` 直接调用即可。如果你习惯性地去找 `PWC_FCGx_PERIPH_GPIO`，会发现没有这个宏。

## 6.2 引脚复用

### 为什么需要复用

芯片有几十个外设，每个都要占用引脚，加起来远超实际引脚数。解决办法是让一个物理引脚可以承担多种功能，通过配置选择用哪种。这就是引脚复用（Pin Multiplexing）。

比如 PB06 这个引脚，可以配置为：

- 普通 GPIO 输出
- SPI3 的 SCK
- 某个定时器的 PWM 输出
- 某个串口的 TX

同一时刻只能用一种。

### 端口与引脚的表示

HC32 把端口和引脚分成两个参数：

```c
PORT_SetFunc(PortB, Pin06, Func_Spi3_Sck, Disable);
//            ↑端口  ↑引脚  ↑复用功能      ↑副功能
```

端口枚举：`PortA`、`PortB`、`PortC`、`PortD`、`PortE` ...
引脚枚举：`Pin00` ~ `Pin15`

第四个参数用于少数引脚的"副功能"（某些引脚有两种复用功能可选），绝大多数情况填 `Disable`。

### 复用功能名怎么查

复用功能名的格式是 `Func_<外设>_<信号>`：

```c
Func_Spi3_Sck        // SPI3 时钟
Func_Spi3_Mosi       // SPI3 数据输出
Func_Spi3_Miso       // SPI3 数据输入
Func_Usart2_Rx       // USART2 接收
Func_Usart2_Tx       // USART2 发送
Func_Mclkout         // 时钟输出（MCO）
```

完整列表在 `hc32f460_gpio.h` 里，搜索 `Func_` 即可。

### 复用能随便配吗

不能。每个引脚能承担哪些复用功能是芯片设计时定死的，查芯片数据手册的"引脚定义"表（Pinout / Pin Description）。

比如 SPI3 的 SCK 只能在某些特定引脚上（你的板子上是 PB06），你不能把它配到 PA01。

数据手册里的引脚表通常长这样（示意）：

```
引脚    Func0(GPIO)   Func1      Func2      Func3
PB06    Pxy           SPI3_SCK   TMRx_PWM   ...
PB07    Pxy           SPI3_MOSI  ...
```

设计时先查手册确定能怎么配，再画原理图。反过来，你手上的开发板原理图已经定死了连线，所以配置时要按照原理图的连接来。

### 复用与 GPIO 的关系

如果一个引脚配成了复用功能，它就不能同时当普通 GPIO 用了。反过来，引脚默认是 GPIO 功能。

一个常见错误：把引脚配成串口 TX 之后，又用 `PORT_SetBits()` 想让它输出高电平——这不会生效，因为引脚已经被串口外设接管了。

### 释放调试引脚

有一个特殊情况需要注意。部分引脚默认被调试接口占用（JTAG 的 TDI、TDO/SWO），如果你想把它们当普通 GPIO 或复用成外设功能，必须先禁用调试功能：

```c
PORT_DebugPortSetting(TDI, Disable);
PORT_DebugPortSetting(TDO_SWO, Disable);
```

你的开发板上 LCD 用到了 PB03（背光）和 PB08/PB09（DC/RST），其中部分引脚与调试接口冲突，所以 LCD 驱动的初始化里有这两行。

需要注意的是，禁用后可能影响下载和调试。通常保留 SWD 的 SWCLK/SWDIO 两根线用于下载，只释放 TDI/TDO。

## 6.3 统一的配置流程

把第 3 章的配置结构体、本章的时钟门控和引脚复用串起来，加上中断（第 5 章），得到 HC32 外设配置的通用流程。

### 基本流程（所有外设都适用）

```c
/* 1. 定义并清零配置结构体 */
stc_xxx_init_t stcXxxInit;
MEM_ZERO_STRUCT(stcXxxInit);

/* 2. 填充配置参数 */
stcXxxInit.enField1 = Value1;
stcXxxInit.enField2 = Value2;

/* 3. 开外设时钟门（GPIO 除外） */
PWC_FcgxPeriphClockCmd(PWC_FCGx_PERIPH_XXX, Enable);

/* 4. 配置引脚复用（如果外设需要占用引脚） */
PORT_SetFunc(PORT_x, PIN_x, Func_Xxx, Disable);

/* 5. 初始化并检查返回值 */
if (Ok != XXX_Init(M4_XXX, &stcXxxInit))
{
    while(1);        /* 失败处理 */
}

/* 6. 使能外设或具体功能 */
XXX_Cmd(M4_XXX, Enable);
/* 或者单独使能收发、中断等功能 */
XXX_FuncCmd(M4_XXX, XxxRxInt, Enable);
```

### 需要中断时追加

```c
/* 7. 使能外设的中断源 */
XXX_IntCmd(M4_XXX, Enable);

/* 8. 注册中断回调 */
stc_irq_regi_conf_t stcIrqRegiConf;
MEM_ZERO_STRUCT(stcIrqRegiConf);
stcIrqRegiConf.enIntSrc    = INT_XXX;
stcIrqRegiConf.enIRQn      = Int0xx_IRQn;
stcIrqRegiConf.pfnCallback = &XxxCallback;
enIrqRegistration(&stcIrqRegiConf);

/* 9. NVIC 三件套 */
NVIC_ClearPendingIRQ(stcIrqRegiConf.enIRQn);
NVIC_SetPriority(stcIrqRegiConf.enIRQn, DDL_IRQ_PRIORITY_DEFAULT);
NVIC_EnableIRQ(stcIrqRegiConf.enIRQn);
```

### 需要 DMA 时追加

```c
/* 开 DMA 和 AOS 的时钟（FCG0） */
PWC_Fcg0PeriphClockCmd(PWC_FCG0_PERIPH_DMA1, Enable);
PWC_Fcg0PeriphClockCmd(PWC_FCG0_PERIPH_AOS, Enable);

/* 配置 DMA 通道 */
DMA_InitChannel(M4_DMA1, DmaCh0, &stcDmaCfg);
DMA_SetTriggerSrc(M4_DMA1, DmaCh0, EVT_XXX);
DMA_Cmd(M4_DMA1, Enable);
```

### 步骤顺序的原则

**时钟门控必须在初始化之前**。道理很直接：没时钟，写寄存器不生效。

**引脚复用一般在初始化之前**。先告诉引脚"你现在归串口管了"，再配置串口本身。不过顺序反了有时候也能工作，因为引脚复用是独立的配置。

**中断注册和 NVIC 使能放在最后**。如果外设还没配好就开中断，可能在初始化过程中误触发。

**使能放在最末**。全部配置就绪后再打开外设，避免中间状态产生意外行为。

## 6.4 实例：串口的完整配置

用前面的流程走一遍串口配置，这段代码来自开发板例程 `2.usart/uart_polling`：

```c
int32_t main(void)
{
    en_result_t enRet;

    /* ===== 1. 系统时钟（第 4 章） ===== */
    BSP_CLK_Init();
    SystemCoreClockUpdate();        // 必须，波特率计算依赖它

    /* ===== 2. 开时钟门：串口在 FCG1 ===== */
    PWC_Fcg1PeriphClockCmd(PWC_FCG1_PERIPH_USART2, Enable);

    /* ===== 3. 引脚复用 ===== */
    PORT_SetFunc(PortA, Pin10, Func_Usart2_Rx, Disable);
    PORT_SetFunc(PortA, Pin15, Func_Usart2_Tx, Disable);

    /* ===== 4. 配置结构体 ===== */
    const stc_usart_uart_init_t stcInitCfg = {
        UsartIntClkCkNoOutput,      // 内部时钟源，不输出通信时钟
        UsartClkDiv_1,              // 时钟不分频
        UsartDataBits8,             // 8 位数据
        UsartDataLsbFirst,          // 低位先传
        UsartOneStopBit,            // 1 位停止位
        UsartParityNone,            // 无校验
        UsartSampleBit8,            // 8 位采样
        UsartStartBitFallEdge,      // 起始位下降沿
        UsartRtsEnable,             // 使能 RTS
    };

    /* ===== 5. 初始化 ===== */
    enRet = USART_UART_Init(M4_USART2, &stcInitCfg);
    if (enRet != Ok) { while (1); }

    /* ===== 6. 设波特率（HC32 单独一步） ===== */
    enRet = USART_SetBaudrate(M4_USART2, 115200);
    if (enRet != Ok) { while (1); }

    /* ===== 7. 使能收发 ===== */
    USART_FuncCmd(M4_USART2, UsartRx, Enable);
    USART_FuncCmd(M4_USART2, UsartTx, Enable);

    /* ===== 使用 ===== */
    while (1)
    {
        if (Set == USART_GetStatus(M4_USART2, UsartRxNoEmpty))   // 收到数据
        {
            uint16_t data = USART_RecData(M4_USART2);             // 读
            while (Reset == USART_GetStatus(M4_USART2, UsartTxEmpty));  // 等可发
            USART_SendData(M4_USART2, data);                     // 发回
        }
    }
}
```

对照流程：时钟（第 2 步）、引脚复用（第 3 步）、配置结构体（第 4 步）、初始化（第 5 步）、使能（第 7 步）。串口多了一步设置波特率，这是 HC32 和 STM32 的差异之一。

这个例子没有用中断，所以没有第 8、9 步。第 8 章会加上中断版本。

## 6.5 参数该填什么：查表的方法

配置时最常遇到的问题是"这个字段有哪些可选值"。方法是顺着类型名在头文件里找。

以 `stc_usart_uart_init_t` 的第一个字段为例。打开 `hc32f460_usart.h`，找到结构体定义：

```c
typedef struct stc_usart_uart_init
{
    en_usart_clk_mode_t     enClkMode;        // 时钟模式
    en_usart_clk_div_t      enClkDiv;         // 时钟分频
    en_usart_data_len_t     enDataBits;       // 数据位
    en_usart_first_bit_t    enFirstBit;       // 首位
    en_usart_stop_bit_t     enStopBit;        // 停止位
    en_usart_parity_t       enParity;         // 校验
    en_usart_sample_mode_t  enSampleMode;     // 采样
    en_usart_start_bit_t    enStartBit;       // 起始位
    en_usart_rts_t          enRts;            // RTS
} stc_usart_uart_init_t;
```

每个字段的类型名告诉你该找哪个枚举。比如 `en_usart_data_len_t`，在头文件里搜索它：

```c
typedef enum en_usart_data_len
{
    UsartDataBits8  = 0u,      // 8 位
    UsartDataBits9  = 1u,      // 9 位
} en_usart_data_len_t;
```

枚举值通常有注释说明含义。如果注释不够，就需要查芯片手册的寄存器描述——枚举值最终对应寄存器里的某几个 bit。

### 调试技巧

如果某个配置不起作用，可以反过来验证：初始化之后读回寄存器的值，看是不是你期望的。在调试器里查看 `M4_USART2->CR1` 这样的寄存器，对照手册确认每个 bit 是否正确。这是排查配置问题的终极手段。

## 6.6 练习

### 练习 1 找出你用到的外设的时钟分组

假设你要用这些外设：USART2、SPI3、DMA1、Timer0 单元 2、ADC1。

查本章的分组表，写出每个外设应该用哪个 `PWC_FcgxPeriphClockCmd()` 和哪个宏。

（答案在本章的分组表中。重点注意 ADC 和 DMA，它们最容易记错。）

### 练习 2 故意漏掉时钟门控

写一个简单的串口发送程序，故意注释掉 `PWC_Fcg1PeriphClockCmd()` 这一行，下载运行。

观察现象：程序能运行，但串口没有输出。

然后用调试器查看 `M4_USART2->CR1` 寄存器的值——你会发现写入的值没有生效（读回来是 0 或者不变）。

这个练习让你对"忘了开时钟门"的症状建立直观认识。以后遇到"外设没反应"时，这是第一个要检查的。

### 练习 3 引脚复用的验证

配置 PA15 为 USART2 的 TX，然后用示波器或逻辑分析仪观察这个引脚。

先不调用 `PORT_SetFunc()`，观察引脚电平（应该保持默认状态，无串口波形）。

再调用 `PORT_SetFunc(PortA, Pin15, Func_Usart2_Tx, Disable)`，重新观察（应该出现串口波形）。

如果没有示波器，可以用另一个串口模块接收来验证。

### 练习 4 总结你自己的配置模板

打开你正在做的项目，找一个外设的初始化代码，对照本章的"统一配置流程"，看看它符合哪几步、缺了哪几步。

如果缺了某步但代码能工作，思考为什么（可能是那个外设有特殊之处，或者某步在别处做了）。

这个练习的目的是让你把流程内化成自己的东西，而不是死记本章给出的步骤。

## 6.7 第二篇小结

到这一章，通用机制的部分讲完了。回顾一下：

第 3 章讲了配置系统的三个要点：模块开关决定驱动是否参与编译、配置结构体必须清零、`en_result_t` 反映参数检查结果。

第 4 章讲了启动流程和时钟：复位后经过启动文件的初始化到达 `main`，时钟需要显式配置，升频要处理三件事，`SystemCoreClockUpdate()` 不能忘。

第 5 章讲了中断：HC32 用中断控制器把中断源映射到 NVIC 槽位，需要 `enIrqRegistration()` 注册，回调里必须清标志。

第 6 章把前面的内容串成统一流程：开时钟门、配引脚复用、填结构体、初始化、使能。

这四章的内容不涉及任何具体外设，但会出现在每一个外设的配置代码里。从下一章开始进入第三篇，每章讲一个外设组件，你会发现它们都在套这个流程。

下一章从最简单的 GPIO 开始。
