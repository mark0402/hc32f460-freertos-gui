# 第 12 章 其他常用外设

这一章集中讲五个在实际项目中几乎必用、但例程往往写得很简略的外设：I2C、RTC、看门狗、内部 Flash、低功耗模式。

每个外设按"原理概要 → 关键配置 → 使用要点"的方式展开，不追求面面俱到，重点是让你能上手并避开常见坑。

---

## 12.1 I2C

### 原理概要

I2C 是两线制串行总线：

| 信号 | 说明 |
|---|---|
| SDA | 串行数据线，双向 |
| SCL | 串行时钟线，由主机产生 |

关键特性：

**开漏输出 + 外部上拉**。所有设备（包括主机）都只用开漏方式驱动 SDA/SCL 线，靠外部上拉电阻拉高。这使得多个设备可以共享总线而不冲突——任何设备拉低，线就是低。这就是"线与"逻辑。

**地址寻址**。每个从设备有一个 7 位（或 10 位）地址。主机发起通信时先发送地址，只有地址匹配的设备才响应。

**多主多从**。总线上可以有多个主机（需要仲裁机制）。

**速率**。标准模式 100kHz，快速模式 400kHz，高速模式可达 3.4MHz。

**引脚必须配成开漏**。这是 I2C 硬件要求。如果配成推挽，多个设备同时驱动会造成短路。

### 通信时序

一次典型的"主机写数据"过程：

```
1. 起始条件：SCL 高电平时，SDA 从高变低
2. 发送从机地址（7位）+ 读写位（0=写）
3. 从机回应 ACK（拉低 SDA）
4. 发送数据字节
5. 从机回应 ACK
6. ... 重复 4-5
7. 停止条件：SCL 高电平时，SDA 从低变高
```

"主机读数据"类似，但地址后的读写位是 1，数据由从机驱动，主机每收到一个字节要回应 ACK（最后一个字节回应 NACK 表示结束）。

### DDL 配置

```c
stc_i2c_init_t stcI2cInit;
MEM_ZERO_STRUCT(stcI2cInit);

/* 1. 开时钟门（I2C 在 FCG1） */
PWC_Fcg1PeriphClockCmd(PWC_FCG1_PERIPH_I2C1, Enable);

/* 2. 引脚复用 */
PORT_SetFunc(PortC, Pin04, Func_I2c1_Scl, Disable);
PORT_SetFunc(PortC, Pin05, Func_I2c1_Sda, Disable);

/* 3. 配置 */
stcI2cInit.u32ClockDiv = I2C_CLK_DIV2;      // 时钟分频
stcI2cInit.u32Baudrate = 400000ul;          // 400kHz
stcI2cInit.u32SclTime  = 0ul;
I2C_Init(M4_I2C1, &stcI2cInit, &fErr);      // 第三参数是误差输出

I2C_BusWaitCmd(M4_I2C1, Enable);            // 总线等待
I2C_Cmd(M4_I2C1, Enable);
```

### 收发函数

主机发送：

```c
I2C_Start(M4_I2C1, timeout);                            // 起始
I2C_TransAddr(M4_I2C1, devAddr, I2CDirTrans, timeout);  // 地址+写
I2C_TransData(M4_I2C1, pTxData, size, timeout);         // 数据
I2C_Stop(M4_I2C1, timeout);                             // 停止
```

主机接收：

```c
I2C_Start(M4_I2C1, timeout);
I2C_TransAddr(M4_I2C1, devAddr, I2CDirReceive, timeout);
I2C_MasterDataReceiveAndStop(M4_I2C1, pRxData, size, timeout);
I2C_Stop(M4_I2C1, timeout);
```

这些函数都带超时参数，返回 `en_result_t`。实际项目里建议检查返回值，I2C 通信失败很常见（设备未响应、总线被占用等）。

### 使用要点

**上拉电阻必须有**。通常用 4.7kΩ 接到 3.3V。如果通信不稳定，先检查上拉。

**总线挂死的恢复**。如果通信过程中复位或干扰导致从机一直拉低 SDA，总线会挂死。恢复方法是主机发送 9 个时钟脉冲，或者对 I2C 外设做软件复位：

```c
I2C_SoftwareResetCmd(M4_I2C1, Enable);
I2C_SoftwareResetCmd(M4_I2C1, Disable);
```

**外设地址**。7 位地址，注意有的器件手册给的是 8 位地址（含读写位），需要右移一位。函数参数通常填 7 位地址。

## 12.2 RTC

### 原理概要

RTC（Real Time Clock）提供日历和时钟功能，掉电后可由备用电池维持。

时钟源通常是 32.768kHz 晶振——这个频率是 2 的 15 次方，经过 15 级二分频正好得到 1Hz，即每秒一个脉冲，天生适合计时。

RTC 提供：

- 年/月/日/时/分/秒
- 星期
- 闹钟（按时间或日期触发）
- 周期中断（每秒、每分、每小时）
- 闰年自动处理

### 配置

```c
/* 1. 使能外部 32.768kHz 晶振 */
stc_clk_xtal32_cfg_t stcXtal32Cfg;
MEM_ZERO_STRUCT(stcXtal32Cfg);
stcXtal32Cfg.enDrv = ClkXtal32HighDrv;
stcXtal32Cfg.enFilterMode = ClkXtal32FilterModeFull;
CLK_Xtal32Config(&stcXtal32Cfg);
CLK_Xtal32Cmd(Enable);
Ddl_Delay1ms(3000);              // 等晶振稳定，这一步很重要

/* 2. 配置 RTC */
stc_rtc_init_t stcRtcInit;
MEM_ZERO_STRUCT(stcRtcInit);
stcRtcInit.enClkSource  = RtcClkXtal32;           // 时钟源
stcRtcInit.enPeriodInt  = RtcPeriodIntOneSec;     // 每秒中断
stcRtcInit.enTimeFormat = RtcTimeFormat24Hour;    // 24 小时制
RTC_Init(&stcRtcInit);

/* 3. 设置时间 */
stc_rtc_date_time_t stcDateTime;
MEM_ZERO_STRUCT(stcDateTime);
stcDateTime.u8Year    = 26;
stcDateTime.u8Month   = 1;
stcDateTime.u8Day     = 1;
stcDateTime.u8Weekday = RtcWeekdayThursday;
stcDateTime.u8Hour    = 12;
stcDateTime.u8Minute  = 0;
stcDateTime.u8Second  = 0;
RTC_SetDateTime(RtcDataFormatDec, &stcDateTime, Enable, Enable);

/* 4. 使能 */
RTC_Cmd(Enable);
```

### 使用要点

**晶振起振需要时间**。使能 XTAL32 后要延时等待（通常几百毫秒到几秒），否则 RTC 不走或者走时不准。

**周期中断要单独使能**：

```c
RTC_IrqCmd(RtcIrqPeriod, Enable);
```

**不要在每次复位时重设时间**。上面的代码每次上电都会把时间重置。正确做法是检查 RTC 是否已经运行（比如读一个备份寄存器标志），只在首次上电时设置。

**读时间**：

```c
stc_rtc_date_time_t stcNow;
RTC_GetDateTime(RtcDataFormatDec, &stcNow);
printf("%02d-%02d-%02d %02d:%02d:%02d\r\n",
       stcNow.u8Year, stcNow.u8Month, stcNow.u8Day,
       stcNow.u8Hour, stcNow.u8Minute, stcNow.u8Second);
```

## 12.3 看门狗

### 原理

看门狗（Watchdog Timer）是一个独立的计数器，如果程序没有在规定时间内"喂狗"（重置计数器），计数器溢出就会复位芯片。

用途：检测程序跑飞、死循环等异常，让系统自动恢复。

HC32F460 有两个看门狗：

| 类型 | 时钟 | 特点 |
|---|---|---|
| WDT | 独立 RC | 常规看门狗 |
| SWDT | 独立 RC | 特殊看门狗，可配置更灵活 |

### 配置

```c
stc_wdt_init_t stcWdtInit;
MEM_ZERO_STRUCT(stcWdtInit);

stcWdtInit.enClkDiv      = WdtPclk3Div512;         // 时钟分频
stcWdtInit.enCountCycle  = WdtCountCycle16384;     // 计数周期
stcWdtInit.enRefreshRange = WdtRefresh0To25Pct;     // 喂狗窗口 0%~25%
stcWdtInit.enSleepModeCountEn = Disable;
stcWdtInit.enRequestType = WdtTriggerResetRequest;  // 溢出产生复位
WDT_Init(&stcWdtInit);

WDT_RefreshCounter();        // 启动后必须先喂一次
```

### 窗口看门狗

注意 `WdtRefresh0To25Pct` 这个配置——它表示**只能在计数器 0%~25% 的区间内喂狗**。

这就是窗口看门狗：喂得太早（程序跑飞后一直在循环里喂狗）和喂得太晚（程序卡死）都会导致复位。普通的看门狗只在超时时才复位，无法检测"程序跑飞但仍在喂狗"的情况。

喂狗前先读计数值判断是否在窗口内：

```c
if (WDT_GetCountValue() < (16384u / 4u))     // 在 0~25% 窗口内
{
    WDT_RefreshCounter();
}
```

### 使用要点

**喂狗位置**。通常在主循环里喂，确保所有任务都正常执行到。如果有多个任务，需要设计机制确认所有任务都活着（比如每个任务置一个标志，主循环检查全部标志后再喂狗）。

**调试时关闭**。看门狗会给调试带来麻烦（单步时超时复位）。可以在调试配置里禁用，或者用宏控制。

**喂狗不要太频繁也不要太少**。留出足够余量应对偶尔的长耗时操作。

## 12.4 内部 Flash 读写

### 原理

Flash 存储器用来保存程序，也可以划出一部分保存数据（掉电不丢失）。

Flash 的特性：

- **写入前必须先擦除**。擦除是把所有 bit 置 1，写入是把某些 bit 清 0。不能把 0 改回 1，只能整块擦除。
- **擦除的最小单位是扇区**（通常几 KB），不能只擦一个字节
- **擦写次数有限**，通常 1 万到 10 万次
- **擦写期间 CPU 需要等待**，且不能从被操作的 Flash 区域取指

### 操作

```c
#define FLASH_SECTOR_ADDR   (0x0007C000u)

/* 1. 解锁 */
EFM_Unlock();

/* 2. 使能 Flash 操作 */
EFM_FlashCmd(Enable);
while (Set != EFM_GetFlagStatus(EFM_FLAG_RDY))    // 等就绪
{
    ;
}

/* 3. 擦除扇区（必须先擦后写） */
EFM_SectorErase(FLASH_SECTOR_ADDR);

/* 4. 写入（每次 4 字节） */
EFM_SingleProgram(FLASH_SECTOR_ADDR, 0x5A5A5A5A);

/* 5. 上锁 */
EFM_Lock();
```

读取数据直接按地址访问：

```c
uint32_t val = *(volatile uint32_t *)FLASH_SECTOR_ADDR;
```

### 使用要点

**不要擦除程序区**。Flash 末尾的扇区通常留给数据。要确认你的程序占用了多大空间，选择未被占用的扇区。查看编译后的 map 文件或者程序大小。

**解锁/上锁成对**。`EFM_Unlock()` 后才能擦写，操作完 `EFM_Lock()`。

**擦写期间不能取指**。如果代码从 Flash 执行，擦写同一块区域会导致程序崩溃。HC32 的做法是擦写期间硬件自动暂停 CPU，或者需要把代码放到 RAM 执行。

**寿命考虑**。频繁保存的数据（比如计数器）要考虑磨损均衡，避免反复擦写同一位置。

## 12.5 低功耗模式

### 模式对比

| 模式 | CPU | 外设 | 唤醒源 | 功耗 | 唤醒时间 |
|---|---|---|---|---|---|
| Sleep | 停止 | 运行 | 任意中断 | 中 | 最短 |
| Stop | 停止 | 大部分停止 | 外部中断、RTC | 低 | 短 |
| PowerDown | 停止 | 几乎全停 | 特定唤醒源 | 最低 | 长 |

**Sleep**：内核停止，外设继续工作。任意中断唤醒。适合短暂等待。

**Stop**：大部分时钟关闭，保留 RAM 和寄存器内容。功耗显著降低。

**PowerDown**：几乎全部关闭，功耗最低，但唤醒后需要重新初始化部分外设。

### 进入低功耗

```c
/* 睡眠 */
PWC_EnterSleepMd();

/* 停止（需要先配置） */
stc_pwc_stop_mode_cfg_t stcStopCfg;
MEM_ZERO_STRUCT(stcStopCfg);
/* ... 配置 ... */
PWC_StopModeCfg(&stcStopCfg);
PWC_EnterStopMd();

/* 掉电 */
PWC_EnterPowerDownMd();
```

调用后芯片进入低功耗，直到唤醒源触发。唤醒后从调用点的下一条指令继续执行。

### 配置唤醒源

进入低功耗之前必须先配置好唤醒源，否则芯片永远醒不过来：

```c
/* 外部中断唤醒 */
NVIC_EnableIRQ(...);           // 使能对应的中断

/* RTC 闹钟唤醒 */
PWC_WakeupCmd(...);
```

具体的唤醒源配置函数查 `hc32f460_pwc.h`。

### 使用要点

**降低功耗的其他手段**：

- 关闭不用外设的时钟门（`PWC_FcgxPeriphClockCmd(..., Disable)`）
- 未使用的引脚配成输出低电平或带上拉输入，不要浮空
- 降低系统时钟频率
- 进入 Stop/PowerDown 前把高频时钟切到低速

**唤醒后的处理**。Stop 模式唤醒后，系统时钟可能改变了（取决于配置），需要重新确认。PowerDown 唤醒相当于部分复位，需要重新初始化。

**调试困难**。低功耗模式下调试器可能断开连接。调试时先注释掉进入低功耗的代码，确认逻辑正确后再加回来。

## 12.6 练习

### 练习 1 I2C 读写 EEPROM

如果有 I2C 接口的 EEPROM（比如 AT24C02），练习：

- 写入一个字节到某个地址
- 读回该地址验证

注意：EEPROM 写入后需要等待内部写周期完成（通常 5~10ms）才能读。

思考：如果总线上没有设备，调用 `I2C_TransAddr` 会返回什么？怎么处理这种错误？

### 练习 2 RTC 走时

配置 RTC，每秒通过串口打印一次时间。

验收：观察 60 秒，检查时间是否准确（与电脑时钟对比）。

如果走时不准，检查 32.768kHz 晶振是否起振（`CLK_Xtal32Cmd` 后是否有足够延时）。

### 练习 3 看门狗复位

配置看门狗，超时时间设为 1 秒左右，然后故意不喂狗，观察芯片复位。

然后用 RMU 模块查询复位来源：

```c
stc_rmu_rstcause_t stcRstCause;
MEM_ZERO_STRUCT(stcRstCause);
RMU_GetResetCause(&stcRstCause);
if (Set == stcRstCause.enWdt)
{
    printf("Last reset was caused by watchdog!\r\n");
}
RMU_ClrResetFlag();
```

验收：串口输出显示复位来源是看门狗。

### 练习 4 Flash 保存计数器

实现一个掉电不丢失的启动计数器：

- 上电时从 Flash 读取计数值
- 加 1
- 擦除扇区，写回新值
- 串口打印当前是第几次启动

验收：复位开发板几次，观察计数递增。

思考：每次启动都要擦除整个扇区，如果频繁启动会很快达到擦写寿命上限。有什么改进方法？

### 练习 5 低功耗唤醒（进阶）

配置一个按键作为唤醒源，让芯片进入 Sleep 模式，按键唤醒后翻转 LED 并打印信息，然后再次进入 Sleep。

用电流表（或万用表电流档）测量 Sleep 前后的电流，对比差异。

思考：Sleep 模式能省多少电？如果要把功耗降到最低，还需要做什么？

## 12.7 小结

I2C 是两线制总线，引脚必须开漏 + 外部上拉，通过地址寻址。总线挂死时可用软件复位恢复。

RTC 用 32.768kHz 晶振（2 的 15 次方，分频正好 1Hz）提供日历和周期中断，使能晶振后要等待起振。

看门狗检测程序异常，HC32 的 WDT 支持窗口模式（喂太早或太晚都复位），配合 RMU 可以查询复位来源。

内部 Flash 保存数据需先擦除扇区再写入，操作前 `EFM_Unlock()` 后 `EFM_Lock()`，注意擦写寿命。

低功耗有 Sleep/Stop/PowerDown 三级，进入前必须配置唤醒源，唤醒时间越长功耗越低。
