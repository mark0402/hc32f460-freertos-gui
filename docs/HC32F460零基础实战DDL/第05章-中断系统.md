# 第 5 章 中断系统

从 STM32 转到 HC32 时，中断机制是最让人不适应的一处。STM32 里中断服务函数的名字是写死的，你照着名字写就能接上；HC32 里没有固定名字，你得调用 `enIrqRegistration()` 把自己写的函数"挂"上去。

这一章解释为什么会这样设计，以及这套机制该怎么用。理解之后你会发现它其实很灵活，只是需要知道背后的结构。

---

## 5.1 Cortex-M 的中断基础

先回顾 Cortex-M 内核自带的中断机制，这是所有 Cortex-M 芯片共有的部分。

### NVIC

NVIC（Nested Vectored Interrupt Controller，嵌套向量中断控制器）是内核的一部分，负责：

- 管理中断的优先级
- 决定哪个中断先响应
- 支持中断嵌套（高优先级打断低优先级）
- 自动保存和恢复现场

Cortex-M4 用 4 位表示优先级，共 16 级。**数值越小优先级越高**，0 是最高优先级。这点和 FreeRTOS 的任务优先级相反（RTOS 里数值越大越优先），混用时容易搞错。

### 中断向量表

回顾第 4 章，Flash 开头是中断向量表：

```
0x00000000   初始栈顶
0x00000004   Reset_Handler
0x00000008   NMI_Handler
0x0000000C   HardFault_Handler
...
0x00000040+  外部中断 0
0x00000044   外部中断 1
...
```

前 16 项是内核异常（复位、NMI、HardFault、SysTick 等），之后是芯片厂商定义的外部中断，比如串口中断、定时器中断、外部引脚中断。

STM32 的做法是：向量表里第 N 项对应哪个外设，是芯片设计时就定死的。所以 STM32F103 的向量表里 `USART1_IRQHandler` 永远在第 37 项，你写这个函数名，链接器就把它放对位置。

HC32 的做法不同，下面展开。

---

## 5.2 HC32 的中断控制器

### 多了一层映射

HC32 在片内外设和 NVIC 之间加了一个**中断控制器（INTC）**。它的作用是：任何一个片内外设的中断请求，可以被映射到 NVIC 的任意一个外部中断槽位上。

```
外设中断请求                    INTC                    NVIC
─────────────                ─────────                ─────
INT_USART2_RI  ─┐         ┌─ 可映射 ─┐           Int000_IRQn
INT_USART2_EI  ─┤         │          ├──────────  Int001_IRQn
INT_PORT_EIRQ3 ─┼────────▶│  INTC    │──────────▶ Int002_IRQn
INT_TMR02_GCMA ─┤         │          │            Int003_IRQn
EVT_SPI3_SPTI  ─┘         └──────────┘                ...
（中断源，几十上百个）      （配置寄存器）        （内核，槽位有限）
```

对比一下：

**STM32 模式**：`USART1 中断` → 固定连到 `向量表第 37 项` → 你必须写 `USART1_IRQHandler`。

**HC32 模式**：`INT_USART2_RI 中断源` → 由你决定连到 `Int0xx_IRQn` 中的某一个 → 你注册的回调函数在那个槽位触发时被调用。

### 为什么要这样设计

主要好处是**避免中断冲突**。在固定映射的芯片上，如果两个外设的中断只能共用一个向量（这种情况在资源紧张的设计里很常见），你就得在服务函数里判断到底是谁触发的。HC32 的可映射设计让你把它们分到不同槽位，各自独立。

另一个好处是灵活性。同一个中断源可以在运行时重新映射到不同槽位，从而改变它的优先级顺序。

代价就是多一步配置：你必须显式调用 `enIrqRegistration()` 建立这个映射关系，否则中断源没有连到任何槽位，永远不会触发。

## 5.3 enIrqRegistration 机制

### 三个要素

每次注册中断，需要提供三样东西：

```c
stc_irq_regi_conf_t stcIrqRegiConf;
MEM_ZERO_STRUCT(stcIrqRegiConf);

stcIrqRegiConf.enIntSrc    = INT_PORT_EIRQ13;   // ① 中断源：PC13 按键
stcIrqRegiConf.enIRQn      = Int000_IRQn;       // ② 槽位：挂在哪里
stcIrqRegiConf.pfnCallback = &Key_Callback;     // ③ 回调：触发后执行什么

enIrqRegistration(&stcIrqRegiConf);
```

| 要素 | 类型 | 含义 | 去哪查 |
|---|---|---|---|
| `enIntSrc` | `en_int_src_t` | 中断源编号，标识具体是哪个外设的哪个事件 | `mcu/common/hc32f460.h` |
| `enIRQn` | `IRQn_Type` | NVIC 的中断槽位号 | 同文件，`Int000_IRQn` 起 |
| `pfnCallback` | `func_ptr_t` | 你的回调函数指针 | 自己写的函数 |

### 中断源怎么查

中断源的命名有规律，基本是 `INT_<外设>_<事件>`：

```c
INT_USART2_RI        // USART2 接收中断
INT_USART2_TI        // USART2 发送中断
INT_USART2_EI        // USART2 错误中断
INT_PORT_EIRQ3       // 端口外部中断通道 3
INT_TMR02_GCMA       // Timer0 单元2 通道A 比较匹配
INT_TMR02_GCMB       // Timer0 单元2 通道B 比较匹配
EVT_SPI3_SPTI        // SPI3 发送（DMA 触发源用）
```

注意最后那个 `EVT_` 前缀的，它属于**事件**而不是中断，主要用于触发 DMA，不是给 `enIrqRegistration` 用的。

在 `mcu/common/hc32f460.h` 里搜索 `INT_`（或 `en_int_src_t`）可以列出所有可用中断源。

### 槽位怎么选

`Int000_IRQn` 到 `Int031_IRQn`（具体数量查手册）是 HC32 提供的可映射槽位。选哪个？

原则：
- 每个中断源占用一个**独立**的槽位，不要两个中断源共用
- 槽位号本身不代表优先级，优先级由 `NVIC_SetPriority()` 单独设置
- 官方例程和 BSP 里已经占用了一些槽位，避开它们

> 注：下面列出的是**官方评估板 BSP**（`ev_hc32f460_lqfp100_v1`）给按键分配的槽位。你手上的板子只有一个按键（PC13，外部中断通道 13），实际分配见 README 资源表。这里引用评估板的槽位，只是为了让你知道「哪些槽位已被 BSP 占用，自己写中断时要避开」。

```c
#define BSP_KEY_KEY2_IRQn   (Int025_IRQn)   // 评估板 KEY2 / PD03
#define BSP_KEY_KEY3_IRQn   (Int027_IRQn)   // 评估板 KEY3 / PD05
#define BSP_KEY_KEY4_IRQn   (Int026_IRQn)   // 评估板 KEY4 / PD04
#define BSP_KEY_KEY5_IRQn   (Int028_IRQn)   // 评估板 KEY5 / PD06
```

而开发板 `3.timer0` 例程用了：

```c
stcIrqRegiConf.enIRQn = Int001_IRQn;   // Timer0 通道 A
stcIrqRegiConf.enIRQn = Int002_IRQn;   // Timer0 通道 B
```

写自己的代码时，挑一个没被占用的槽位即可。如果冲突，后注册的会覆盖先注册的，表现为"某个中断突然不工作了"。

### 注册之后还要配 NVIC

`enIrqRegistration()` 建立的是"中断源 → 槽位"的映射。但 NVIC 那边的使能、优先级还要单独设置，标准三件套：

```c
NVIC_ClearPendingIRQ(stcIrqRegiConf.enIRQn);                     // 清挂起
NVIC_SetPriority(stcIrqRegiConf.enIRQn, DDL_IRQ_PRIORITY_DEFAULT); // 设优先级
NVIC_EnableIRQ(stcIrqRegiConf.enIRQn);                           // 使能
```

这三行一个都不能少：

- `NVIC_ClearPendingIRQ` 清除可能存在的挂起标志。如果不清，可能一使能就立刻进一次中断（误触发）。
- `NVIC_SetPriority` 设置优先级。不设的话是默认值，通常能工作，但在有多个中断时可能产生意料之外的嵌套行为。
- `NVIC_EnableIRQ` 使能该槽位的中断。忘了这行，中断永远不触发。

优先级常用的宏：

```c
DDL_IRQ_PRIORITY_00   // 最高
DDL_IRQ_PRIORITY_DEFAULT
DDL_IRQ_PRIORITY_15   // 最低
```

## 5.4 中断回调函数里的规则

### 必须清除中断标志

这是 HC32 中断编程中最重要的一条规则。

硬件产生中断时会设置一个标志位，这个标志**不会自动清除**。如果你不手动清，中断退出后标志还在，NVIC 会认为中断仍然挂起，于是立刻再次进入中断——结果就是程序卡在中断里，主循环永远得不到执行。

表现：程序下载后看起来"死机"了，调试发现 PC 一直在中断函数里。

每种外设清标志的方式不同：

```c
/* 外部中断：清通道标志 */
EXINT_IrqFlgClr(ExtiCh03);

/* 串口：清错误标志 */
USART_ClearStatus(M4_USART2, UsartFrameErr);

/* 定时器：部分自动清，部分需要手动 */

/* DMA：清传输完成标志 */
DMA_ClearIrqFlag(M4_DMA1, DmaCh0, TrnCpltIrq);
```

通常的做法是"先查询、再处理、再清除"：

```c
static void Key_Callback(void)
{
    if (Set == EXINT_IrqFlgGet(ExtiCh03))    // 确认是本通道触发
    {
        /* 处理 */
        BSP_LED_Toggle(LED_GREEN);

        EXINT_IrqFlgClr(ExtiCh03);            // 清除标志
    }
}
```

先查询再处理还有一个好处：如果多个中断源共用处理逻辑，可以区分是谁触发的。

### 中断要尽可能短

中断打断的是主程序的执行。中断函数执行期间，同优先级和更低优先级的中断无法响应。所以中断里应该只做最必要的事。

常见做法是**只置标志，业务逻辑放到主循环**：

```c
volatile uint8_t g_key_pressed = 0;

static void Key_Callback(void)
{
    if (Set == EXINT_IrqFlgGet(ExtiCh03))
    {
        g_key_pressed = 1;              // 只置标志
        EXINT_IrqFlgClr(ExtiCh03);
    }
}

int32_t main(void)
{
    while (1)
    {
        if (g_key_pressed)              // 主循环里处理
        {
            g_key_pressed = 0;
            /* 执行耗时操作：刷新显示、发送串口数据等 */
        }
    }
}
```

中断里应该避免：
- 调用耗时函数（比如 `LCD_ShowString`，涉及 SPI + DMA，可能几毫秒）
- 调用带阻塞的延时
- 做浮点运算（如果没有 FPU 或者 FPU 上下文未保存）
- 用了 RTOS 后，调用非 `FromISR` 版本的 RTOS API

### 共享变量要用 volatile

中断和主循环共享的变量必须加 `volatile`：

```c
volatile uint8_t  g_key_pressed = 0;
volatile uint32_t g_tick_count = 0;
```

原因：编译器不知道这个变量会被中断修改。它可能做这样的优化——把变量值读到寄存器，之后一直用寄存器里的副本，不再访问内存。结果主循环永远看不到中断里的修改。

`volatile` 告诉编译器"这个变量可能在任何时刻被意外修改"，强制每次访问都从内存读取。

### volatile 的局限

需要注意的是，`volatile` 只解决"看不到修改"的问题，不解决"操作不是原子的"问题。

比如主循环里做 `g_counter++`，中断里也做 `g_counter++`。这个操作实际是"读—改—写"三步，如果主循环读到值之后、写回之前被中断打断，中断里的修改就会丢失。

解决方法是操作时关闭中断：

```c
__disable_irq();          // 关中断
g_counter++;              // 临界区操作
__enable_irq();           // 开中断
```

或者用 DDL 提供的临界区保护（如果有的话）。在单核 MCU 上，短时间关中断是最简单可靠的互斥方法。

## 5.5 优先级

### NVIC 优先级的含义

Cortex-M 的优先级**数值越小，优先级越高**。0 最高，15 最低（4 位表示时）。

这与 FreeRTOS 的任务优先级相反——RTOS 里数值越大越优先。如果你在同一个项目里同时用两者，要特别小心这个差异。

### 抢占优先级与子优先级

Cortex-M 允许把 4 位优先级拆成两部分：抢占优先级（preemption priority）和子优先级（subpriority）。

- 抢占优先级高的中断可以打断正在执行的低抢占优先级中断（嵌套）
- 抢占优先级相同时，子优先级高的先响应，但不能互相打断

HC32 通常用 `NVIC_SetPriority()` 直接设置整体的优先级值，不区分这两部分。具体拆分方式由优先级分组寄存器（AIRCR 的 PRIGROUP 位）决定。

裸机开发一般用不到复杂的分组，保持默认、给不同中断设置不同的优先级值即可。

### RTOS 下的特殊要求

如果你用 FreeRTOS，有一条规定：

**在中断里调用 FreeRTOS API（比如释放信号量）的中断，其 NVIC 优先级必须低于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 对应的等级。**

由于 NVIC 是数值越小优先级越高，这里的"低于"意味着**数值要大于等于**某个值。具体来说，能调用 RTOS API 的中断，优先级数值必须在 `[configMAX_SYSCALL_INTERRUPT_PRIORITY >> 4, 15]` 这个范围内。

举例：如果 `configMAX_SYSCALL_INTERRUPT_PRIORITY = 0x50`，那么 `0x50 >> 4 = 5`，所以能调用 RTOS API 的中断优先级数值应在 5~15 之间。

违反这条规定会导致系统在运行一段时间后崩溃，而且很难复现和定位。这个话题在第 15 章还会提到。

## 5.6 完整实例：按键中断

把前面的内容串起来，一个完整的按键中断配置：

```c
#include "hc32_ddl.h"
#include "ev_hc32f460_lqfp100_v1.h"

/* 你的板子按键：PC13，上拉，外部中断通道 13 */
#define KEY_PORT      (PortC)
#define KEY_PIN       (Pin13)
#define KEY_EXINT     (ExtiCh13)               // 外部中断通道
#define KEY_INT_SRC   (INT_PORT_EIRQ13)        // 中断源
#define KEY_IRQn      (Int000_IRQn)           // NVIC 槽位（任选空闲槽位）

volatile uint8_t g_key_pressed = 0;

/* ① 回调函数 */
static void Key_Callback(void)
{
    if (Set == EXINT_IrqFlgGet(KEY_EXINT))     // 确认是通道 3
    {
        g_key_pressed = 1;                     // 只置标志
        EXINT_IrqFlgClr(KEY_EXINT);            // 清标志（必须）
    }
}

/* ② 初始化 */
static void Key_Init(void)
{
    stc_exint_config_t  stcExtiConfig;
    stc_irq_regi_conf_t stcIrqRegiConf;
    stc_port_init_t     stcPortInit;

    MEM_ZERO_STRUCT(stcExtiConfig);
    MEM_ZERO_STRUCT(stcIrqRegiConf);
    MEM_ZERO_STRUCT(stcPortInit);

    /* 配置外部中断 */
    stcExtiConfig.enExitCh   = KEY_EXINT;
    stcExtiConfig.enFilterEn = Enable;              // 硬件滤波，消抖
    stcExtiConfig.enFltClk   = Pclk3Div8;
    stcExtiConfig.enExtiLvl  = ExIntFallingEdge;    // 下降沿（按下）
    EXINT_Init(&stcExtiConfig);

    /* 配置引脚 */
    stcPortInit.enExInt  = Enable;      // 关键：允许外部中断
    stcPortInit.enPullUp = Enable;      // 上拉，未按下为高
    PORT_Init(KEY_PORT, KEY_PIN, &stcPortInit);

    /* 注册中断 */
    stcIrqRegiConf.enIntSrc    = KEY_INT_SRC;
    stcIrqRegiConf.enIRQn      = KEY_IRQn;
    stcIrqRegiConf.pfnCallback = &Key_Callback;
    enIrqRegistration(&stcIrqRegiConf);

    /* NVIC 三件套 */
    NVIC_ClearPendingIRQ(stcIrqRegiConf.enIRQn);
    NVIC_SetPriority(stcIrqRegiConf.enIRQn, DDL_IRQ_PRIORITY_DEFAULT);
    NVIC_EnableIRQ(stcIrqRegiConf.enIRQn);
}

int32_t main(void)
{
    BSP_CLK_Init();
    SystemCoreClockUpdate();

    /* LED 初始化（实际板子 PA00/01/02，低电平点亮） */
    stc_port_init_t stcLedInit;
    MEM_ZERO_STRUCT(stcLedInit);
    stcLedInit.enPinMode = Pin_Mode_Out;
    stcLedInit.enPullUp  = Enable;
    PORT_Init(PortA, Pin00, &stcLedInit);
    PORT_Init(PortA, Pin01, &stcLedInit);
    PORT_Init(PortA, Pin02, &stcLedInit);

    Key_Init();

    while (1)
    {
        if (g_key_pressed)
        {
            g_key_pressed = 0;
            PORT_Toggle(PortA, Pin01);          // 业务处理放主循环（LED1）
        }
    }
}
```

这段代码的结构适用于 HC32 的**所有**中断，只是中断源、清标志的函数不同。后面讲串口中断、定时器中断、DMA 中断时，都是这套流程。

### 外部中断通道号的规律

外部中断通道号和引脚号一一对应：

```
Pin00 → ExtiCh00
Pin01 → ExtiCh01
...
Pin03 → ExtiCh03
...
Pin15 → ExtiCh15
```

所以 PD03 对应 `ExtiCh03`，中断源是 `INT_PORT_EIRQ3`。

有个限制：不同端口的相同引脚号**共用**同一个外部中断通道。比如 PA03、PB03、PC03、PD03 都对应 `ExtiCh03`，同一时刻只能有一个使用。这一点在多按键设计时要注意。

## 5.7 常见问题

### 中断不触发

按顺序检查：

1. 外设本身的中断使能了吗？（比如 `USART_FuncCmd(USART_CH, UsartRxInt, Enable)`）
2. `enIrqRegistration()` 调用了吗？三个要素填对了吗？
3. `NVIC_EnableIRQ()` 调用了吗？
4. 引脚配置里 `enExInt = Enable` 了吗？（外部中断时）
5. 槽位是否被别的中断源占用了？

### 程序卡在中断里

99% 是没清中断标志。检查回调函数里有没有调用对应的 `XXX_ClearXxx()` 或 `XXX_IrqFlgClr()`。

### 中断触发一次后不再触发

也是清标志的问题，或者是中断里意外关闭了中断使能。

### 编译报 enIrqRegistration 未定义

`ddl_config.h` 里 `DDL_INTERRUPTS_ENABLE` 没开。

### 编译报 EXINT_Init 未定义

`DDL_EXTI_ENABLE` 没开。

## 5.8 练习

### 练习 1 亲手制造卡死

把上面例子里的 `EXINT_IrqFlgClr(KEY_EXINT);` 注释掉，重新编译下载，按一次按键。

预期现象：LED 不再响应，程序看起来死机。用调试器暂停，会看到程序停在中断里。

这个练习的价值在于让你对"没清标志"的症状形成肌肉记忆。以后遇到类似现象能立刻反应过来。

### 练习 2 双按键

配置 KEY2（PD03）和 KEY3（PD05）两个按键，分别控制绿灯和蓝灯。

要求两个按键用**不同的中断槽位**（Int025 和 Int027），并在回调函数里区分是哪个按键。

完成后思考：如果两个按键共用同一个槽位会怎样？

### 练习 3 上升沿与下降沿

把触发方式从 `ExIntFallingEdge` 改成 `ExIntRisingEdge`，观察现象变化。

预期：按下时不触发，松开时才触发。

再改成 `ExIntBothEdge`，观察按下和松开都触发。

### 练习 4 中断里做耗时操作的后果

在回调函数里加一个长延时（比如 `Ddl_Delay1ms(1000)`），然后主循环里让另一个 LED 快速闪烁。

观察：中断期间主循环的 LED 停止闪烁。

这个练习直观展示"中断要短"的必要性。之后把耗时操作移到主循环，对比效果。

## 5.9 小结

HC32 在片内外设和 NVIC 之间加了中断控制器，允许把任意中断源映射到任意 NVIC 槽位。这就是需要 `enIrqRegistration()` 的原因，也是它和 STM32 最大的差异。

注册中断需要三个要素：中断源 `enIntSrc`、槽位 `enIRQn`、回调函数 `pfnCallback`。注册之后还要调用 NVIC 三件套（清挂起、设优先级、使能）。

回调函数里必须清除中断标志，否则会无限重复进入中断导致程序卡死。中断应该尽可能短，耗时操作放到主循环，通过 `volatile` 标志传递。

优先级方面，NVIC 是数值越小优先级越高，与 FreeRTOS 任务优先级相反，混用时要小心。
