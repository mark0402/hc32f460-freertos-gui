# 第 4 章 启动流程与时钟系统

这一章分两部分。前半部分讲从按下复位到 `main()` 执行之间发生了什么，后半部分讲时钟树。

为什么要讲这些？因为"程序莫名跑飞"和"时序完全不对"这两类最让人头疼的问题，根源大多在这里。而这两块内容恰好是很多教程会跳过的——它们不涉及具体外设，看起来也不产生"效果"，但它们决定了你后面写的所有代码是否运行在正确的前提下。

---

## 4.1 复位之后发生了什么

### 内核的复位序列

Cortex-M 内核复位后，硬件自动做两件事：

```
1. 从地址 0x00000000 读出 4 字节，作为初始栈顶指针（MSP）
2. 从地址 0x00000004 读出 4 字节，作为复位向量（Reset_Handler 的地址）
3. 跳转到 Reset_Handler 执行
```

这两个地址对应 Flash 的最开头，也就是**中断向量表**的前两项。向量表是一个数组，第一项是栈顶，第二项是复位处理函数，后面依次是各个中断的处理函数地址。

HC32 的向量表在启动文件里定义（`mcu/common/` 下的 `startup_hc32f460.s` 之类），内容大致是：

```assembly
__Vectors
    DCD  __initial_sp              ; 0: 栈顶
    DCD  Reset_Handler             ; 1: 复位
    DCD  NMI_Handler               ; 2: NMI
    DCD  HardFault_Handler         ; 3: 硬件错误
    /* ... 更多中断 ... */
```

### Reset_Handler 做了什么

标准的 CMSIS 启动流程，`Reset_Handler` 依次完成：

```assembly
Reset_Handler
    /* 1. 设置栈指针 */
    LDR  R0, =__initial_sp
    MSR  MSP, R0

    /* 2. 复制 .data 段：从 Flash 搬到 RAM */
    /*    .data 存放已初始化的全局/静态变量 */
    LDR  R0, =_sdata        ; RAM 中的目标地址
    LDR  R1, =_etext        ; Flash 中的源地址
    /* ... 循环复制 ... */

    /* 3. 清零 .bss 段 */
    /*    .bss 存放未初始化的全局/静态变量 */
    LDR  R0, =_sbss
    LDR  R1, =_ebss
    /* ... 循环清零 ... */

    /* 4. 调用 SystemInit */
    BL   SystemInit

    /* 5. 跳转到 main */
    BL   main
```

这里有个值得记住的细节：全局变量为什么一上来就是 0？因为 `.bss` 段被启动代码清零了。而 `int g_val = 100;` 这样的已初始化全局变量，初值存在 Flash 里，启动时被复制到 RAM。这些都是启动文件的功劳，不是 C 语言的特性。

在资源受限的场景下，这个复制过程是有代价的——如果你定义了一个很大的已初始化数组（比如 `uint8_t buf[64*1024] = {1,2,3};`），启动时就要复制 64KB，会明显拖慢启动速度，而且这个数组同时占用 Flash 和 RAM。

### SystemInit 做了什么

`SystemInit()` 定义在 `mcu/common/system_hc32f460.c`，它在 `main()` 之前执行。不同版本的实现略有差异，通常包含：

- 配置中断向量表的位置（如果有重定向）
- 初始化系统时钟到某个默认状态
- 设置 `SystemCoreClock` 全局变量的初值

关键的一点：**执行完 `SystemInit()` 之后，系统时钟是复位默认值**，也就是内部 MRC 8MHz。此时 `SystemCoreClock` 也被设成 8000000。

你在 `main()` 里调用 `BSP_CLK_Init()` 把时钟升到 200MHz，这是第二次配置。很多人的误解是以为 `SystemInit()` 已经配好了时钟，实际上它只保证芯片能跑起来，主频是最低配置。

## 4.2 时钟树

### 为什么需要时钟树

芯片内部不同的部件需要不同的工作频率：

- CPU 内核和高速总线：越快越好
- 某些外设（比如 ADC）：有最高频率限制，太快反而精度下降
- RTC：需要精确的 32.768kHz 来计时
- 低功耗模式：需要关闭高速时钟

单一频率无法满足所有需求，所以芯片内部有复杂的时钟分配网络，这就是时钟树。它的结构是：**选一个时钟源 → 经过倍频得到高频 → 分频给各个部件**。

### 五个时钟源

HC32F460 有五个可选时钟源：

| 源 | 频率 | 特点 |
|---|---|---|
| HRC | 16MHz / 20MHz | 内部高速 RC，精度约 ±1%，无需外部器件 |
| MRC | 8MHz | 内部中速 RC，**复位默认使用** |
| LRC | 32kHz | 内部低速 RC，低功耗时用 |
| XTAL | 4~24MHz | 外部高速晶振，**精度高**，你的板子上是 8MHz |
| XTAL32 | 32.768kHz | 外部低速晶振，供 RTC，你的板子上焊了 |

**复位后默认使用 MRC 8MHz**。这是为什么一个新工程不配时钟也能跑——只是跑得慢，而且精度不高。

内部 RC 的优点是不需要外部晶振、启动快；缺点是精度差（受温度影响明显）。如果你的应用涉及串口通信、精确定时、USB，通常需要用外部晶振。

你的开发板焊了 8MHz 外部晶振，这就是 XTAL。

### 从时钟源到系统时钟

```
     HRC / MRC / LRC / XTAL / XTAL32
                  │
                  ▼
        ┌──────────────────┐
        │  PLL 输入选择     │  CLK_SetPllSource()
        │  或直接使用       │
        └──────────────────┘
                  │
        ┌─────────▼─────────┐
        │      MPLL         │  主锁相环（倍频）
        │  VCO = 入/ M × N  │
        │  P/Q/R = VCO / D  │
        └─────────┬─────────┘
                  │
        ┌─────────▼─────────┐
        │  系统时钟源选择    │  CLK_SetSysClkSource()
        │  选 MPLL 输出     │
        └─────────┬─────────┘
                  │
                  ▼   SYSCLK
        ┌──────────────────┐
        │    总线分频       │  CLK_SysClkConfig()
        └──────────────────┘
           │    │    │    │
          HCLK EXCLK PCLK0~4
```

除了 MPLL，芯片还有 UPLL（专供 USB），这里不展开。

### MPLL 的倍频原理

MPLL 是主锁相环，它做两件事：**先分频、再倍频、再分频**。

配置参数有三个：

```c
stc_clk_mpll_cfg_t stcMpllCfg;
stcMpllCfg.pllmDiv = 1ul;    // M：输入分频
stcMpllCfg.plln    = 50ul;   // N：倍频系数
stcMpllCfg.PllpDiv = 2ul;    // P：输出分频
stcMpllCfg.PllqDiv = 2ul;    // Q：另一路输出分频
stcMpllCfg.PllrDiv = 2ul;    // R：第三路输出分频
```

计算公式：

```
VCO 频率 = (输入频率 / pllmDiv) × plln 
MPLLP   = VCO / PllpDiv
MPLLQ   = VCO / PllqDiv
MPLLR   = VCO / PllrDiv
```

以你的板子为例，输入是 8MHz 外部晶振：

```
VCO   = 8MHz / 1 × 50 = 400MHz
MPLLP = 400MHz / 2    = 200MHz   ← 这个给系统时钟
```

所以最终公式是：

```
系统主频 = (晶振频率 / pllmDiv × plln) / PllpDiv
        = (8MHz / 1 × 50) / 2
        = 200MHz
```

P/Q/R 是三路独立的输出分频，可以产生三个不同频率，分别给系统时钟、USB、其他外设。常规应用只用 P 路。

### PLL 的约束

不是随便填数字都行，芯片手册规定了两个范围：

| 参数 | 允许范围 | 你的配置 |
|---|---|---|
| 输入频率（分频后） | 1 MHz ~ 12 MHz | 8MHz / 1 = 8MHz |
| VCO 频率（倍频后） | 240 MHz ~ 480 MHz | 8 × 50 = 400MHz |

超出范围 PLL 无法锁定，`CLK_MpllCmd(Enable)` 之后 PLL 就绪标志永远不置位。

想改主频时，保持 VCO 在 240~480MHz 之间调整三个参数：

| 目标主频 | pllmDiv | plln | PllpDiv | 验算 |
|---|---|---|---|---|
| 168 MHz | 1 | 42 | 2 | 8/1×42/2 = 168 |
| 200 MHz | 1 | 50 | 2 | 8/1×50/2 = 200 |
| 240 MHz | 1 | 60 | 2 | 8/1×60/2 = 240 |

如果你的板子换成了 12MHz 晶振，需要重新计算，注意 VCO 不要超 480MHz：

```
12 / 1 × 40 / 2 = 240MHz   （VCO = 480MHz，刚好达上限）
12 / 1 × 33 / 2 = 198MHz   （VCO = 396MHz，安全）
```

### 总线分频

系统时钟出来后，再分给各条总线：

```c
stc_clk_sysclk_cfg_t stcSysClkCfg;
MEM_ZERO_STRUCT(stcSysClkCfg);

stcSysClkCfg.enHclkDiv  = ClkSysclkDiv1;   // HCLK  = SYSCLK / 1 = 200MHz
stcSysClkCfg.enExclkDiv = ClkSysclkDiv2;   // EXCLK = SYSCLK / 2 = 100MHz
stcSysClkCfg.enPclk0Div = ClkSysclkDiv1;   // PCLK0 = 200MHz
stcSysClkCfg.enPclk1Div = ClkSysclkDiv2;   // PCLK1 = 100MHz
stcSysClkCfg.enPclk2Div = ClkSysclkDiv4;   // PCLK2 = 50MHz
stcSysClkCfg.enPclk3Div = ClkSysclkDiv4;   // PCLK3 = 50MHz
stcSysClkCfg.enPclk4Div = ClkSysclkDiv2;   // PCLK4 = 100MHz
CLK_SysClkConfig(&stcSysClkCfg);
```

各条总线的用途：

| 总线 | 典型挂载 |
|---|---|
| HCLK | CPU 内核、SRAM、Flash、DMA |
| EXCLK | 外部存储器接口（QSPI 等） |
| PCLK0 | GPIO、部分定时器 |
| PCLK1 | USART、SPI、I2C |
| PCLK2 | 定时器、部分通信外设 |
| PCLK3 | ADC、RTC、部分定时器 |
| PCLK4 | 外设桥、AOS、事件端口 |

具体某个外设挂在哪条总线上要查芯片手册的时钟树图。这个信息很重要：串口的波特率是根据 PCLK1 算的，ADC 的转换时钟来自 PCLK3，定时器的计数时钟来自 PCLK1 或 PCLK2。

## 4.3 升频必须处理的三件事

这是本章最需要记住的部分。仅仅配置 PLL 并不足以让芯片稳定工作在 200MHz，还有三件事必须同时处理。

### 为什么需要它们

问题的根源是**速度不匹配**。CPU 能在 200MHz 稳定工作，但存储器的响应速度跟不上：

- Flash 的访问速度通常在 20~40MHz 量级
- SRAM 稍快，但也远低于 200MHz

CPU 每个周期都要取指令。如果 Flash 需要 5 个周期才能返回数据，而 CPU 只等 1 个周期，读到的就是错误数据——结果是程序跑飞，通常表现为 HardFault。

解决方法是插入**等待周期**：CPU 访问 Flash 时自动多等几个周期，等数据稳定了再读取。频率越高，需要的等待周期越多。

### 第一件：Flash 等待周期

```c
EFM_Unlock();                       // 解锁 Flash 控制寄存器
EFM_SetLatency(EFM_LATENCY_5);      // 设置 5 个等待周期
EFM_Lock();                         // 重新上锁
```

`EFM_SetLatency` 必须在解锁后调用，操作完要上锁，防止程序跑飞时误改写 Flash 内容。

等待周期数和频率的对应关系查芯片手册。在 200MHz 时通常对应 `EFM_LATENCY_5`。

### 第二件：SRAM 等待周期

```c
stc_sram_config_t stcSramConfig;
MEM_ZERO_STRUCT(stcSramConfig);

stcSramConfig.u8SramIdx = Sram12Idx | Sram3Idx | SramHsIdx | SramRetIdx;
stcSramConfig.enSramRC  = SramCycle2;    // 读等待 2 周期
stcSramConfig.enSramWC  = SramCycle2;    // 写等待 2 周期
SRAM_Init(&stcSramConfig);
```

`u8SramIdx` 指定要配置哪些 SRAM 块。回顾第 1 章的存储器映射，HC32F460 有 SRAM1/2/3、高速 SRAM、保持 SRAM 五块，这里一次性全配。`Sram12Idx` 表示 SRAM1 和 SRAM2。

### 第三件：电源模式切换

```c
PWC_HS2HP();     // High Speed → High Performance
```

这与供电能力有关。芯片内部有多个电源域，高频工作时需要更强的驱动能力，否则信号边沿不够陡峭，会导致逻辑错误。

`PWC_HS2HP()` 把电源从"高速模式"切到"高性能模式"。反过来，如果要降低功耗，可以用 `PWC_HP2HS()` 切回。

### 顺序很重要

三件事必须在**切换系统时钟源之前**完成。完整的升频顺序：

```
1. 配置总线分频          CLK_SysClkConfig()
2. 使能外部晶振          CLK_XtalCmd(Enable)
3. 配 SRAM 等待周期      SRAM_Init()
4. 配 Flash 等待周期     EFM_SetLatency()
5. 配置 MPLL 参数        CLK_MpllConfig()
6. 启动 MPLL 并等锁定    CLK_MpllCmd() + 等待就绪标志
7. 切电源模式            PWC_HS2HP()
8. 切换系统时钟源        CLK_SetSysClkSource(CLKSysSrcMPLL)
9. 更新 SystemCoreClock  SystemCoreClockUpdate()
```

第 6 步的等待很关键。PLL 从启动到输出稳定需要时间，不等它就切换系统时钟，芯片会在时钟不稳定时运行：

```c
CLK_MpllCmd(Enable);
while(Set != CLK_GetFlagStatus(ClkFlagMPLLRdy))    // 等待锁定
{
    ;
}
```

漏掉这个等待是"自己写时钟配置就死机"的常见原因之一。

## 4.4 SystemCoreClock

### 它是什么

`SystemCoreClock` 是 CMSIS 定义的一个全局变量，记录 CPU 当前的工作频率（单位 Hz）。它由 `SystemInit()` 初始化为 8MHz（对应复位默认的 MRC）。

这个变量不是硬件寄存器，芯片不会自动更新它。你在 `main()` 里把时钟升到 200MHz，硬件确实跑在 200MHz 了，但 `SystemCoreClock` 变量里还是 8000000。

### 谁在用它

很多代码依赖这个变量做计算：

**软件延时**。`Ddl_Delay1ms()` 通过执行空循环来延时，循环次数根据 `SystemCoreClock` 计算。如果变量是 8MHz 而实际跑 200MHz，延时就缩短了 25 倍——你写 `Ddl_Delay1ms(1000)` 期望 1 秒，实际只有 40 毫秒。

**串口波特率**。`USART_SetBaudrate()` 根据外设总线时钟计算分频系数。总线时钟从 `SystemCoreClock` 推导，变量不对，算出的分频系数就不对，串口输出乱码。

**SysTick 配置**。`SysTick_Config(SystemCoreClock / 1000)` 设置 1ms 中断，变量错了节拍就不准。

**RTOS 的节拍**。FreeRTOS 的 `configCPU_CLOCK_HZ` 通常定义为 `SystemCoreClock`，变量不对，1ms 的 tick 就会漂移，任务延时算出来就不再是真实的 1 秒（节拍与时钟的联动见「走向 FreeRTOS」一章）。

### 必须调用 SystemCoreClockUpdate

切换时钟之后，一定要调用：

```c
SystemCoreClockUpdate();
```

这个函数会根据实际的时钟配置重新计算 `SystemCoreClock` 的值。

**这是 HC32 开发中最容易犯的错误之一**。症状是"程序能跑，但串口乱码、延时不对、RTOS 节拍飘"。排查时如果看到这类现象，第一件事就是检查有没有调用 `SystemCoreClockUpdate()`。

## 4.5 落到你的开发板

你的开发板 BSP 已经把这些都封装好了，函数 `BSP_CLK_Init()` 在 `HC32F460 Demo/bsp/ev_hc32f460_lqfp100_v1/ev_hc32f460_lqfp100_v1.c` 里：

```c
void BSP_CLK_Init(void)
{
    stc_clk_sysclk_cfg_t    stcSysClkCfg;
    stc_clk_xtal_cfg_t      stcXtalCfg;
    stc_clk_mpll_cfg_t      stcMpllCfg;
    stc_sram_config_t       stcSramConfig;

    MEM_ZERO_STRUCT(stcSysClkCfg);
    MEM_ZERO_STRUCT(stcXtalCfg);
    MEM_ZERO_STRUCT(stcMpllCfg);
    MEM_ZERO_STRUCT(stcSramConfig);

    /* 1. 总线分频 */
    stcSysClkCfg.enHclkDiv  = ClkSysclkDiv1;
    stcSysClkCfg.enExclkDiv = ClkSysclkDiv2;
    stcSysClkCfg.enPclk0Div = ClkSysclkDiv1;
    stcSysClkCfg.enPclk1Div = ClkSysclkDiv2;
    stcSysClkCfg.enPclk2Div = ClkSysclkDiv4;
    stcSysClkCfg.enPclk3Div = ClkSysclkDiv4;
    stcSysClkCfg.enPclk4Div = ClkSysclkDiv2;
    CLK_SysClkConfig(&stcSysClkCfg);

    /* 2. 外部晶振 */
    stcXtalCfg.enMode = ClkXtalModeOsc;
    stcXtalCfg.enDrv = ClkXtalLowDrv;
    stcXtalCfg.enFastStartup = Enable;
    CLK_XtalConfig(&stcXtalCfg);
    CLK_XtalCmd(Enable);

    /* 3. SRAM 等待 */
    stcSramConfig.u8SramIdx = Sram12Idx | Sram3Idx | SramHsIdx | SramRetIdx;
    stcSramConfig.enSramRC = SramCycle2;
    stcSramConfig.enSramWC = SramCycle2;
    SRAM_Init(&stcSramConfig);

    /* 4. Flash 等待 */
    EFM_Unlock();
    EFM_SetLatency(EFM_LATENCY_5);
    EFM_Lock();

    /* 5. MPLL: 8M / 1 * 50 / 2 = 200M */
    stcMpllCfg.pllmDiv = 1ul;
    stcMpllCfg.plln    = 50ul;
    stcMpllCfg.PllpDiv = 2ul;
    stcMpllCfg.PllqDiv = 2ul;
    stcMpllCfg.PllrDiv = 2ul;
    CLK_SetPllSource(ClkPllSrcXTAL);
    CLK_MpllConfig(&stcMpllCfg);

    /* 6. 启动并等待锁定 */
    CLK_MpllCmd(Enable);
    while(Set != CLK_GetFlagStatus(ClkFlagMPLLRdy))
    {
        ;
    }

    /* 7. 切电源 + 8. 切时钟源 */
    PWC_HS2HP();
    CLK_SetSysClkSource(CLKSysSrcMPLL);
}
```

对照上一节的九个步骤，这里完成了 1~8 步。第 9 步 `SystemCoreClockUpdate()` 需要你在 `main()` 里补上：

```c
int32_t main(void)
{
    BSP_CLK_Init();
    SystemCoreClockUpdate();     // 别忘

    /* ... */
}
```

这段代码值得完整读一遍，因为它把本章讲的所有概念都串起来了。第 13 章还会再分析它的封装方式。

## 4.6 验证时钟是否正确

### 用代码读取

```c
stc_clk_freq_t stcClkFreq;
CLK_GetClockFreq(&stcClkFreq);

printf("SYSCLK = %lu\r\n", stcClkFreq.sysclkFreq);
printf("HCLK   = %lu\r\n", stcClkFreq.hclkFreq);
printf("PCLK1  = %lu\r\n", stcClkFreq.pclk1Freq);
printf("SystemCoreClock = %lu\r\n", SystemCoreClock);
```

按上面的配置，输出应该是：

```
SYSCLK = 200000000
HCLK   = 200000000
PCLK1  = 100000000
SystemCoreClock = 200000000
```

如果 `SystemCoreClock` 显示的不是 200000000，说明漏了 `SystemCoreClockUpdate()`。

### 用示波器测量

把时钟信号从引脚引出来直接测：

```c
stc_clk_output_cfg_t cfg;
MEM_ZERO_STRUCT(cfg);
cfg.enOutputSrc = ClkOutputSrcSysclk;    // 输出系统时钟
cfg.enOutputDiv  = ClkOutputDiv8;        // 200MHz / 8 = 25MHz
CLK_OutputClkConfig(ClkOutputCh1, &cfg);
PORT_SetFunc(PortA, Pin08, Func_Mclkout, Disable);
CLK_OutputClkCmd(ClkOutputCh1, Enable);
```

在 PA08 上应该测到 25MHz 方波。测不到或者频率不对，说明时钟配置有问题。

这个方法的价值在于它不依赖软件——如果程序因为时钟问题根本跑不起来，串口打印也看不到，示波器是唯一的手段。

## 4.7 关于 32.768kHz

你的板子上除了 8MHz 还焊了一颗 32.768kHz 的晶振。它和主频无关，专门给需要精确计时的场合：

**RTC 实时时钟**。32.768kHz = 2 的 15 次方，经过 15 级二分频正好得到 1Hz，即每秒一个脉冲。这个巧合让它成为时钟芯片的标准频率。

**Timer0 的异步时钟源**。Timer0 的通道 A 可以配置成用 XTAL32 驱动，这样即使主时钟关闭（低功耗模式），定时器仍能工作。你的开发板例程 `3.timer0/BaseTimer` 就演示了这个用法。

**低功耗保持**。主时钟关掉后，32.768kHz 可以继续维持 RTC 和低功耗定时器，功耗极低。

使能方式：

```c
CLK_Xtal32Cmd(Enable);
```

如果你的项目不用 RTC、不做低功耗，这颗晶振可以不使能。

## 4.8 练习

### 练习 1 观察默认时钟

写一个最小程序，不调用 `BSP_CLK_Init()`，只初始化串口并打印 `SystemCoreClock` 和各总线频率。

预期结果：SYSCLK 为 8000000（MRC 默认），各 PCLK 也是 8MHz 的分频。

这个练习让你确认"复位后到底是什么时钟"，建立对默认状态的直观认识。

### 练习 2 制造一个时序错误

在 `BSP_CLK_Init()` 之后故意不调用 `SystemCoreClockUpdate()`，然后写一个每秒翻转 LED 的循环（你的板子 LED 接 PA00，低电平点亮，翻转用 `PORT_Toggle(PortA, Pin00)`）：

```c
while(1)
{
    PORT_Toggle(PortA, Pin00);
    Ddl_Delay1ms(1000);
}
```

用手机秒表测量 10 次翻转的时间。你会发现远小于 10 秒（大约 0.4 秒）。

然后加上 `SystemCoreClockUpdate()`，重新测量，应该接近 10 秒。

亲手制造并修复这个问题，比读十遍说明都管用。

### 练习 3 改主频

把 `BSP_CLK_Init()` 里的 `plln` 从 50 改成 42，重新编译下载。

预期：系统时钟变成 168MHz。用 `CLK_GetClockFreq()` 验证。

注意观察串口是否还能正常输出——波特率是根据 PCLK1 算的，时钟变了但波特率配置会自动跟着变（因为 `USART_SetBaudrate` 是在时钟配置之后调用的），所以应该仍正常。如果你的代码在时钟配置之前调用了 `USART_SetBaudrate`，串口就会乱码。

### 练习 4 计算练习

假设你的板子换成 16MHz 晶振，要得到 200MHz 主频，`pllmDiv`、`plln`、`PllpDiv` 应该填多少？VCO 频率是多少？是否在允许范围内？

（提示：考虑 16 / 2 × 50 / 2，或者 16 / 1 × 25 / 2。检查 VCO 是否落在 240~480MHz。）

## 4.9 小结

复位后内核从 Flash 开头读取栈顶和复位向量，启动文件负责初始化栈、复制 `.data`、清零 `.bss`，然后执行 `SystemInit()` 和 `main()`。`SystemInit()` 只把时钟配到默认的 8MHz 内部 RC。

时钟树的结构是：选时钟源 → MPLL 倍频 → 选系统时钟源 → 总线分频。你的板子用 8MHz 外部晶振，通过 `8MHz / 1 × 50 / 2` 得到 200MHz。

升频必须同时处理三件事：SRAM 等待周期、Flash 等待周期、电源模式切换。缺任何一个，程序都会在高频下跑飞。启动 PLL 后要等待锁定标志，然后才能切换系统时钟源。

切换时钟后必须调用 `SystemCoreClockUpdate()`，否则延时、波特率、RTOS 节拍全部出错。
