# 第 9 章 定时器

定时器是嵌入式系统里最基础也最重要的外设之一。周期性地采样传感器、产生 PWM 控制电机、测量脉冲宽度、为系统提供时基，都离不开它。

这一章先讲清楚几种计时方式的区别，然后展开 HC32 的定时器体系。

---

## 9.1 三种计时方式

### 软件延时

```c
Ddl_Delay1ms(500);
```

本质是一段空循环，CPU 反复执行无意义的指令来消耗时间。它的实现依赖 `SystemCoreClock`——根据 CPU 频率计算需要循环多少次。

特点：

- 实现简单，一行调用
- **完全阻塞 CPU**，延时期间什么都做不了
- 精度取决于 `SystemCoreClock` 是否准确
- 延时期间如果有中断发生，实际延时会变长

适用场景：初始化阶段的短暂等待（比如等晶振稳定），或者简单的演示程序。不适用于主循环里的周期任务。

### SysTick

Cortex-M 内核自带的 24 位递减计数器，所有 Cortex-M 芯片都有。它通常用作系统时基：

```c
volatile uint32_t g_tick = 0;

void SysTick_Handler(void)
{
    g_tick++;
}

/* 配置成 1ms 中断一次 */
SysTick_Config(SystemCoreClock / 1000UL);
```

参数含义是重装载值：`SystemCoreClock / 1000` 个 CPU 周期产生一次中断。200MHz 时就是 200000 个周期 = 1 毫秒。

特点：

- 不阻塞 CPU（中断方式）
- 精度中等
- 是 RTOS 心跳的标准来源

**重要提示**：SysTick 是 RTOS 的心跳来源。裸机时你可以自己写 `SysTick_Handler()`（配合 `SysTick_Config()`）；一旦移植 FreeRTOS，内核会通过 `FreeRTOSConfig.h` 里的 `#define xPortSysTickHandler SysTick_Handler` 把 SysTick 中断接管成自己的节拍处理函数，**不要再自己定义 `SysTick_Handler`**，节拍由内核管理（具体见「走向 FreeRTOS」一章）。

### 硬件定时器

芯片内部独立的计数电路，不占用 CPU：

```c
TIMER0_BaseInit(M4_TMR02, Tim0_ChannelA, &stcTimerCfg);  // 配置
TIMER0_IntCmd(M4_TMR02, Tim0_ChannelA, Enable);           // 开中断
TIMER0_Cmd(M4_TMR02, Tim0_ChannelA, Enable);              // 启动
```

计数器在后台自动累加，达到设定值时产生中断或触发其他动作。

特点：

- **完全不阻塞 CPU**
- 精度高（由硬件时钟驱动）
- 功能丰富：PWM 输出、输入捕获、正交编码
- 可以产生硬件触发信号驱动 DMA、ADC 等

这是做实际项目的主要方式。

### 对比

| 方式 | 阻塞 CPU | 精度 | 功能 | 用途 |
|---|---|---|---|---|
| 软件延时 | 是 | 低 | 单纯延时 | 初始化短暂等待 |
| SysTick | 否 | 中 | 周期中断 | 系统时基、RTOS |
| 硬件定时器 | 否 | 高 | 定时/PWM/捕获 | 周期任务、控制、测量 |

## 9.2 HC32 的定时器体系

HC32F460 提供了四组定时器，各有专长：

| 定时器 | 单元数 | 主要用途 |
|---|---|---|
| **Timer0** | 2 单元 × 2 通道 | 基础定时，周期中断 |
| **TimerA** | 6 单元 | 通用：PWM、输入捕获、正交解码 |
| **Timer4** | 3 单元 | 电机控制：三相 PWM、带死区 |
| **Timer6** | 2 单元 | 高级 PWM：高精度、互补输出 |

选型建议：

- 需要简单的周期性中断（比如每秒采集一次）→ **Timer0**
- 需要输出 PWM 控制 LED 亮度、舵机 → **TimerA**
- 需要测量脉冲宽度、频率 → **TimerA** 的输入捕获
- 做电机控制 → **Timer4** 或 **Timer6**

这一章重点讲 Timer0，因为它是所有定时器里结构最简单、最适合作入门的。理解了它，其他定时器的思路是相通的。

---

## 9.3 Timer0 的结构

### 单元与通道

Timer0 有 2 个单元（TIM01、TIM02），每个单元有 **A、B 两个独立通道**。

关键特性：**两个通道可以使用不同的时钟源**。这是 Timer0 的一个特色，你的开发板例程就演示了这一点——通道 A 用外部 32.768kHz 晶振，通道 B 用内部 PCLK1，两个通道以不同的节奏独立工作。

对应的中断源：

```c
INT_TMR02_GCMA    // 单元2 通道A 比较匹配中断
INT_TMR02_GCMB    // 单元2 通道B 比较匹配中断
INT_TMR01_GCMA    // 单元1 通道A
INT_TMR01_GCMB    // 单元1 通道B
```

### 同步与异步模式

**同步模式（Tim0_Sync）**：计数时钟来自内部总线（PCLK1），与 CPU 同步。

**异步模式（Tim0_Async）**：计数时钟来自外部低速源（XTAL32 或内部 LRC），与 CPU 异步。

异步模式的价值在于低功耗——即使 CPU 主时钟关闭（进入休眠），定时器仍能靠 32.768kHz 继续计时，到时唤醒系统。

代价是异步模式下读取计数值要小心：由于计数器与 CPU 不同步，直接读可能读到不稳定的值。官方例程里的做法是读之前先停止计数器：

```c
/* 异步模式读计数值，需要先停再读 */
TIMER0_Cmd(TMR_UNIT, Tim0_ChannelA, Disable);
u16cnt = TIMER0_GetCntReg(TMR_UNIT, Tim0_ChannelA);
TIMER0_Cmd(TMR_UNIT, Tim0_ChannelA, Enable);
```

### 周期计算公式

```
定时周期 = (比较值 + 1) × 分频系数 / 时钟源频率
```

反过来，已知目标周期求比较值：

```
比较值 = 目标周期 × 时钟源频率 / 分频系数 - 1
```

比较值是 16 位，最大 65535，这限制了单次定时的最长周期。

### 计算实例

开发板例程 `3.timer0/BaseTimer` 里的两个通道：

**通道 A**（异步，XTAL32 = 32768Hz，4 分频，比较值 = 32000/4/2 - 1 = 3999）：

```
周期 = (3999 + 1) × 4 / 32768 = 16000 / 32768 ≈ 0.488 秒
```

约每 0.5 秒触发一次中断，翻转绿灯。

**通道 B**（同步，PCLK1，1024 分频，比较值 = PCLK1/1024/2 - 1）：

```
// PCLK1 = 100MHz 时
周期 = (100000000/1024/2) × 1024 / 100000000 = 0.5 秒
```

也是约 0.5 秒，翻转蓝灯。

注意通道 B 的计算用了 `u32Pclk1` 变量，它是运行时通过 `CLK_GetClockFreq()` 读出来的，而不是写死的数字。这是个好习惯——时钟配置改了，定时器周期自动跟着算，不用手动改代码。

## 9.4 Timer0 的配置

完整流程（对照第 6 章的通用流程）：

```c
#include "hc32_ddl.h"

#define TMR_UNIT      (M4_TMR02)
#define TMR_INI_GCMA  (INT_TMR02_GCMA)

static void Timer0A_CallBack(void)
{
    PORT_Toggle(PortA, Pin01);      // 翻转 LED1（你的板子 LED 接 PA01，中断里只做简单动作）
}

static void Timer0_Init(void)
{
    stc_tim0_base_init_t stcTimerCfg;
    stc_irq_regi_conf_t  stcIrqRegiConf;
    stc_clk_freq_t       stcClkTmp;

    MEM_ZERO_STRUCT(stcTimerCfg);
    MEM_ZERO_STRUCT(stcIrqRegiConf);

    /* 读取实际的总线频率，不要写死数字 */
    CLK_GetClockFreq(&stcClkTmp);

    /* 1. 开时钟门（Timer0 在 FCG2） */
    PWC_Fcg2PeriphClockCmd(PWC_FCG2_PERIPH_TIM02, Enable);

    /* 2. 配置通道 A：同步模式，PCLK1，1024 分频，1 秒周期 */
    stcTimerCfg.Tim0_CounterMode     = Tim0_Sync;
    stcTimerCfg.Tim0_SyncClockSource = Tim0_Pclk1;
    stcTimerCfg.Tim0_ClockDivision   = Tim0_ClkDiv1024;
    stcTimerCfg.Tim0_CmpValue        = (uint16_t)(stcClkTmp.pclk1Freq / 1024UL / 1UL - 1UL);
    TIMER0_BaseInit(TMR_UNIT, Tim0_ChannelA, &stcTimerCfg);

    /* 3. 使能中断 */
    TIMER0_IntCmd(TMR_UNIT, Tim0_ChannelA, Enable);

    /* 4. 注册中断（第 5 章流程） */
    stcIrqRegiConf.enIRQn      = Int001_IRQn;
    stcIrqRegiConf.enIntSrc    = TMR_INI_GCMA;
    stcIrqRegiConf.pfnCallback = &Timer0A_CallBack;
    enIrqRegistration(&stcIrqRegiConf);
    NVIC_ClearPendingIRQ(stcIrqRegiConf.enIRQn);
    NVIC_SetPriority(stcIrqRegiConf.enIRQn, DDL_IRQ_PRIORITY_15);
    NVIC_EnableIRQ(stcIrqRegiConf.enIRQn);

    /* 5. 启动 */
    TIMER0_Cmd(TMR_UNIT, Tim0_ChannelA, Enable);
}

int32_t main(void)
{
    stc_port_init_t stcLedInit;
    MEM_ZERO_STRUCT(stcLedInit);

    BSP_CLK_Init();
    SystemCoreClockUpdate();

    /* 你的板子 LED 在 PA00/01/02，低电平点亮 */
    stcLedInit.enPinMode = Pin_Mode_Out;
    stcLedInit.enPullUp  = Enable;
    PORT_Init(PortA, Pin00, &stcLedInit);
    PORT_Init(PortA, Pin01, &stcLedInit);
    PORT_Init(PortA, Pin02, &stcLedInit);

    Timer0_Init();

    while (1)
    {
        /* 主循环空着，定时由硬件负责 */
    }
}
```

注意第 2 步的 `Tim0_CmpValue` 计算：

```c
stcClkTmp.pclk1Freq / 1024UL / 1UL - 1UL
```

这里除以 1 是因为目标是 1 秒周期。如果要 0.5 秒，就除以 2；要 2 秒，除以 0.5（即乘以 2，但要小心溢出）。

### 常用函数

| 函数 | 作用 |
|---|---|
| `TIMER0_BaseInit(unit, channel, cfg)` | 初始化 |
| `TIMER0_DeInit(unit, channel)` | 复位 |
| `TIMER0_Cmd(unit, channel, Enable/Disable)` | 启停 |
| `TIMER0_IntCmd(unit, channel, Enable)` | 中断使能 |
| `TIMER0_GetCntReg(unit, channel)` | 读当前计数值 |
| `TIMER0_SetCmpReg(unit, channel, val)` | 运行时改比较值 |
| `TIMER0_GetFlag / ClearFlag` | 查询/清除标志 |

`TIMER0_SetCmpReg()` 可以在运行时动态改变周期，比如实现变速闪烁。

## 9.5 PWM 输出（TimerA）

Timer0 只能做基础定时，要输出 PWM 需要用 TimerA。

### PWM 原理

PWM（Pulse Width Modulation，脉宽调制）通过改变方波中高电平所占的比例来模拟不同的"强度"：

```
占空比 25%   ▁▁▔▁▁▁▁▁▁▁▔▁▁▁▁▁▁
占空比 50%   ▁▁▁▁▔▔▔▔▁▁▁▁▔▔▔▔
占空比 75%   ▁▔▔▔▔▔▔▁▔▔▔▔▔▔▔
```

周期固定，高电平时间可变。占空比 = 高电平时间 / 周期。

应用：

- LED 调光（占空比越大越亮）
- 舵机控制（特定频率下，占空比对应角度）
- 直流电机调速
-  DAC 替代（配合滤波电路输出模拟电压）

### 两个参数

产生 PWM 需要设定两个值：

**周期值（Period）**。决定 PWM 的频率。频率 = 时钟 / (分频 × 周期值)。

**比较值（Compare）**。决定占空比。占空比 = 比较值 / 周期值。

TimerA 用 `TIMERA_SetPeriodValue()` 和比较寄存器实现。

### 配置思路

TimerA 的配置比 Timer0 复杂，涉及周期基准、通道模式、输出极性等。原厂例程 `timera/` 目录下有多个示例，建议需要时直接参考：

```c
/* 简化的配置流程，具体参数查例程 */
stc_timera_base_init_t stcBaseInit;
stc_timera_compare_init_t stcCompareInit;

/* 1. 开时钟门（TimerA 在 FCG2） */
PWC_Fcg2PeriphClockCmd(PWC_FCG2_PERIPH_TIMA1, Enable);

/* 2. 引脚复用为 TimerA 的 PWM 输出 */
PORT_SetFunc(PortX, PinXX, Func_Tima0_..., Disable);

/* 3. 配置基础计数（周期） */
MEM_ZERO_STRUCT(stcBaseInit);
stcBaseInit.enClkDiv = TimeraPclkDiv1;
stcBaseInit.enCntMode = TimeraCountModeSawtooth;   // 锯齿波模式
stcBaseInit.enCntDir = TimeraCountDirUp;
stcBaseInit.u32Period = 周期值;
TIMERA_BaseInit(M4_TMRA1, &stcBaseInit);

/* 4. 配置比较输出（占空比） */
MEM_ZERO_STRUCT(stcCompareInit);
stcCompareInit.u16CompareVal = 比较值;
stcCompareInit.enStartCountOutput = TimeraCountStartOutputLow;
stcCompareInit.enStopCountOutput = TimeraCountStopOutputLow;
stcCompareInit.enCompareMatchOutput = TimeraCompareMatchOutputHigh;
TIMERA_CompareInit(M4_TMRA1, TimeraCh1, &stcCompareInit);

/* 5. 启动 */
TIMERA_Cmd(M4_TMRA1, Enable);
```

具体的枚举名和参数以 `hc32f460_timera.h` 和原厂例程为准。

### 输入捕获

TimerA 的另一大用途是测量外部信号的脉宽或频率。原理是：外部信号的边沿触发时，把当前计数值锁存到捕获寄存器，两次捕获的差值就是周期或脉宽。

典型应用：超声波测距（测量回波脉宽）、红外解码、频率计。

## 9.6 扩充：定时器的硬件联动

HC32 的定时器不仅能产生中断，还能输出**触发信号**，直接驱动其他外设，完全不需要 CPU 参与。这类信号在 DDL 里叫"事件"（`EVT_` 前缀），比如：

```c
EVT_SPI3_SPTI     // SPI3 发送缓冲空
EVT_ADC1_EOCA     // ADC1 转换完成
EVT_TMR02_GCMA    // Timer0 单元2 通道A 比较匹配
```

把定时器的事件连到 ADC 的触发源，就能实现"定时器每 1 毫秒自动启动一次 ADC 转换，转换完成自动触发 DMA 搬运，全部无 CPU 干预"。

这种联动通过 AOS（异步操作选择器）配置。原厂例程里有相关演示，做高速数据采集时非常有用。

## 9.7 开发板实例：双通道定时

`3.timer0/BaseTimer` 里两个通道的配置对比，这段代码很好地展示了 Timer0 的双通道特性：

```c
/* 通道 A：异步模式，用外部 32.768kHz 晶振 */
CLK_Xtal32Cmd(Enable);                              // 先使能 XTAL32
stcTimerCfg.Tim0_CounterMode      = Tim0_Async;
stcTimerCfg.Tim0_AsyncClockSource = Tim0_XTAL32;
stcTimerCfg.Tim0_ClockDivision    = Tim0_ClkDiv4;
stcTimerCfg.Tim0_CmpValue         = (uint16_t)(32000u/4u/2u - 1u);
TIMER0_BaseInit(TMR_UNIT, Tim0_ChannelA, &stcTimerCfg);

/* 通道 B：同步模式，用内部 PCLK1 */
stcTimerCfg.Tim0_CounterMode     = Tim0_Sync;
stcTimerCfg.Tim0_SyncClockSource = Tim0_Pclk1;
stcTimerCfg.Tim0_ClockDivision   = Tim0_ClkDiv1024;
stcTimerCfg.Tim0_CmpValue        = (uint16_t)(u32Pclk1/1024ul/2ul - 1ul);
TIMER0_BaseInit(TMR_UNIT, Tim0_ChannelB, &stcTimerCfg);
```

注意这里有个细节：通道 A 的比较值写死了 `32000/4/2-1`（假设 XTAL32 是 32000Hz，不是精确的 32768），而通道 B 用的是运行时读出的 `u32Pclk1`。

两者风格不一致是因为外部晶振频率是固定的硬件参数，可以写死；而 PCLK1 取决于你的时钟配置，动态读取更稳妥。

两个通道各自注册中断、各自有回调函数，分别翻转绿灯和蓝灯。由于周期都是约 0.5 秒，你会看到两个灯同步闪烁。

## 9.8 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 定时器不进中断 | 漏了 `TIMER0_IntCmd` 或 `NVIC_EnableIRQ` | 对照流程检查 |
| 报 `TIMER0_BaseInit` 未定义 | `DDL_TIMER0_ENABLE` 没开 | 改 `ddl_config.h` |
| 周期不对 | 分频或比较值算错 | 用 `CLK_GetClockFreq` 确认实际频率 |
| 周期偏差 25 倍 | `SystemCoreClock` 没更新 | 加 `SystemCoreClockUpdate()` |
| 用了 FCG1 开 Timer0 时钟 | Timer0 在 **FCG2** | 改 `PWC_Fcg2PeriphClockCmd` |
| 异步模式读计数值异常 | 异步模式需先停计数器再读 | 参照例程的停—读—启 |
| 比较值超过 65535 | 16 位限制 | 加大分频系数 |

## 9.9 练习

### 练习 1 验证周期公式

配置 Timer0 通道 B，用 PCLK1 + 1024 分频，比较值设为 `PCLK1/1024/2 - 1`。

用手机秒表测量 LED 翻转 10 次的时间，应该接近 5 秒（0.5 秒周期）。

然后把比较值改成 `PCLK1/1024/1 - 1`，重新测量，应该接近 10 秒。

这个练习验证你对周期公式的理解。如果测出来差很多，检查 `SystemCoreClockUpdate()` 是否调用、分频系数是否正确。

### 练习 2 精确的 1 秒定时

配置一个通道，让它**精确**每秒触发一次中断，在中断里通过串口打印一个递增计数。

验收：串口每秒输出一行，用秒表对比 60 秒内输出的行数应该接近 60。

注意：用 `printf` 在中断里打印是不推荐的（耗时），这里只是验证。实际项目里应该置标志，在主循环里打印。

完成后思考：如果系统里还有其他中断，1 秒的精度会受影响吗？

### 练习 3 双通道不同节奏

配置通道 A 为 1 秒周期（翻转绿灯），通道 B 为 0.25 秒周期（翻转蓝灯）。

验收：绿灯每 1 秒翻转，蓝灯每 0.25 秒翻转，两者互不影响。

这个练习体会 Timer0 双通道独立工作的特性。

### 练习 4 用定时器替代软件延时

回顾第 7 章的流水灯练习，当时用的是 `Ddl_Delay1ms()`。改用定时器中断驱动：定时器每 200ms 触发一次，在中断里切换 LED。

对比两种方式：

- 软件延时版本：`while(1) { 切换LED; Ddl_Delay1ms(200); }`
- 定时器版本：`while(1) { /* 空 */ }`，切换逻辑在中断里

思考：定时器版本有什么好处？如果主循环还要处理串口数据，哪个版本更合适？

### 练习 5 PWM 调光（进阶）

用 TimerA 输出 PWM 驱动一个 LED，实现呼吸灯效果——占空比从 0% 平滑增加到 100%，再平滑减小，循环。

提示：用一个定时器周期性改变 PWM 的比较值（占空比），或者在主循环里配合延时改变。

验收：LED 平滑地由暗变亮再变暗。

## 9.10 小结

三种计时方式：软件延时阻塞 CPU，SysTick 是内核时基（RTOS 用它），硬件定时器不阻塞且功能丰富。

HC32 有四组定时器：Timer0 做基础定时，TimerA 做 PWM 和捕获，Timer4 做电机控制，Timer6 做高级 PWM。

Timer0 每单元有 A/B 两个独立通道，可以用不同时钟源。周期公式是 `(比较值 + 1) × 分频 / 时钟源频率`，比较值是 16 位。

配置时推荐用 `CLK_GetClockFreq()` 动态读取总线频率来计算比较值，而不是写死数字，这样时钟配置改了代码不用动。

常见错误是时钟门控用错分组——Timer0 在 FCG2，不是 FCG1。
